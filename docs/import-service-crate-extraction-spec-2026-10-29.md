# Import service crate extraction — implementation specification

**Status:** Specification only; implementation not started by this document (2026-10-29).
**Target:** existing placeholder `crates/reliquary-import` / `reliquary-import`.
**Repository / branch:** `C:\!bin\workspace\Reliquary-crate-first` / `refactor/crate-first-restart`.
**Starting commit:** `b960e4ca` — Project Environment extraction accepted.
**Intent:** move *existing, deterministic* import-domain code across a real Cargo boundary. Preserve all native import, epoch, reconciliation and public API behavior. No new model inference, import source, VCS operation, data format or compatibility reader.

## 1. Existing state and acceptance baseline

`crates/reliquary-import/src/lib.rs` is a four-line placeholder exporting no functionality. Production import behavior currently lives in `src/imports/` (including `contract.rs`, `providers.rs`, `chatgpt.rs`, `claude.rs`, `hermes.rs`, `prepare.rs`, `commit.rs`, `readiness.rs`, `completion.rs`, `epoch_scope.rs`, `epoch_store.rs`, `epoch_codec.rs`, and reconciliation code). `src/facade/cva_historical_import.rs` and associated historical freshness/embedding helpers remain owner operations. The already-extracted `reliquary-import-store` holds durable import epochs and codecs; it is **not** to be reimplemented.

**Fresh baseline:** `cargo test --lib imports:: --locked --offline -j 1 -- --test-threads=8` returned **85 passed, 0 failed, 0 ignored**, at `b960e4ca`. The full Root suite had independently passed **1,457, with 5 ignored**, and CLI **32/32**, in the prior Project Environment acceptance. These are test baselines, not future implementation results.

A source audit found that `prepare.rs` uses `IncomingTurn`/`IncomingAttachment` already owned by `reliquary-archive`, and returns an Archive-owned `ImportReceipt`. Provider adapters and pure canonical preparation contain **no `Cva` dependency**. Conversely, `commit.rs`, `readiness.rs`, `completion.rs`, `epoch_scope.rs`, and reconciliation read or mutate `Cva`, Container, owner stores or source files. Their complete extraction would violate the current dependency direction. Move policy where genuinely separable; leave owner coordination under Root by design. Do not claim that these retained owner adapters are unimplemented.

## 2. Exact responsibility split

| Current code or contract | Required owner after extraction |
| --- | --- |
| `src/imports/contract.rs` — `NativeImport`, `ImportConversation`, `ImportMessage`, `ImportBranch`, `ImportArtifact` | **Import crate** owns *one* canonical model set with unchanged `serde` names, `deny_unknown_fields`, schema 1 and existing field semantics. Root `pub use` retains the identical public types. |
| `contract.rs` — `ImportReadinessOwner/Status/Blocker`, `ImportVectorReadiness`, `ImportReadinessReport`, `ImportCompletionPending/Outcome` | Move only the existing **data-only** report/enumeration contracts into Import crate if possible with Archive/Import Store value types; Root re-exports the same concrete types. Actual readiness evidence reads and completion remain Root. |
| `contract.rs` — `ImportError` | **Root public error** stays with Root for current `ArchiveError`, `InsomniaError`, `ContainerError`, `Epoch` and public `Display` semantics. Create a *single narrowly scoped* lower error for parse/validate (`Invalid`, `Unsupported`, `Json`) only as required for compilation, and convert it at the Root call boundary preserving existing variants and exact strings. No duplicate long-lived source contracts or broad error framework. |
| `src/imports/providers.rs`, `chatgpt.rs`, `claude.rs`, `hermes.rs` | **Move actual provider adapters** into the Import crate with their existing exports: `normalize_agent`, `normalize_chatgpt`, `normalize_claude`, `normalize_hermes_jsonl`. Root public forwarding functions must retain the same return type (`ImportError`) and behavior. |
| `src/imports/prepare.rs` | **Move** input bounds, canonical sorting, source keys/digests, node/revision identity, parent/replace/deletion checks, attachment bytes, branch handling, `ImportedConversation`/`ImportReceipt` construction and `IncomingTurn` preparation. Use canonical Archive `IncomingTurn`, `IncomingAttachment`, `ImportReceipt`; no Root type copies. |
| `src/imports/mod.rs` | Becomes a compact Root assembly/re-export module: compiled Import models/normalizers/preparer plus retained owner operation modules. Delete the displaced local implementations. Do not put obsolete aliases or an inert parallel `NativeImport` there. |
| `src/imports/commit.rs` | **Root/Cva** exclusively owns ImportStart acceptance, write admission, Archive turn/branch publication, Insomnia Episode/queue admission, import receipt writes, retry/reopen and synchronization. Consume lower `PreparedImport`; do not give the new crate a mutable `Cva`, `Container` or independent owner writer. |
| `src/imports/epoch_store.rs`, `epoch_codec.rs` | **Root adapters** to the already-compiled `reliquary-import-store` while they directly borrow `Container` and map Root `ImportError`. Do not create another epoch codec/store or move physical writes to Import. |
| `src/imports/epoch_scope.rs`, `readiness.rs`, `completion.rs` | **Root/Cva** retains authoritative source/cohort evidence hydration, epoch-scoped Insomnia/Dream/Perception/Freshness readiness, complete-marker publication and exact retry. Move an existing *pure, self-contained* validation function only if its inputs are already immutable lower-owner values and moving it requires no large reconstructed evidence facade. Never replace evidence with unrelated owner-wide counts. |
| `src/imports/reconciliation.rs`, `reconciliation_interval.rs`, `reconciliation_replay.rs` | **Root owner composition**: explicit REL opens, foreign/import identity proofs, interval authorization, graph/memory/freshness reconciliation, physical replay and output publication. Do not move this into a library that would import Root/History or build its own stores. |
| `src/facade/cva_historical_import.rs`, `historical_*.rs`, `src/rewrite/**` | **Remain current owners**. Historical reconstruction/embedding/settlement commits and Maintenance/rewrite are different authority scopes. The many `historical_*_fingerprint.rs` modules under `src/lib.rs` are `#[cfg(test)]` oracles, **not** product History implementation to promote into Import. |
| Existing `src/imports/*_tests.rs`, import integration tests and historical fixture tests | Keep Root tests of real REL/PHY, import epoch recovery, freshness/Graph and reconciliation. Add only focused new crate-level tests covering its real public output; migrate existing *pure* tests rather than copy entire fixtures. |

**Physical dependencies:** The new crate should initially depend directly only on the lower `reliquary-archive` and, only when its moved public result types require it, `reliquary-import-store`; plus the actually used `serde`, `serde_json`, `sha2` libraries. `reliquary-insomnia`, `reliquary-freshness`, `reliquary-history` and other edges in `docs/architecture/crate-map.json` are **maximum permissions, not required dependencies**. No Import→Root, Import→Gateway, Import→Maintenance, or Import→Container direct edge. Root depends downward on Import. Do not insert a dependency on the empty History crate or fabricate history services to make the diagram look complete.

## 3. Fidelity requirements

1. **Input identity**: exact schema 1, namespace/source format, role whitelist, revision derivation, stable content digest, imported conversation/node IDs, topological parent ordering, branch/canonical designation and replacement/deletion semantics; no timestamp normalization changes or source-key reinterpretation.
2. **Bounds and errors**: retain current limits (10,000 conversations; 100,000 messages; 64 MiB content/artifact total; source key length/NUL rules), duplicate/conflict detection, unsupported roles and exact `ImportError` categories/messages. Normalization may not read a URL or filesystem path for artifact bytes.
3. **Provider fidelity**: ChatGPT, Claude, Hermes JSONL and generic agent parser output match the pre-cut model, stable ordering, metadata, malformed-input rejection and empty/partial edge cases. Preserve user-facing normalizer function signatures through Root.
4. **Epoch and authorization**: exact owner UUID/import key binding, ImportStart/ImportComplete markers, collision/retry protection, write fence, bounded Insomnia import Episode scheduling, receipt publication, fresh-historical settlement requirement and close/sync semantics. Import crate may calculate a proposal; only authorized Root/Cva can commit it.
5. **Readiness and completion**: a completed import means the same exact attributed source/Episode/Memory/Graph/Freshness work as before. Preserve `Pending`/failure distinctions, exact `ImportReadinessBlocker` identity/status, vector `SupportedUnavailable` behavior, accepted completion retries and crash recovery. Never silently complete missing or ambiguous work.
6. **Reconciliation**: no changes to existing replay intervals, conflict authority, physical envelopes, imported-epoch provenance, history/owner bytes, or destination construction. The new crate is **not** a second import history or reconciliation engine.
7. **No format migration**: persisted REL/PHY, ImportStore epoch records, Archive import receipts, Insomnia work and Freshness settlement remain byte-compatible with the current-only format; do not introduce runtime legacy readers or migration scaffolding. If any format change becomes unavoidable, stop extraction and follow the development-corpus immediate-migration policy explicitly.
8. **No duplicate source**: delete migrated provider and canonical-preparation modules from Root once the compiled crate is consumed. A thin Root adapter for the public error/concrete return type is acceptable; a duplicate provider implementation or second normalized model is not.
