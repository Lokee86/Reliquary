# Owner sessions

Parent index: [Reliquary architecture](./INDEX.md)

## Purpose

Describe the owner-session boundary that composes durable stores and controls authorized mutation for one REL or PHY file.

## Overview

`reliquary-owner-session` owns concrete REL and PHY sessions, their typed store handles, owner authorization inputs, replayed projections, writer leases, and multi-record publication methods. A session is bound to one file identity and owner kind. `RelSession` and `PhySession` provide reads; `RelWriter` and `PhyWriter` provide controlled mutation. Higher layers receive session operations and selected immutable values, never a `Container` or a bag of writable stores.

The crate is the only product boundary that composes the eight persistent domain owners listed in [storage](storage.md). It does not own Application policy such as how to rank candidates or which user workflow should run.

## State, lifecycle, and concurrency

`RelWriter::create_current_path(path, owner_id)` initializes a new current REL with the neutral 2.1 scope value. Existing RELs expose their stored scope on open. Maintenance that preserves owner identity uses the source's container identity.

Opening a session checks the physical file identity/kind, opens the relevant stores, and replays their records into owner-scoped views. A trusted path mount checks an expected owner ID at the leased header, before physical or semantic replay. The replay passes borrow each frame from a reusable payload buffer. The stores decode and retain the records they own, and the replay checks validate each publication in physical order. A writer obtains an owner-local lease/fence before publication. Prepared work is rechecked against current owner revisions and authorization at commit; a stale or foreign cut is rejected. Grouped commit APIs coordinate related records under one owner writer so readers do not see a higher-level success without its required receipt/history records.

Ordinary REL writer admission and scoped local reads look for a private checkpoint. It captures the typed projections and history locators at a verified file boundary. Graph stores ordered relation versions and rebuilds its relation indexes on restore. Freshness stores its accepted journal once and rebuilds the change and lookup indexes from it. Core checks the header, physical file identity, clock, and covered digest on the original lease. A verified checkpoint can continue native clock reservations, Archive turn and branch publications, REL dependency changes, the supported Memory publications and grouped user mutations, Entity separation confirmations and withdrawals, and Observation batches. For an unsealed native import with the current clock contract, it can continue clock reservations and native Archive turn and branch records. It can also resume a Dream-only tail with the current initial frontier, batch, and settlement records. The checkpoint must establish the source's grouped birth, and each record must verify its Memory, Graph, pair, and Freshness effects in physical order. Mixed source and Dream tails and unsupported records take full native admission on the same lease. Full audits, maintenance sources, PHY opens, and detached REL snapshots replay their owners from the start.

During cold admission each store selects the physical records it can interpret. Archive validates the turn bodies and supplies its version and activity at each grouped Insomnia carrier. Owner-session checks that the Episode was admitted by that Archive version and that the Memory birth uses the same turn count. The owner admission, Graph and Dream scans read the frame families they use for ordered proof. Identity prefix validation reads standalone Memory body IDs from the header. Memory replay validates the body. Archive hashes each import receipt's canonical JSON through a bounded buffer and supplies the physical position and key of every accepted receipt, including exact repetitions of a raw receipt. Owner-session checks those positions against the epoch and processing markers without decoding the receipt body again. A settled import hashes its complete source prefix through a fixed buffer, using the existing frame lengths and bytes as input. An import journal awaiting settlement reads and validates its epoch records. External Memory intents verify preceding source activity separately. See [physical replay](storage.md) for the lease and clock rules.

Archive text, attachments and historical branch revisions, Echo event payloads, Memory bodies, and packed matrices can be read through digest-checked positions on the leased REL. A requested historical cut selects its retained revision metadata before reading its body. A row lookup reads only the relevant packed pages. An invalid position or changed payload fails the read and fences the writer. On a miss, writer admission finishes before creating a replacement checkpoint. The writer builds it at the next due refresh or when it closes, using the synchronized writer boundary and accepted cut. The disposable checkpoint hashes the covered file bytes and checkpoint pages with BLAKE3. It records verified Dream populations as additions and removals in Memory-cut order. On restore, admissions and pending passes share an index of the membership changes. Retry and root checks use exact membership at the admitted cut. Inspection can request a complete historical Begin. Existing REL record digests keep their original format. Commit receipts come from the durable REL, and checkpoint publication is best effort. On Windows, the cache directory and staged checkpoint files are created with the current user's account as the owner. Checkpoint admission verifies the account owner and private access list. Windows rebuilds derived checkpoints in a new cache directory to recover from older caches created with a group owner.

On a leased REL, Archive keeps each accepted import receipt's identity, conversation coverage and titles, and the verified position of its original frame. The private checkpoint omits per-message mappings. A full receipt lookup checks the frame digest and decoded metadata before returning the mappings. A failed check fences the writer. After its first verified lookup, the current import can reuse a session-local source membership map for work and evidence checks. The map is discarded at completion and is absent from the checkpoint.

An open native import with an accepted source receipt authorizes Archive vector publication for the owner cut.
The import writer validates the epoch before preparing the input and again at publication. It uses the same
fragment definitions, packed matrix, and activation records as ordinary Archive writes. The native import's
semantic plan and settlement are independent of the Archive generation. The same publication path prepares eight-turn windows with two-turn overlap for ordinary and native import Archive vectors. A window above 12,000 UTF-8 bytes yields one vector per passage. The accepted passage range is used for both lexical and semantic ranking. Archive embedding documents and configured Archive queries pass through local redaction before inference. Recognizers mask identifiers such as email addresses, phone numbers, government IDs, payment and bank numbers, Windows account security identifiers, and network addresses. They also mask contextual names, addresses and birth dates, and credentials such as API keys, authorization tokens, passwords, private keys, cookies, and connection credentials. Detection runs on the original turn before the embedding passage is clipped. Citations and lexical evidence use the original text.

Native semantic import retains the initial processing fingerprint for replay. Resuming applies the current inference routes and checks the accepted embedding profile. The writer retains the authorized PHY destination and can attach a first destination before the profile is bound.

Native Dream reuses completed extraction cohort verification under the current REL writer lease. An Archive or grouped completion change requires a new cohort check. Each pass checks the import scope, Memory birth receipt, current frontier and publication evidence. A frontier for a Memory born in the current import's accepted grouped completion encodes the first Memory version in that cohort and a digest of the active Memory IDs immediately before it. The owner derives membership changes from historical Memory metadata and excludes every sibling born in the same group. Full replay, checkpoint continuation, and the import writer share immutable populations across those birth cuts. They stream the exact digest and reuse it for passes from the same cohort. Native import processing binds the frontier through Owner Session and can request a complete population separately. Full replay and checkpoint continuation authenticate the grouped birth, the import epoch, and the corresponding Archive, Memory and Graph cuts. Existing explicit and standalone Dream Begin records use their original admission rules. A build must support the native birth variant to reopen a REL after it contains one. Dream batch publication verifies pair links against its staged Graph and writes the validated encoding in one grouped append and sync. Freshness settlement reads current eligibility from Memory metadata and checks credit reachability against the accepted Graph cut. Full replay advances a temporary active duplicate-edge index to each settlement cut for the same bounded reachability check. It indexes earlier direct, duplicate and archival evidence by source. Replay applies each accepted settlement to an unpublished journal. Frontier and settlement writes stage their journal updates and install them after the carrier is synced.

During full replay, Dream evidence admission records the physical position of each accepted Frontier. Settlement validation matches that frame's position, length, and marker on the same lease and reuses the accepted Begin and candidates. It applies its settlement checks in physical order.

When graph-prefix replay proves an embedded explicit Begin against its birth cut and derives the admission, Dream evidence reuses those checked facts at the matching Frontier position. It shares the verified population history across birth cuts. Historical Begin reads reconstruct the original explicit set on demand. Caller-supplied admissions still compare against the encoded population. The Dream pair projection keeps batch fingerprints for exact retries and the last batch Graph version at which each Memory was archived.

The standalone Dream proof scan skips raw Frontier bodies after full REL graph-prefix replay validates them. Freshness checkpoint restore rebuilds event, receipt, and turn indexes from the accepted journal, including the events derived from accepted uses.

During full leased REL replay, the packed vector store verifies each matrix in 64 KiB pages and retains its physical location and page digests. The graph-prefix check uses those admitted positions to enforce that Memory vector publications follow their backing matrices. Memory and Freshness apply their frame size limits to the records they replay.

A failed checkpoint publication keeps the verified hash on the current writer lease. A later refresh on that lease can hash only the appended bytes.

An Archive vector search captures the active generation and shared references to its immutable packed matrix and fragment mapping. The search view keeps those values alive when the owner advances or closes. The generation binds the source Archive cut and the accepted activation record. Hybrid capture pins readable text and source coordinates under the same owner read. It checks the persisted index against the digest of the readable source range. The first lexical lookup builds from captured text when there is no matching record. A temporal search also captures the readable ancestor path of each fragment with its original turn timestamps. It uses the active generation's accepted fragment coordinates. The ordinary cached lexical view does not retain duplicate turn payloads. Explicit index publication prepares the same index outside the writer lock, then rechecks the file, active generation and write fence. The writer appends and syncs the sealed frame before recording publication. A retry returns the existing publication with zero added bytes. A new generation drops the session's reference to the previous index, and captured views can finish with their original index and packed rows.

Copied Hermes imports write source-keyed Echo records under the native import epoch. Exact copied-range reads combine Archive and matching Echo from the requested cut. A terminal conversation is excluded from temporal search views and from the inputs and carried rows of a subsequent Archive vector generation.

REL and PHY writers are separate authorities. Session clones do not create independent authority to bypass the writer boundary. Runtime-level synchronization and leases serialize mutation through mounted Gateway writers; persistence is still recovered from the file's append/replay state after process restart.

Community recompute captures eligible IDs and active structural edges from one REL read. Capture and publication share the same active-Memory check. The writer rechecks the captured file identity and versions, requires every eligible ID exactly once, and syncs the Community frame through the owner write boundary.

REL owner-session also owns the directional Entity identity receipt projection and typed publication. A derived, lazily built index maps an Entity to its resolved mention keys. It includes typed resolutions retained during migration. A subsequent decision in the REL takes precedence for the same key, including withdrawal or reassignment. Opaque retained entries have no verified span and supply no excerpt. Capture checks the active Memory revision and direct source and records the field, exact mention position and surrounding excerpt span. The receipt stores those references and any grounded Relationship references in the recording REL. On historical inspection each owner verifies its retained mention resolution, Memory revision and body before returning the excerpt. Gateway checks access to both RELs and coordinates their sessions.

For automatic Entity identity discovery, REL owner-session projects seekable pages of active non-principal Entities in Entity ID order. It folds case and whitespace in complete names and aliases and hashes them separately from structured identifiers found in the bounded, directly sourced resolved mention excerpts. Serial codes and reverse-domain package names preserve their separators and match across case variations. The matcher skips ordinary words, common date strings and version forms. Gateway compares the keys within the current authorized mount context and refreshes them when the evidence cut changes. A shared key only nominates a pair for the existing evidence comparison. Receipt publication leaves the evidence cut unchanged.

The REL owner-session publishes verified ordinary and relational Observations in one versioned `RELOBS01` carrier inside the native publication envelope. Each accepted batch can contain stable revision transitions, review triggers and comparisons, local Freshness receipts, and audit progress. The writer verifies the current owner and history generation, exact cited bodies and UTF-8 ranges, relational participants and mention revisions, upstream standing, and the expected Observation head. A completed input fingerprint returns the same receipt after reopen. A successor retains its stable ID, and its references remain pinned to the exact verified revisions. Retained claims and review records stay available for historical inspection under the owner grant. Current reads exclude claims pending review, including when changes to pinned evidence or upstream standing become visible.

The Archive removal frontier governs derived content at the same owner cut as a conversation tombstone or rewind. Memory eligibility checks exact content and grounding coordinates and the accepted extraction Episode range. An affected Memory is effectively tombstoned at its existing revision and Memory version. Its history retains revision metadata and omits the payload. Current retrieval, graph traversal, Entity evidence and audit work use the same eligibility rule. Cached Community membership that includes a removed Memory is withheld until recompute publishes an eligible partition.

Removing a cited source immediately marks the affected Observation as changed support. Descendants wait on upstream review. Historical inspection retains citation and review metadata and withholds affected proposition and evidence bodies. Reverification can publish a successor with independent citations and the same wording. Observation admission and replay evaluate the Archive prefix at publication, so an earlier valid receipt remains replayable. Perception captures and prepared publications carry the removal frontier and recapture when it advances.

A bounded RELOBS02 claim-vector publication binds document embeddings to exact verified Observation revisions and a compatible owner Memory profile. Older Observation records replay with an empty claim-vector index. Only a currently eligible claim uses its vector for new retrieval. Review history, citation identity and source Memories keep their exact records.

Full replay and verified checkpoint suffix replay validate Observation records at their physical publication prefix. Historical proofs include the Observation frontier and the complete accepted batches through that cut. Existing REL and PHY 2.1 headers and manual Relationship history retain their formats. Readers need `RELOBS01` support for Observation history and `RELOBS02` support once claim indexing writes to the REL. Verified same-owner copies and supported reclamation preserve these batches. A fresh-history rewrite or divergent reconciliation of Observation-bearing history fails before destination creation. Memory pruning fails before destination creation when a selected body is needed by retained Observation evidence.

## Failure, recovery, and invariants

Important guarantees are owner/file-kind matching, no cross-owner write, deterministic retry identity, typed replay, and all-or-rejected grouped publication where the operation defines a group. An interrupted or uncertain publication is reconciled from owner records and stable operation ids; callers must not infer success from a prepared value alone. Verified copy/reconciliation APIs preserve source owners and reopen the result before reporting verification.

Cold replay validates Entity separation confirmations against the recording REL's publication prefix without opening the peer. Existing 2.1 files start with an empty confirmation history. An owner-session historical proof includes confirmations and withdrawals through their own cut and verifies that the cut includes the Memory, Perception and comparison-receipt state present at publication.

Exact copies, exact-prefix reconciliation and verified maintenance transforms retain the audit chain. Entity description pruning preserves the digest of any reviewed description. Fresh-history rewrites and divergent reconciliation refuse sources with confirmation records before creating a destination.

REL dependency declarations are owner-local, REL-only metadata. The writer checks the expected generation, appends a canonical snapshot and syncs it. Reopen validates the record sequence independently of the mounted graph. Owner-session also exposes the stored Ego synthesis when its Memory version matches the current one.

Ordinary 2.1 owner admission replays retained publications and verifies the owning clocks and references. The offline writer uses the same native codecs and reopens its staged output through that admission. Offline comparison reads through the optional `d02-observation` feature in a separate Cargo workspace. The historical FRS07 reader and its transfer formats run in a separate checkout. REL and PHY files produced by migration follow the usual grant rules.

## Extension seams

Add a session operation when the invariant is inherently owner-local: it must check current owner state, acquire/validate the owner writer, or commit a set of related store records. Keep semantic analysis and user-facing orchestration above this crate. Expose immutable value types deliberately; never expose mutable store handles or low-level codec construction for convenience.

Storage reclamation preserves the replay-validated historical Freshness snapshots emitted by native imports. These snapshots carry the settled Freshness history through a verified same-owner copy.
