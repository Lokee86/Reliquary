## Generic review evaluator

Typed source validation and pure policy arithmetic live in `src/staleness/mod.rs`; source readings live in `src/facade/review_clocks.rs`. Verification is in `src/staleness/tests.rs` and `src/facade/review_clocks_tests.rs`, covering source/owner/unit mismatch, signed time, checked interval arithmetic, bootstrap and real owner accessors. Current API and ownership are documented in [Rust API](api.md) and [Architecture](architecture.md); these helpers may be used for Ego summary scheduling but are **not** a per-Memory review engine. The accepted future owner-local Freshness metadata, event propagation and lifecycle index are specified by [ADR 0039](decisions/0039-unified-deterministic-memory-freshness.md) and [the unified implementation plan](generic-staleness-implementation-plan.md). No persisted record format changes in implemented step 2.3.

## Memory Freshness owner and F1 evidence

The F1 source audit distinguishes **creation at first accepted MemoryStore publication**, exposed by grouped Insomnia completion (`src/runtime_inference/insomnia/processor/application.rs`) and direct owner publication (`src/memory/memory_store.rs`), from ordinary **Web admission at first successful settled Dream lifecycle promotion to nonarchived `knowledge`/`canonical`**, including no-link settlement (`src/runtime_inference/dream_lifecycle.rs`). An explicitly active first direct publication may admit immediately. The Graph memory projection currently contains only relation endpoints, so neither the first Graph edge nor first extracted MemoryStore publication universally means admission. Freshness must not use MemoryStore's `changed` result alone to detect creation because revisions also change it. New first-cycle links are observable from Dream's `DreamPublicationOutcome::Published` in `src/runtime_inference/dream_owner_publisher.rs`, `dream_owner_duplicate.rs`, both bounded Dream processor paths and `src/runtime_inference/runtime_host_dream_owner.rs`; commit/processed-epoch ordering and crash replay are covered by the F3/F5 recovery suites. `src/runtime_inference/runtime_host_memory_search.rs` and low-level `Cva::memory` only **read/hydrate** candidates; an external accepted-context/use producer must invoke the existing receipt API to produce +25 events. Core scoring/propagation/persistence are implemented under the owner-local `src/freshness/` module and `src/freshness_storage.rs`. `tests/freshness_f1_reference.rs` remains an independent policy oracle; the owner, recovery, reconciliation and exhaustive propagation suites verify production seams. [Unified plan](generic-staleness-implementation-plan.md); [ADR 0039](decisions/0039-unified-deterministic-memory-freshness.md).

## Boundaries

- `cli/` owns only operator argument/prompt/output composition and depends exclusively on public library APIs; removing it cannot change core library semantics.
- `ReliquaryConfig` owns machine-local current configuration separately from `.rel`; config changes do not enter semantic history.
- `CredentialsConfig` owns decrypted in-memory provider secrets; `credential.<id>` objects are independently authenticated/encrypted and route references use stable IDs.
- `ModelSwitchboardConfig` owns provider/model/endpoint/credential selection; `ModelSwitchboard` validates matching credentials and attaches request auth. These choices cannot establish Compatibility Profile identity or vector compatibility.
- `Cva` owns the single Container handle and explicit concrete-store scan dispatch; it owns no semantic dependency graph.
- Durable owner identity belongs to the typed container header. Scope/type plus UUID derives the canonical owner ID; filenames and optional adapters remain outside core identity.
- Container owns physical storage and global ordering only.
- Archive owns Archive-local ordering and conversation/session semantics.
- Packed-vector storage owns immutable matrix identity/shape only.
- Archive-Vector storage owns row-to-Archive-fragment identity only.
- Compatibility Profiles own immutable endpoint-independent vector-space compatibility contracts and reference probes; provider/model provenance is outside this owner.
- Vector Generations own profile/population activation, Archive coverage, and the vector-local semantic watermark.
- Archive and vector-local version adjacency do not imply ancestry or cross-store dependency identity.
- Node parent links and branch/session revisions own local conversation history.
- Source attachments are intrinsic to source-turn ingestion; later file-to-Memory links remain explicit cross-owner references.
- `InteractionRuntime` owns transport-neutral session coordination, completed-message stream assembly, durable acknowledgement, and explicit live Episode scheduling above Archive ingestion; future adapters and product surfaces must converge through that boundary rather than defining Archive semantics.
- A future CVA management surface composes concrete owner APIs and cannot become a generalized semantic store.
- Future stores retain independent authority even when they share the CVA global clock.
