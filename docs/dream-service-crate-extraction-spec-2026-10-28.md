## 1. Goal and acceptance boundary

Extract Dream's classifier/verifier, bounded pair evaluation, candidate ranking/selection, duplicate-component planning, lifecycle *decision policy*, and derived Community naming into a real library. Root remains the owner-authorized executor: it reads Memory/vector/Graph facts, selects model endpoints, coordinates REL/PHY frontier processing, validates source and graph versions, writes relationships and lifecycle mutations, records the Dream-pair journal and settles first-cycle/Freshness evidence.

A passing build of an empty crate, one-way file move, re-export-only facade, or partial processor without the authoritative pair/duplicate/naming algorithms is **not** acceptance. A compiling but uncommitted extraction is **not** acceptance.

The existing `reliquary-dream-store` is already integrated and owns `CVDREAM1` journal, `CVDREAM2` Begin codec and population digest. This service must never re-own that state. The separate `DreamPairStore` and its compact pair codec currently live in Root (`dream_pair_history.rs` and `dream_pair_codec.rs`): **keep that durable owner adapter in Root for this cut**. Do not move durable pair records into the semantic service; any future independent durable-store move needs its own explicitly authorized boundary.

| **Root / Cva / Phylactery** | Authenticated Memory/source-time/body and vector reads; evaluated-pair exclusion and current Graph/Community data; REL/PHY owner authorization and publication; `DreamProcessor` and `DreamCommunityNamer` host-facing coordination; Graph version conflict handling, user-origin override checks, actual duplicate-chain edits, Memory revision `mutation_id`/append, Freshness first-pass Begin/roots/accepted cut/settlement, cadence writes and error composition. |

| **Memory Core / Graph / Vectors / Chronos** | Canonical Memory bodies, durable graph/relations and Communities, vector data/profiles, and temporal parsing/matching. Service may use stable public *value* types and pure Chronos policy; it cannot acquire mutable owner stores or container handles. |
| **Switchboard** | `GeneralEndpoint` and configured model routing/credentials. Dream receives selected endpoints; it cannot discover routes or perform provider authentication. |

The `docs/architecture/crate-map.json` Dream maximum allowance currently includes Chronos, Dream Store, Freshness, Graph, Memory Core, Switchboard and Vectors. **Maximum is not a dependency shopping list.** Add only actual pure/value imports needed for the moved code, and inspect the real Cargo graph at each step. No direct Dream-service dependency on Root, Container, Owner Lifecycle, Runtime, History, mutable Memory/Graph store handles or mutable Freshness state; no upward or circular dependency. A permitted direct dependency on the lower Graph crate may supply immutable relation value types, but never allow the service to open or mutate Graph state. Do not solve an ID/type mismatch with a duplicate root cache, `Cva` trait facade, unsafe alias, or generic service locator.

### 2.1 Public/API identity: explicit nontrivial seam

Existing public `DreamProcessor<C,V>` methods take `&mut Cva`/`&mut Phylactery`. A type owned by the lower Dream crate **cannot** keep those inherent host methods without a forbidden Root dependency. Therefore:

- Keep the public **Root-owned `DreamProcessor<C,V>` as a thin, concrete host adapter**, holding a service-owned pair evaluator (`DreamPairEvaluator<C,V>`, exact final name may vary). Its model constructors and existing `process_memory`, `process_phylactery_memory`, `*_with_pair_concurrency` and `process_memories_with_concurrency` contracts remain callable with the same signatures. Its host adapter selects candidates, invokes service evaluation, publishes and settles. It contains **no** second classifier, verifier, candidate or duplicate policy implementation.
- `DreamClassifier<E>` and `DreamVerifier<E>` themselves can move fully to the service and be re-exported from Root with existing constructors and result/error behavior. Expose only truly required service evaluator methods; do not publish internal planning state unnecessarily.
- Keep the public **Root-owned `DreamCommunityNamer<E>` as a thin host adapter** for `name_communities` and `name_phylactery_communities`; a service-owned `DreamCommunityNameEvaluator<E>` receives authorized representative texts, selects wording and validates results. The Root adapter retains snapshot/current-graph checks, representative Memory retrieval and durable naming publication.
- Preserve public `DreamCandidateConfig`, `DreamCandidateSet`, `DreamMemoryContext`, `DreamPairClassification`, `DreamPairVerification`, `DreamVerificationPolicy`, `DreamPublicationOutcome`, `DreamLifecycleResult` and errors. Move canonical pure value definitions if their lower dependencies resolve; if a Root type carries owner-specific errors/records, keep it Root-owned and explicitly convert *owned immutable values at one seam*. Do not keep duplicate live model types or alter the public `MemoryId` identity.
- `DreamProcessResult`, `DreamMemoryProcessOutcome` and `DreamProcessError` compose owner/Graph/Freshness errors and remain Root/public-product results. Service errors are narrowly typed and translated once, retaining existing `is_backpressure` and failure precedence.

Inventory all existing imports and associated methods **before** changing the type owner; the above host/service split is the agreed resolution of the inherent-method dependency problem, not an optional later workaround.

## 4. Behavior to freeze before implementation

1. **Candidate lane fidelity:** exact current limits: total default **12**, semantic **24**, prior-semantic quota **3**, lexical **8**, temporal **8**; hard total limit **128**. Preserve blocked pairs, archived exclusion, source exclusion, active-relations exclusion, vector dimension/zero-vector error, Chronos matches, lane order/tie breaks, RRF weights and source/body provenance. Do not use a future Retrieval policy in place of Dream's dedicated ranker.
2. **Classification/verification:** classifier contract **v3** and verifier **v1**; one canonical pair ordering, typed relation/direction, exactly one verbatim Memory quote per side for non-none, none has no evidence, direction normalization, optional verification and precise accept/reject/uncertain outcomes. Default verification requires duplicate/supersedes; broad-semantic policy keeps its existing selections.
3. **Inference behavior:** `DREAM_INFERENCE_RETRY_LIMIT = 2` and unchanged transient/backpressure behavior, per-pair concurrency and deterministic output ordering. Frontier default **6**, inference concurrency default **12**. Freeze exact prompt payload bytes/JSON structures and override system-prompt behavior; no provider-model drift.
4. **Owner publication authority:** no relation when classifier returned none, verification withheld, user-origin protection denies the state change, or graph source/version conflict exists. Neither pure plan nor a `Published` outcome substitutes for the actual accepted Graph write. Ensure duplicate-chain rewires are not new first-cycle Freshness linkage events.
5. **Duplicate/canonical rules:** component-based duplicate identity; temporal representative ordering with exact source timestamps and ID tie-breaks; canonical superseder uniqueness, anchored corroboration, current/historical birth evidence, archived/inactive exclusions and cycle/conflict rejection. Do not infer authorized representative from stale graph or physical chain order.
6. **Lifecycle:** `extracted → knowledge` for active noncanonical first-pass source when eligible; canonical promotion only with existing verified authority; archive/supersede/rewire policy unchanged; owner publishes exact `dream-lifecycle:...` mutation IDs and applies existing no-change logic. Re-run decisions against current graph/memory revisions before the first write.
7. **First-cycle/Freshness:** Beginning, roots, evaluated-pair receipts and settlement remain in exactly the existing order, including zero-link active admission and +50 **only** for newly accepted first-cycle links. No missed/duplicate first-cycle events on retry/reopen; no replay inference. REL and PHY paths must retain their actually implemented distinct settlement behavior, not be artificially homogenized.
8. **Community naming:** owner-local derived current Community only; user names take precedence; algorithm/version/snapshot guard stays Root; bounded representative selection and two-per-subcentroid current behavior; max display bytes, UTF-8 and control-character guards; `DREAM_COMMUNITY_NAMING_RETRY_LIMIT = 2` retains retry semantics and backpressure behavior. No re-generation or name writes on stale snapshots.
9. **Cooldown:** processing lane **1**, cadence version **1**, default **30-day** reprocess interval, extracted-first-pass behavior and read-only eligibility. Memory processing epoch writes remain Root and do not become inferred from model success.
10. **Persistence/history:** `CVDREAM1`/`CVDREAM2` and compact Dream pair records are byte-identical, with exact Begin population and physical pre-Begin source/owner proof. Do not edit the file format, add compatibility readers, reserialize historic evidence or write during ordinary open. `CVAFRS07` six-file corpus recovery is separately gated.

## 5. Execution plan: bounded hard-cut slices

Every slice moves one bounded semantic concern and its direct callers. **At the end of each completed slice one canonical implementation remains.** A temporary red compile during a coordinated module/call-site move is acceptable; never keep two production copies under permanent Root/service forwarding stubs. Avoid a new 300+-line production file; target under 200 lines per file and split existing modules during migration, not as a later cleanup.

| Gate | Specific change | Required witness |
| --- | --- | --- |

| **D1 — real service shell** | Add only used lower value/endpoint dependencies and Root Cargo dependency; compile external-consumer import of a real lower policy function. | `cargo check -p reliquary-dream`, Cargo graph no forbidden/cyclic edge. |

| **D4 — pure candidate ranker** | Extract lane fusion, stable ordering, lexical/cosine and cap validation over already-authorized Memory/body/temporal/vector facts. Root remains hydrated data source. | Frozen multi-lane ranking/parity fixtures and exclusion/tie-break tests. |

## 6. Acceptance matrix (run on the final cut)

**Service:** `cargo test -p reliquary-dream --locked --offline -j 1`, including cross-crate behavioral consumer tests exercising actual classify/verify, candidate ranking, and a duplicate/lifecycle pure plan, without loading Root or creating an REL/PHY.

**Store:** `cargo test -p reliquary-dream-store --locked --offline -j 1` and exact CVDREAM1/CVDREAM2 and population digest vectors. Verify no new Dream-service dependency in Dream Store or Owner Lifecycle.

**Focused product:** existing Dream classification, verification, candidates, duplicate component, Graph publisher, canonical/history, lifecycle, frontier, Community naming, Chronos, Freshness initial settlement, and REL/PHY tests. Test source/global chronology, historical source birth/cut, selected endpoint fallback/backpressure, contested user-origin relation and per-frontier partial failure/ordering. Record exact filter and pass count: the word `dream` alone does not cover all related modules.

**Full integration:** `cargo check --workspace --all-targets --locked --offline -j 1`; `cargo test --lib --locked --offline -j 1 -- --test-threads=8` with local loopback support and repository-local temp where needed; `cargo test --manifest-path cli/Cargo.toml --locked --offline -j 1`; `cargo fmt --all -- --check`; `git diff --check`. Run root semantic/new tests and real REL/PHY close/reopen, Dream-pair replay, History/import/rewrite and direct Memory publication parity. If a suite is interrupted or blocked, label it **unverified**, never passed; preserve its prior green baseline separately.

**Architecture/docs:** current architecture guard and available refreshed Lexicon/Arcana/Pitlord checks; `ddocs check --indexes --links`, documentation policy, source/code-map audit and direct Cargo tree. Update `docs/subsystems/dream.md`, `docs/architecture.md`, `docs/api.md`, `docs/maintainer-map.md`, `docs/documentation-coverage.md`, `docs/crate-first-layout-spec-2026-10-25.md`, `docs/crate-first-architecture.md`, applicable crate/component maps and `docs/INDEX.md` for *actual* moved code. Record previous policy tool Windows `target` path failure if it recurs. Don't invent success for a failed tooling invocation.

**Fidelity:** compare deterministic inputs/outputs before/after using existing REL/PHY/golden fixtures: candidate set/order/scores, prompt/schema JSON, class/verifier verdict and errors, Graph changes and provenance, first-pass roots/accepted cuts, lifecycle revisions, duplicate representative, Community name generation, processing epoch state and exact stored bytes. Live model endpoints or absent frozen corpus are not silently substituted with simulation. Promoted `CVAFRS07` and other historical corpus gates stay independently open unless run and passed.

**Definition of accepted:** service contains the real semantic logic; Root retains only owner coordination; public API and observed REL/PHY behavior are unchanged; durable format and current history proof are identical; no upward dependency; all runnable focused and full checks pass; architecture/documentation results are reported; evidence is written; integrated implementation is committed. If an externally blocked benchmark remains, specify exactly what is blocked and make no claim of that particular product-level acceptance.
