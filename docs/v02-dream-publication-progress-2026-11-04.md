# V02 — Dream publication progress (2026-11-04)

**Status: IN PROGRESS — not accepted.** V02 is the Application workflow that admits S03's pure Dream decisions to a REL/PHY owner and durably settles Graph, Memory lifecycle, evaluated-pair and first-cycle Freshness evidence. S03's evaluator and G1 storage are already accepted; V01 ingestion remains an acceptance prerequisite.

## Implemented: one-effect zero-link publication

- Application exposes `commit_dream_zero_link` with `DreamOwnerWriter::Rel/Phy`. Only a draft created by the checked Dream preparation workflow can be passed from outside Application; draft fields are no longer publicly mutable or constructible.
- Publication requires one classifier-derived `none` decision, two observed Memories, no unsupported relation/lifecycle effect and no verifier or fabricated evidence. Positive or multi-pair proposals fail closed **before writing**. It does not treat an unverified positive relation as a zero-link result.
- Owner-session revalidates the **exact authorized owner ID**, current Graph version and both current Memory revision/body identities; archived, tombstoned, missing or pruned source bodies are rejected. All validation occurs while holding the canonical writer lease, immediately before the durable evaluated-pair write.
- The existing compact Dream pair record persists and replays for REL and PHY. Repeating the identical accepted zero-link result returns `false` without another frame; an interruption during the actual append uses existing Container writer-recovery requirements.
- Tests prove REL/PHY durable reopen, byte-stable retry, rejected cross-owner authority, refusal of positive effects without mutation, stale Graph version and stale Memory revision refusal.

This is a **single-effect publication**, not necessarily a single physical frame: new Memory identity reference frames may precede the pair marker. Complete unpaired references are replayable, and uncertain appends require reopening or explicit recovery. It deliberately does **not** issue independent multi-domain store writes and call them an atomic Dream transaction.

## Implemented: one grouped positive-relation publication (continuation)

- Application now exposes `commit_dream_relation` for a checked, classifier-derived **single Topical/Factual/Causal/Recurrent relation** with exact Memory-side evidence. The new path rejects unsupported lifecycle effects, duplicate/supersession, multi-pair proposals and mismatched owner/effect inputs before mutation. The semantic Dream crate remains read-only.
- Owner-session owns a new `RELDRG01` carrier: one accepted **active Dream Graph relation and its evaluated-pair receipt share a single synced frame**. REL and PHY writers validate the authorized owner, retained Memory identity/revision/body, current Graph version, write lease and existing pair receipt. In-memory Graph and pair projections update only after the frame is durable.
- REL/PHY reopen replay both effects from that one carrier. A retry of its exact accepted cut after Graph advancement is a byte-stable no-op; conflicting/stale cuts fail closed. Unaware standalone Graph readers reject grouped carriers rather than silently dropping relation history.
- Focused positive REL/PHY tests prove reopen and idempotent retry; negative PHY tests prove cross-owner and stale Memory revision rejection without mutation. A post-sync/pre-projection crash simulation writes the carrier and deliberately skips both in-memory updates, then reopens a PHY and verifies both recovered effects.
- **Deliberate limit:** This first grouped carrier accepts Memory **revision 1 only**, a single active non-lifecycle relation and one pair; it does not provide a general grouped lifecycle, multi-pair, first-cycle or Freshness transaction. More complex cuts remain unsupported, not silently decomposed into independent writes.

## Continuation: first-cycle Begin, settlement and Freshness (2026-11-05)

**Status remains IN PROGRESS.** This increment continues accepted parent `0fbe6fc8`; the interrupted uncommitted empty-pass attempt was repaired and extended, rather than treated as verification evidence.

- Owner writers expose `begin_initial_dream_pass`. The owner derives the preexisting active population at the source's physical birth cohort from canonical Memory history; same-frame siblings are excluded. Begin pins the current Memory and Graph cuts, and returns the authenticated admission used on reopen. Previous promotions, revisions and tombstones do not erase the historical population. A source has one first-cycle pass identity; exact Begin retry is byte-stable, including after settlement and promotion.
- Application exposes `settle_initial_dream_cycle` (also available as `commit_empty_dream_cycle`) for a checked source-only draft with no remaining classifications or proposed pair/lifecycle effects. It invokes Dream's pure lifecycle policy and Freshness's pure propagation evaluator. It refuses unsupported duplicate/archive/canonical choices and never fabricates a classifier `none` response just to settle an empty frontier. A classified no-link pair can be committed through the existing pair workflow, followed by a fresh empty-frontier draft and settlement.
- The new owner-private `RELDRF01` carrier atomically records retained initial roots, accepted Graph/Community/turn proof, Dream settlement, canonical Freshness birth/admission/event bytes for REL, and an optional standard Memory metadata delta promoting `extracted` to `knowledge`. Memory prepares and verifies the exact delta through its ordinary revision, version and mutation rules; body, provenance and original content-update timestamp stay intact. In-memory projections apply only after one append and sync. Standalone Memory/Freshness readers that cannot interpret owner carriers fail closed.
- Already accepted direct relation/pair carriers remain durable before settlement; they are not silently rolled back or described as one transaction with the later settlement frame. Eligible initial roots come only from those accepted direct receipts after the pinned Begin Graph cut, against the source's preexisting population. A resume after relation sync can therefore retain its original linkage evidence with no model candidates left. User-created edges, preexisting adjacency, unreceipted Dream rewires, and reverse duplicate evidence never create an initial linkage event.
- REL produces at most one source-scoped initial Dream event, using the accepted Graph/Community snapshot and the configured linkage principal. The source is excluded from its own propagation. Existing births and admissions retain their original coordinates; exact settlement retry reuses the durable receipt without appending, re-enrollment, another promotion or reinforcement, including after later Graph work. PHY retains the same Begin/root/settled and Memory lifecycle evidence but carries no REL Freshness effects and borrows no REL clock.
- Reopen authenticates Begin's actual physical Memory/Graph prefix and settlement's owner, source/body/revision, prior Begin, roots, current physical Graph/Community cut, canonical lifecycle delta and Freshness effects. Negative cases reject foreign owners, stale or fabricated cuts, unsupported effects, invented roots, missing enrollment effects, malformed/truncated carrier payloads and unrelated lifecycle mutations without rewriting accepted bytes.
- Interruption tests cover Begin-only resume, accepted relation before final settlement, synced settlement before any in-memory projection, and an incomplete physical settlement frame. The incomplete tail blocks ordinary reopen until explicit Container repair; retry then applies all effects once. REL and PHY tests cover durable reopen, byte-stable retry, subsequent first cycles after earlier promotion, and no reinforcement from user edges or raw rewires.

**Deliberate limits:** publication source cuts and supported direct grouped relation endpoints remain revision one. First-cycle population is capped at 4,096 identities, retained roots at 16, and Freshness recipients at 64; unsupported cuts fail closed rather than truncating effects. This does not implement multi-pair atomic coalescing, general duplicate/canonical/archive settlement, completion policy for rejected/uncertain or unfinished frontiers, temporal-inference admission, or bounded candidate/population/propagation read cost. These and the V01 dependency/full V02 acceptance matrix remain outstanding; V02 and G2 are not accepted.
