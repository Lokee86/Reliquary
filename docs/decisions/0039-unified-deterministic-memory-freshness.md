# ADR 0039: Unified deterministic Memory Freshness

Parent: [Architectural decisions](INDEX.md)

Implementation contract: [Unified Memory Freshness plan](../generic-staleness-implementation-plan.md). Policy summary: [Memory Freshness](../memory-staleness-plan.md).

## Status

**Accepted — 2026-10-03; REL-local core, intrinsic live F8 and explicit offline H1–H8 implemented and reviewed.** The [C12 production disposition](../freshness-historical-production-disposition-2026-10-13.md) closes the native historical release after C1–C11 verification. Live F8 is always part of REL Freshness and has no activation switch; historical reconstruction remains an explicit offline operation and is not automatically invoked by normal runtime startup. Universal context-delivery/Ego consumer wiring and PHY Freshness remain separate incomplete work. Retained historical measurements distinguish actual first-cycle evidence from the one-time labelled legacy approximation; neither provides human relevance labels for changing semantic-policy constants. This ADR withdraws ADR 0033's mandatory stale-Memory Perception/Chronos audit. Archive accepted activity remains the authoritative REL clock; existing Observation/Chronos/Dream/Ego ownership contracts are unchanged.

## Context

Periodic per-Memory review deadlines, separate Community and access windows and a semantic reinforcement audit proved unnecessarily complex for the actual objective: prioritizing a finite context around subjects receiving recent attention. REL accepted turns are the one canonical measure of conversation progress. Insomnia/Dream already generate the Memories, relationships, duplicate components and derived Leiden Communities needed to interpret *where* that activity is concentrated.

Freshness may decline even while a fact remains true. It must not be confused with semantic contradiction, valid time, archival or model confidence.

## Decision

- One bounded signed -100..+100 integer Freshness score per Memory; new Memories start at +100. Derived states: Fresh +1..+100, Stale -50..0, Dormant -100..-51. No separate mutable lifecycle truth.
- Creation initializes a Memory at +100 with no propagation: it initially has no connections. First accepted MemoryStore publication creates local +100 state without starting decay for newly `extracted` Memories. **Ordinary Memory-Web admission is the first successful settled Dream lifecycle promotion to nonarchived `knowledge` or `canonical`, even if no relationships are found**. A newly direct-published Memory explicitly already in an active state may admit at first publication. The Graph's physical Memory projection records relation endpoints only, so first edge is not a universal admission boundary; an edge may exist before final settlement and isolated settled Memories may lack Graph nodes. Prepared drafts, no-change replay, later reprocessing and revisions do not reset admission. Lazy decay thereafter loses one point per ten accepted owner-REL turns, preserving the sub-10-turn remainder and continuing to -100. No wall-time aging or all-Web per-message score rewriting.
- Events: qualifying direct access adds +25; only **actual committed first-cycle Dream relationships** add +50 to existing linked information, including an established Dream-resolved duplicate canonical representative. No relationship means no linkage propagation event. Scoring, event ordering and propagation are deterministic even though event-producing models are probabilistic.
- Use binary Dream graph relationships, hop distance and one fixed **originating Leiden Community**. Normal per-hop reduction is 5; **any hop outside the originating Community** costs 10, including subsequent hops inside other Communities. Do not invent generic numerical Dream link strengths or an arbitrary distance cap; stop when the next candidate is nonpositive.
- Each Memory can be reinforced **once per originating event**, using the strongest eligible graph path, never the sum of several paths. Received score increases do not generate new events; independent later real events are cumulative. A Dream duplicate-chain rewire alone is not an event.
- Build bounded concurrent propagation from the outset, with descending remaining-reinforcement frontier barriers and deterministic commits/ordering. Use idempotent owner-local event identity and crash-safe multi-node effect publication. Derive an indexed next-lifecycle threshold from score and the existing REL activity clock.
- Ego consumes graded Freshness for routine context selection without deleting Memories or violating the established full-Web-if-economical, mandatory broad audit and protected hard-keep rules. Freshness does not require Perception or Chronos verification. Summary regeneration source-progress scheduling is **separate**.

## Superseded proposal and boundaries

This supersedes per-Memory `MemoryReconsideration` registration/`next_review_at` reviews, 500-turn elapsed review gating, four-new-Memories-in-100-turn reactivation, separate access/Community decay counters and mandatory evidence-time Perception audit for relevance recovery. Generic typed source-progress comparison already implemented for future Ego summary scheduling is retained as an independent utility; optional Archive counter materialization remains an independently evaluated optimization.

Current policy is REL-local. PHY has no Archive REL turn clock and must not inherit another REL's clock, wall time or raw PHY Memory versions by accident. The F1 source-inspected contract allows a nonpositive source/recipient to pass along an otherwise positive **single originating event**; remaining event strength alone determines propagation. +25 access requires an explicit accepted context/use receipt, never an automatic low-level read or search hit. Initial Dream settlement yields at most one multi-root event per newly created Memory, based on genuine first-cycle links to pre-existing Memories, including initial committed links preserved across partial-attempt retries; no node update or raw duplicate-chain rewire may create another event.

## Semantic activity reinforcement extension (live and historical explicit opt-in implemented)

Ingested conversation activity supplies a direct relevance lane independent of committed Memory use or newly committed Dream relationships. Consume genuine retained Archive fragment embeddings, including mixed-turn fragments, once at their latest represented accepted activity position. With a compatible profile and owner scope, apply the inclusive cosine **0.75**, monotone **+1..+10** curve and **top-64 eligible local roots per fragment**. Take the strongest match per fragment/Memory and exclude every represented source and its generating cohort. Fixed owner/domain/FragmentId identity permits one award per fragment/target; overlapping distinct fragments remain independent, while re-embedding/profile rotation cannot re-award the same observation. [Calibration](../freshness-semantic-calibration-2026-10-11.md) freezes the constants; [normalization](../freshness-retained-fixture-normalization-plan-2026-10-12.md) records the accepted source/clock correction. Relevance-quality evidence informs threshold/bonus policy tuning; F8 itself is intrinsic and is not activation-gated.

**Normal/live semantic bonuses are local only and never launch graph propagation.** A vector match means the subject is receiving attention, not that all connected facts were consulted. If the matching Memory is independently delivered and genuinely consumed, its separate explicit accepted-use receipt is eligible for the already-defined +25 propagation path. Graph reachability, search hits and internal reads alone do not constitute accepted use. Semantic matches must never recursively reinforce one another or create new activity events from their score updates.

Reuse the **same bounded -100..+100 score**, REL accepted-turn clock, lazy-decay accounting, existing durability/reconciliation boundary and existing policy-version discipline. Do **not** create a semantic reinforcement ledger, parallel freshness score, access-history surrogate, new global semantic ticket or second persistence subsystem. Candidate lists and similarity measurements can be discarded after processing; where the current durable Freshness event contract requires retry-safe identity/ordering, carry the minimum accepted-turn/source identity through its existing journal and compact-receipt mechanisms rather than accumulating a new per-Memory semantic history. Any event-type/policy extension must be versioned and tested for deterministic replay across worker counts, retries, reopen, reconciliation and repack.

**Import and regeneration boundary:** Normal live semantic bonuses remain local only. A separate, optional **historical import reconstruction** mode is accepted for a freshly generated complete imported corpus. It reconstructs provenance-timed semantic activity and approximate first-cycle Dream reinforcement against the **single completed Dream graph**. Only **historical-import semantic** reinforcement propagates, under a separate versioned import policy. Historical propagation may traverse future/ineligible Memories, but source event timing and **recipient credit** obey provenance-based eligibility; ordinary owner authorization never relaxes. Replay per-Memory events chronologically with the existing lazy decay and per-event -100/+100 caps, beginning at +100 and approximate historical Web admission. Never invent historical +25 consumed-use events.

Archive regeneration of an **already-enrolled** owner restores existing authoritative Freshness and never reissues either kind of reinforcement. New-corpus generation can already produce provisional +100 birth and first-cycle Dream effects: one atomic, owner-local superseding checkpoint must replace the provisional **scoring projection**, not append retrospective effects to it or delete Dream evidence. The complete design, its accepted approximation, explicit REL/PHY clock restrictions and independent H1–H8 implementation gates appear in [historical reconstruction](../freshness-historical-import-reconstruction-spec-2026-10-03.md). The owner-derived native coordinator, generation/provenance/graph/vector barriers, bounded offline embedding and CVAFRS03 replacement/recovery are implemented and reviewed in [C12](../freshness-historical-production-disposition-2026-10-13.md). Ordinary current imports use genuine completed Dream proof; missing proof remains unsupported and verified no-link never falls back to later adjacency. The deleted one-time retained-fixture normalizer supplied explicitly labelled legacy approximation only where retained evidence proved it. No public legacy conversion framework is maintained. The dated [Step 26 review](../freshness-combined-production-review-2026-10-12.md) preserves its earlier blocked diagnosis, superseded by C1–C12 closure.

This extension is an ingestion-time relevance signal, **not** the superseded periodic semantic/Perception audit. The existing direct-use and first-cycle Dream event principals and graph propagation rules are unchanged. The [frozen v1 calibration](../freshness-semantic-calibration-2026-10-11.md) selects the inclusive 0.75 threshold, +1..+10 curve and top-64 local limit. Prospective owner opt-in is implemented; [Step 12 release verification](../freshness-semantic-release-verification-2026-10-12.md) owns the executed standalone gates. Automatic activation and policy upgrade remain unsupported. Historical integration, native crash recovery and retained-corpus acceptance are complete for the explicit offline REL scope in C12; mounted historical management and PHY remain deferred. Existing F2–F7 principals and ownership are unchanged.

## Consequences and verification

- An unreinforced +100 Memory reaches 0 after 1,000 accepted **post-admission** REL turns and first Dormant score -51 after 1,510.
- Duplicate-component canonical target selection must follow Dream's existing active/canonical ownership, not assume an arbitrary chain endpoint.
- Persistence must distinguish Freshness metadata/event results from semantic Memory revisions and preserve exact accepted history across reopen and physical transformations.
- Tests must cover stronger alternate paths, arbitrary cycles, originating-Community exit/re-entry, long duplicate chains, negative/positive score transitions, concurrent interleavings, retries and crash safety; measure dense Community reachability before adding optimization beyond natural positive-score stopping.
