# Critical behavioral contract matrix

Parent index: [Development](./INDEX.md)

## Purpose

Map critical state, authority, concurrency and recovery claims to focused executable checks and expose what static architecture policy cannot prove.

## Overview

This is a test route, not a replacement for the owning prose or a passing-test report. Test paths are repository-relative; names below identify actual tests inspected at implementation baseline `fa574eec`. The [workflow](workflow.md) runs workspace, CLI and separate Root-only consumer suites. Historical live/corpus evidence is retained in [disposition](document-disposition.md); no real provider or corpus mutation is needed for these gates.

## Verification limits

Cargo package edges and supported semantic imports can be checked statically. They cannot prove single-writer runtime behavior, fsync/crash semantics on every filesystem, provider quality, complete privacy, or every scheduling interleaving. The focused tests above cover named cases. The focused per-path lock test proves mutual exclusion/release of the locking primitive. It does not prove every end-to-end concurrent credential-write or legacy-migration interleaving; stale-handle/key lifecycle tests cover the named sequential cases. A new lifecycle, recovery, receipt or concurrency promise needs a test and current owner update; absent tests remain an explicit gap rather than an implied proof.
