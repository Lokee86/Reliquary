# Switchboard first-class crate extraction — implementation specification

**Status:** Implemented; functional acceptance passed, with fresh architecture evidence and documentation ownership enforcement pending (2026-10-27).
**Target:** `crates/reliquary-switchboard`, currently a zero-API placeholder.
**Baseline:** `refactor/crate-first-restart` at `ae2d555a`. **Mode:** correction-only, staged hard cut with bounded compiled integration gates. **Sequence:** immediately after Chronos. Do not mix the retained Graph evidence edit or temporary `t/` runtime-test artifacts into this cut.

## Problem and target

Model routing, configured provider adapters, credential security and local configuration currently compile inside the root product, even though semantic consumers should depend **downward** on a replaceable model execution service. Their existing root placement permits Dream/Insomnia/Chronos/Retrieval/Entity and Gateway code to accidentally reach provider credentials or share transport-policy state.

The compiled `reliquary-switchboard` crate is the **single owner of model endpoint identity, route selection, credential security, provider invocation and the machine-local configuration framing needed to load those settings**. No semantic model prompts, decision criteria or Memory/REL/PHY authority moves into it. The product root continues to assemble configured runtime services and issue semantically authorized work.

**Required outcome:** Root uses canonical Switchboard types and transport without copied endpoints, credentials, routing implementations or caches. Provider/config bytes and observable behavior stay the same. The complete root/CLI product remains usable. No new daemon, VCS format, custom analyzer, endpoint registry or generic dependency-injection framework is created.

## Non-negotiable design decisions

1. **Dependency DAG.** The crate map currently lists `reliquary-switchboard: []` (no internal Reliquary dependencies). Treat that as the target. `ModelSwitchboard` is an infrastructure service; it must not import Memory, Archive, Dream, Insomnia, Chronos, Context, Runtime Gateway, or REL/PHY Container ownership. Third-party `reqwest`, `serde_json`, `aes-gcm`, `zeroize`, `sha2` and platform libraries are allowed when actually used.
2. **Embedding normalization type gate.** Existing `EmbeddingModelEndpoint.normalization` and `EmbeddingEndpoint` use `VectorNormalization`, presently re-exported from `reliquary-vector-store` by root `embedding_endpoint.rs`. This is a **real compiled boundary conflict**. Resolve and document one canonical owning value type **before** moving embedding model/transport; do not silently add Switchboard → Vector Store Cargo dependency contrary to the crate map, duplicate enums and maintain mirrored states, or put vector storage in Switchboard. If the single public enum must be relocated to an existing genuinely neutral lower crate, explicitly record and approve the minimal crate-map amendment and update direct consumers in one cut. Alternatively keep the vector-specific projection/conversion above while the canonical provider transport is lower, using an explicitly typed and justified **single** boundary seam; no independent mutable state or long-lived duplicate model shapes. This decision is an implementation prerequisite, not an invitation to expand the refactor.
3. **Config-file ownership.** Current `reliquary.cfg` header `CVCFG\0\r\n`, framing, flags, ordered objects, object schemas and atomic same-dir replacement remain byte-identical. Lower exposes a *narrow raw document object map* for upper domain payload validation plus canonical model/credential object operations. `ReliquaryConfig` preserves existing public fields and product validation. An invalid config must fail closed, and unknown non-model objects retain exact bytes. Retired `models.chronos` still rejects rather than silently surviving as an extension. Do not break old config credentials by re-encrypting unexpectedly on read, creating a new master key on read, or changing AAD/nonce rules.
4. **Schema-2 General read exception.** Existing `models.general` schema 2 remains deliberately readable alongside the *current written* schema 3, as explicitly documented in `docs/configuration.md`. Audit whether external saved configs require that read support. **Do not remove** an externally meaningful existing format reader merely because internal dev files are current; if migration-only, record evidence and move to single current reader with converted development corpus and no permanent compatibility machinery. Otherwise retain only the justified config boundary compatibility (not REL/PHY historical readers). Do not invent new schemas.
5. **Typed errors/public identity.** Canonical `GeneralEndpoint`, `DecisionEndpoint`, `GeneralEndpointError` (including Backpressure retry-after), `DecisionEndpointError`, `Configured*Endpoint`, `ModelRequestAuth`, `Credential*`, `ModelSwitchboard*`, `OpenAi*Endpoint` and `OpenAiCodexDeviceAuth` move once. Root exports them without copied definitions; consumers retain existing method signatures wherever publicly supported. Avoid changing Debug/redaction of keys and account IDs. Error conversion may be owned at the product wrapper but must not collapse distinguished invalid route, missing/wrong-kind auth, malformed response, provider backpressure and transport failures.
6. **Route policy once.** Shared decision selector currently in `configured_runtime_decision.rs`: Entity Resolution dedicated → general_decision → adapted general → unavailable; Memory Retrieval dedicated → same; Chronos general_decision → adapted general → unavailable. Move **one canonical selector and endpoint constructor** lower, with consumer enum and missing-route decisions; keep `ConfiguredRuntime::runtime_routes` upper. General routes: Insomnia optionally inherits general, Dream optionally inherits general, metadata/extraction/ownership have their documented distinct precedence. No silent retry to lower tier after the chosen endpoint fails. No revived `models.chronos`.
7. **Provider behavior exact.** Keep OpenAI-ready Chat Completions versus Codex Responses, structured-response forced-tool versus response-format selection, reasoning-effort and provider capabilities, status/retry/backpressure semantics, bounded embedding transport, JWT/account-id and device-refresh flow. A provider adapter cannot invent a durable owner receipt or invoke REL/PHY mutations.
8. **Authentication/security.** AES-256-GCM credential framing, authenticated object-key AAD, OS entropy, key paths/JSON, zeroize-on-drop, secret-debug redaction, `Authorization` and `ChatGPT-Account-ID` handling unchanged. No credential bytes in errors, logs, snapshots, routing diagnostics or fixtures. Keep exact OAuth refresh and missing/wrong-kind error behavior. External HTTP still must not be called during replay/history operations.

## Verification / acceptance matrix

**Lower crate:** `cargo check -p reliquary-switchboard --locked --offline` and `cargo test -p reliquary-switchboard --locked --offline`; inspect manifest and source imports to reject any unexpected Reliquary dependency; no root/shared-model copy.

**Config/security:** byte-level roundtrips for general schema 3 (and justified schema 2 read), decision schema 1, embedding schema 2; unknown-object/flags/key preservation; duplicate/truncated/wrong-version rejection; missing/wrong-kind credentials; master-key persistence, corruption, atomic replacement and failure rollback; wrong AAD/object ID rejection; OS entropy/redaction tests. Existing application `ReliquaryConfig` behavior and CLI show/set/clear remain stable.

**Decision/general routes:** all route precedence, Chronos shared decision/general fallback and no dedicated model, provider choice and reasoning effort, missing-route/invalid-credential errors; same request body/schema and choice ID restrictions. No fallback following provider failure, no confidence fabrication.

**Network/provider:** OpenAI-ready forced-tool/response-format JSON and malformed output, Codex SSE partial/failed/incomplete response, retry-after and bounded backpressure, device-auth and token-refresh paths, embedding dimensions/batching/cancellation. Run localhost test transports under an allowed environment or explicitly qualify network-denied failures; never count skipped fixtures as passed.

**Consumers:** root configured Insomnia/Dream/Chronos, Entity and Memory Retrieval decision workflows, runtime-host/Gateway route composition, embedding and externally supplied transcript processing. Verify read-only REL/PHY/history/reopen operations issue zero model calls; no provider transport inherits owner state authority.

**Integration:** `cargo check --workspace --locked --offline -j 1`, `cargo fmt --all -- --check`, `cargo test --lib --locked --offline -j 1`, `cargo test --manifest-path cli/Cargo.toml --locked --offline -j 1`, `ddocs check --indexes --links` and focused configuration/transport suites. Run docs-policy check separately and record any inherited failures. Keep CVAFRS07 and a fresh Arcana graph as separate, explicitly unclaimed gates unless executed; do not create an analyzer. Cargo/source inspection is the architectural authority.

**Complete only when:** compilation shows a genuine lower Switchboard used by public root and actual consumers; config and secrets remain one canonical secure owner, single route evaluator/transport, no root reverse dependency or duplicate endpoint types, byte-equivalent current configuration and secret framing, and focused/full verification evidence committed.

## Out of scope

New provider implementations, model capabilities, semantic prompts, inference policy changes, OAuth security redesign, new credential vault, general config-file migration unrelated to verified consumer needs, REL/PHY format changes, automatic remote retries between model tiers, extracted Gateway/Context Engine/Insomnia business services, extra architecture analyzers, performance retuning and speculative framework layers.
