## Purpose

This is a source-reviewed inventory at commit `529f2a8` (Phase 2 spec) against accepted Phase 1 implementation commit `8614547` and the retained Phase 0 capture. It does not claim that Phase 2 code changes or tests have run.

## Overview

Phase 1 changed the physical Container boundary and completed its Windows acceptance. It did not complete the owner-local semantic boundaries. Current Rust still places several store implementations beside facade/runtime code and some stores import sibling stores or interpret sibling-owned records. The 34-component DAG is the accepted target; the Phase 0 19-area graph and 4,625-classified-finding ledger remain historical evidence and are not a second target or a refreshed source scan.

A source-level edge is classified here as **production** when it appears in executable store/service code, **test-only** when confined to test modules, or **mixed** when production and test paths coexist in the coarse folder. All arrows below are consumer → dependency. This is a bounded textual source-reference inventory over the selected durable-owner roots and the exact store/facade/runtime module paths listed in the companion JSON, not an exhaustive compiler-resolved graph. In particular, `crate` reexports, inherent `impl Cva` blocks, macros, and type-only references require review at each cut; do not infer edge removal from a moved file name.

## REL / PHY replay order and validation boundary

Phase 1 moved physical framing to caller-pulled Container cursors. The preserved source-order composition is recorded in [Phase 1 verification](dependency-convergence-phase1-verification-2026-10-22.md), in the sections “REL replay dispatch” and “PHY / Phylactery replay”; this inventory points back to that accepted sequence rather than duplicating every variant route.

For the exact numbered REL and PHY owner routes, finish sequence, and post-replay validation sequence, see the linked Phase 1 source-reviewed oracle above. Its REL finish ordering is Archive + Archive validations → Memory + prune history → Entity + Relationship + local refs → Ego/Memory/processing-epoch/Dream-pair/provenance/file-target checks → Graph/rewrite baseline → Communities + Insomnia/schedule → deferred Dream/Freshness work → vectors/profiles/generations + semantic clocks → compaction evidence → import evidence → Cva construction and final prune/settlement/entity-resolution validation. PHY order is also captured in that oracle.

PHY replay first routes rewrite-lineage validation and rejects REL-only records; ingests owner-maintenance evidence; decodes publication envelopes and tries Memory → Entity → Relationship → Graph, rejecting unsupported bodies, otherwise feeds legacy-capable Memory/Entity/Graph/Relationship; then ingests Communities, packed vectors, Memory vectors, compatibility profiles, PHY profile, processing epochs, Dream pairs, Ego and Entity resolutions.

After EOF, REL installs physical clock state; validates REL identity and owner rewrites; finishes Archive, Memory and Relationship; validates Archive Memory-link targets and local references; finishes Entity and validates local references plus principal restrictions; validates Ego against Memory version/provenance; validates processing epochs and Dream pairs; finishes Graph and checks rewrite baseline; finishes Communities and semantic global versions; finishes vector/profile/generation stores and their global clocks; finishes compaction evidence without reclaim; validates import owner/receipts; constructs `Cva`; then runs prune, settlement/completion and Entity-resolution validation. PHY installs clock state, revalidates PHY identity; finishes Memory, Entity and Relationship; validates their local references and rejects principal Entity records; validates Ego/Memory version, provenance, processing epochs and Dream pairs; finishes Graph/rewrite baseline; finishes Communities/global versions; finishes vector/profile stores; constructs `Phylactery`; then validates prune evidence and Entity-resolution consistency.

Phase 2 may split **cross-owner** checks into lifecycle/coordinator composition but must retain this route order, validation order where observable, failure point, and no-write-on-open property. It does not add open repair. This is a before-order map, not evidence that these checks currently live in the right owner.
