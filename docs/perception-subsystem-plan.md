# Perception future implementation plan

Parent index: [Documentation index](INDEX.md)

Current implementation: [Perception](subsystems/perception.md) · Decision owner: [ADR 0033](decisions/0033-perception-entities-observations-and-ambiguity.md)

## Purpose

Complete the Observation half of Perception on top of the implemented Entity/mention-resolution foundation.

## Overview

Current production Perception already owns Entity mention state, durable Entity resolution/admission, bounded reconsideration scheduling, typed graph association, and ambiguity-safe identity handling. Those contracts are documented in [Perception](subsystems/perception.md) and [Entity resolution state](entity-resolution-state.md).

The remaining design is propositional: create durable Observations from Memories/Observations, select bounded comparison contexts, expand evidence after a candidate proposition exists, verify reasoning, generate routing receptors, and reconsider Observations over time.

This plan keeps enough target architecture to guide implementation without preserving the earlier Entity implementation diary.

## Target semantic model

Perception distinguishes:

- **Entities** — referential identities used for traversal/association;
- **Memories** — source-grounded propositional nodes;
- **Observations** — derived propositional nodes with explicit support/derivation evidence; and
- **relational Observations** — Observation specialization whose proposition concerns at least two canonical Entity participants.

Entities do not count as standalone propositional evidence. They route to propositions that do.

Relationship is intended to converge into the relational-Observation model rather than remain a parallel long-term semantic authority.

## Anchor eligibility

A newly created propositional node becomes an Observation-processing anchor only after its own required processing is complete.

For a Memory this means, at minimum, Dream organization and Entity resolution needed by the candidate-selection lanes. For an Observation it means its own publication/required processing has completed.

Entity creation alone is not an Observation-processing anchor.

## Whole-Web bootstrap

When the complete authorized propositional Web fits comfortably inside the synthesis context budget, Perception may process the whole eligible Web.

This is the preferred small-Web bootstrap. Do not invent routing complexity simply to avoid using context that already fits.

Once the Web no longer fits, use the bounded lanes below.

## Exploitation

Exploitation follows already-established reasons for comparison. Embedding similarity by itself is not a sufficient Exploitation route.

Initial candidate lanes:

### Entity bridge

Start from durable canonical Entity references on the anchor and locate other propositions that reference the same relevant Entity/set. Entities route; selected Memories/Observations become evidence.

### Source neighbourhood

Use concrete provenance locality such as Episode, conversation, document, import unit, or bounded transcript/document region.

Large sources must use bounded windows rather than making the whole source one context.

### Web-structure / regional neighbourhood

Use existing Dream/Graph structure, bounded paths, and coherent Community/subcommunity locality. Community is one routing signal, not an inference boundary.

### Derivation neighbourhood

Use accepted Observation support/derivation topology: parents, children, shared-support siblings, and related derived propositions.

### Overflow

Candidates generated by valid Exploitation lanes but omitted due to context/inference budget may enter a bounded overflow reservoir for later Exploration.

## Exploration

Exploration deliberately tests comparisons not already prioritized by the Web.

Initial lanes:

- Exploitation overflow;
- semantic similarity;
- lexical similarity;
- cross-region/Community sampling; and
- bounded random sampling.

Exploration must not maintain a permanent "pair completed forever" ledger. Use bounded recent-comparison history so novelty is encouraged while later changed evidence can make an old pair eligible again.

Exact lane weights, candidate caps, and spillover are calibration work.

## Multiple comparison jobs

One anchor may emit several narrow contexts rather than one blended prompt. Context identity should include the reason/lane so overlapping evidence sets can still represent meaningfully different comparisons.

Duplicate identical work should be suppressed.

## Two-stage candidate selection

Observation formation uses two selection stages:

1. **discovery selection** creates a bounded context and proposes zero or more candidate Observations;
2. **reasoning-directed evidence expansion** gathers the extra support, contradiction, qualification, counterexamples, complementary premises, or alternatives needed to evaluate a specific candidate.

The second stage is goal-directed retrieval, not another generic Exploration pass.

## Reasoning modes

The initial reasoning taxonomy is:

- **Deductive** — conclusion follows from supplied propositions.
- **Inductive** — several examples support a bounded generalization; seek counterexamples.
- **Abductive** — candidate is a plausible explanation; seek competing explanations/discriminating evidence.
- **Abstractive** — consolidate several grounded propositions into a higher-level representation without adding unsupported consequence or causal/generalized claims.

Abstractive must not become a catch-all. If a candidate cannot be justified under a defined reasoning contract, abstain.

After evidence expansion, reasoning-specific verification must evaluate the exact evidence. A generic confidence score does not substitute for the reasoning contract.

## Observation publication

A published Observation should retain:

- proposition/body;
- ordinary versus relational profile/class;
- derivation/reasoning mode;
- exact support/derivation lineage;
- challenge/qualification relationships where applicable;
- referenced canonical Entities;
- Chronos temporal semantics where applicable;
- owner/visibility scope; and
- optional discovery-route diagnostics that are not semantic authority.

Evidence is many-to-many. Reusing the same underlying source through several derived paths does not create independent corroboration.

## Relational Observations

Additional deterministic gates apply before relational synthesis:

- anchor/evidence must reference durable Entities;
- the candidate set must introduce at least two distinct canonical Entity participants in the resulting relationship;
- a relational Observation cannot recursively participate as evidence/anchor in another relational-synthesis job.

Relational Observations may still contribute to ordinary higher-order Observations and may themselves be reconsidered.

Owner-qualified participant references do not transfer Entity payload ownership. Active-PHY privacy and authorized-REL visibility remain explicit.

## Routing receptors

Every new or materially rewritten Observation should receive separate receptor generation.

A receptor describes future propositions that could materially support, challenge, qualify, or trigger reconsideration of the Observation. Receptors are embedded independently; do not collapse them into one centroid when relevant future evidence can occupy distinct semantic regions.

Receptors are routing aids, not truth.

## Reconsideration

Relevant contribution mutations accumulate against an Observation. Crossing policy thresholds can trigger semantic reconsideration.

Reconsideration may:

- keep the Observation active;
- qualify it;
- supersede it;
- expose contradiction/ambiguity; or
- change currentness/priority.

Mutation proves that reevaluation is warranted, not that the Observation became fresher.

## Currentness and wall time

Do not apply one wall-time staleness rule to every Observation.

Current-state propositions may use deterministic wall-time checkpoints. Durable/historical propositions may be exempt.

If an Observation class enables a wall-time checkpoint:

- no relevant mutation since the last reconsideration may allow a deterministic stale/currentness transition without inference;
- one or more relevant mutations triggers semantic reconsideration.

"Stale" means currentness uncertain/non-priority. Wall time alone never means false or deleted.

Chronos valid time and Observation currentness remain separate.

## Ambiguity

Perception may persist unresolved Observation ambiguity just as it already persists Entity ambiguity.

When a later user turn deterministically intersects unresolved ambiguity, the runtime may inject a bounded clarification instruction. User clarification returns to Perception; do not generalize this into an unlimited curiosity/open-question subsystem without evidence.

## Scheduling

Exploitation and Exploration should be staggerable rather than running together on every anchor/cycle. Missed epochs do not accumulate an unlimited backlog.

Lower-level Graph/Entity/Community mutations update the structure seen by the next eligible processing round; they do not recursively trigger unbounded synthesis themselves.

## Implementation sequence

1. Define Observation persistent model, ownership, lifecycle, provenance, and codecs.
2. Implement propositional anchor readiness and scheduling.
3. Implement whole-Web bootstrap and bounded Exploitation lanes.
4. Add recent-comparison history and Exploration lanes.
5. Implement discovery proposal contract.
6. Implement reasoning-directed evidence expansion.
7. Implement reasoning-specific verification and abstention.
8. Publish ordinary Observations with exact lineage.
9. Implement relational Observation specialization and privacy.
10. Generate/update routing receptors.
11. Implement mutation/currentness reconsideration.
12. Add Observation ambiguity/clarification integration.
13. Calibrate candidate budgets, lane weights, cadence, and model cost on retained corpora.
14. Converge transitional Relationship persistence into the accepted Observation model where migration/compatibility policy allows.

## Acceptance

Before calling Observation Perception complete:

- small-Web whole-context bootstrap works;
- large-Web lane selection remains bounded;
- multi-job contexts are deterministic/replayable where required;
- exact evidence lineage survives reopen/reconciliation;
- duplicate underlying sources do not fake corroboration;
- relational privacy boundaries hold;
- reasoning-specific verification can abstain;
- receptor routing does not become semantic authority;
- reconsideration/currentness semantics are explicit;
- Chronos integration preserves ownership separation; and
- full owner/storage/architecture/documentation gates pass.

## Non-goals

- making Communities semantic truth;
- using similarity alone as Observation authority;
- treating Entities as propositions;
- reviving Perception as a mandatory Memory Freshness gate;
- using a generic confidence score as reasoning proof; or
- retaining Relationship as an indefinitely duplicated semantic authority.
