# Shared Memory Web audit and first Perception Observations

Parent index: [Planning](./INDEX.md)

## Purpose

Give Ego and Perception one way to audit an authorized Memory Web with predictable coverage and cost. Ego uses it to extract grounded material for summaries. Perception uses it to discover and verify Observation candidates, including Relationships between Entities. Core already resolves mentions and finds Memories and Relationships by Entity. It currently lacks the audit controller and a product path that turns those inputs into Observations. [Current semantic processing](../architecture/semantic-processing.md) · [Historical Ego audit](https://github.com/Lokee86/Reliquary/blob/2b5bd0eabfbac0a85f899d7d730220b5e8e93efa/docs/ego-service-crate-extraction-spec-2026-10-28.md#L55-L77)

## Overview

Application captures an authorized source cut and supplies the audit inputs. The shared audit covers batch selection and exposure, optional browsing, and extraction of candidates with source references. That is where an audit ends. Later steps prepare the material for Ego summary generation or verify and publish Perception Observations.

## Ownership and scope

| Owner | Contract |
| --- | --- |
| New internal audit crate, `reliquary-memory-audit` | Plan bounded batches from an ordered, supplied working set, track mandatory exposure, run the caller's extraction contract, allow bounded evidence requests, and bind results to Core-issued source references. |
| Ego semantic crate | Select its working Web and extract candidate subjects and their supporting Memories. Prepare typed, source-linked inputs for later summary generation. |
| Perception semantic crate | Select routine and older Memory inputs, extract ordinary and relational candidates through distinct prompts and schemas, and verify proposed claims. Define when an existing Observation needs reconsideration. |
| Gateway, Application and owner-session | Gateway supplies current grants, a stable mount and scheduling. Application composes the shared audit and domain contracts using a configured endpoint. Owner-session prepares exact, read-only facts and publishes accepted Perception work through the owning store and native commit boundary. |

Both semantic crates depend on the auditor and Application depends on those semantic crates. The auditor accepts immutable batch values and an authorized lookup callback. Perception supplies its own typed candidate context. Authorization, source selection policy, publication, and provider configuration stay with their existing owners. Use `ConfiguredRuntime::general_endpoint()` via Switchboard for initial audit, extraction and verification. Pin the nonsecret route and contract version for each attempt. An unavailable route leaves work pending, with a bounded retry delay for transient failures. Future specialized routes can bind through the same boundary. [System architecture](../architecture/system.md) · [Switchboard runtime](../../crates/reliquary-switchboard/src/configured.rs)

The release slice covers one authorized REL per audit. It delivers Ego audit/extraction through Application and durable ordinary and relational Perception Observations through Core. Full Ego summary generation, PHY summary persistence and context injection are follow-on work. Cross-REL/PHY Observation synthesis, full exploratory routing, Observation-to-Observation inference and live-provider calibration are outside this slice. Preserve owner-qualified references for later work. A future cross-REL route that relies on identity must use the authorized current effective decision, including operator-confirmed separation. ## Shared audit contract

- The consumer provides an ordered working set at a captured owner cut. Use the whole working set in one batch when it fits. Otherwise split it into deterministic batches. Every admitted Memory must receive mandatory exposure before that run completes. Resolve references to exactly the captured revision. New writes can feed the next run. A withdrawn, replaced or unavailable required source invalidates the affected work. A permanently unavailable body is reported as excluded when planning the next working set.
- Each input identifies owner and history generation, Memory ID, revision and body ID, field and UTF-8 range. Give the model request-local source and participant slots. Bind those slots in Core. Count exposure only for slices actually sent as mandatory input on a successfully processed batch. Split oversized admitted bodies at UTF-8 boundaries and track their mandatory slices. Optional context and search results never satisfy mandatory exposure.
- An extraction or a candidate verification may request evidence relevant to its own task. Allow one optional follow-up request per extraction or verification, with at most two authorized lexical searches and four returned passages per query. Search can follow a lead beyond the batch, including through Stale or Dormant evidence. Restrict it to the same authorized source REL and the captured evidence. Reuse indexed lexical candidates and hydrate only selected bodies. Recheck authorization and body identity before sending results. All reads are non-reinforcing.
- Start with at most eight mandatory slices and 24 KiB of mandatory source text per request. Allow up to 8 KiB of optional passages within a 64 KiB serialized request and a 16 KiB response, subject to lower endpoint limits. Limit each extraction to four output items per response and verify at most four candidates in one bounded batch. Enforce those limits before provider dispatch or result acceptance. Apply one shared accounting path to mandatory input, optional evidence, retry and completion. A failed or malformed response earns no coverage. Bound each poll and continue from the last proven frontier. Keep private text and provider replies out of progress records and diagnostics. Adjust policy constants from observed workloads without changing the storage format.

## Working set and candidate extraction

**Ego.** Carry forward whole-Web-first admission. If the authorized, readable Web exceeds one audit window, apply the established reduction order for mandatory input: Archived, Historical, Dream-recognized duplicates, Superseded, the Dormant band, then the Stale band. Recheck the budget after each step. Batch the remaining set if necessary. Search remains available for authorized older evidence outside that set. The Ego schema proposes subjects and source slots. The Ego extraction stage prepares each accepted subject with its exact supporting source set for later summary work. Optional search or candidate prose cannot substitute for that provenance. [Ego policy](https://github.com/Lokee86/Reliquary/blob/2b5bd0eabfbac0a85f899d7d730220b5e8e93efa/docs/ego-service-crate-extraction-spec-2026-10-28.md#L55-L77)

**Perception.** An invoked audit can read a Memory after Insomnia and Dream settle it. These conditions establish source readiness. Opening or inspecting a REL performs read-only work. Wait for required mention decisions to settle before relational discovery. Ordinary work can proceed while Entity evidence is pending. A later mention resolution or withdrawal makes the affected source eligible for relational work again. Bootstrap existing RELs in stable bounded pages and coalesce new or corrected Memory revisions through an owner-local frontier. Use current, readable, directly supported Memory revisions. Treat archived, retired, superseded and pruned sources according to their actual lifecycle. Stale and Dormant grades alone keep an otherwise eligible Memory in scope.

Some Perception audits must explicitly include older Memories. When a run requests older-Memory sampling, reserve one mandatory slot for each of the Stale and Dormant bands, even when recent work fills the batch. Rotate independently within each band by stable Memory ID with wraparound. A sparse band can carry its scan forward across polls. Visit at most 128 metadata rows per poll and reserve sample work independently of routine work. Resume from durable progress after a restart. Progress stores the ordinary and relational settled-source frontiers, per-band scan positions and the last accepted batch identity for the owner history generation. An interrupted batch resumes from the last committed positions. An empty band releases its slot and lets routine work continue. Use the owner’s current Freshness policy and accepted turn with same-turn events included. Missing grades place a Memory outside the two sample pools. Audit reads leave grades unchanged.

The shared auditor runs when a consumer invokes it with a working set and budget. When to start the first audit, which events trigger routine runs and how often Perception requests older-Memory sampling are open scheduling decisions. They belong to the caller’s runtime policy.

Perception extracts a specific proposition and the references that prompted it. Verification consumes those candidates in a later stage. Verify each candidate separately against exact evidence. The verifier may confirm the claim as written, qualify it with narrower wording, or leave it unpublished. Use targeted lookup to add support or counterevidence when needed, then require citations for the accepted wording. An empty discovery result skips verification. Count two excerpts from one underlying source as one source. The first slice accepts direct statements or a bounded conclusion supported by the cited premises. Unsupported generalizations, unresolved contradictions and causal guesses remain unpublished. Record temporal scope where the cited evidence establishes it. Reuse Chronos to normalize dates and retain uncertainty when the evidence leaves valid time open.

## Relationship candidates

1. Start with the resolved Entity IDs on an admitted Memory. Reuse owner-session's Memory-to-Entity lookup, current resolved mention reverse lookup and active one-hop Memory Graph neighbors. The candidate context can include a second Entity in the same Memory or in a nearby linked Memory. Honor current mention decisions before falling back to supported typed retained decisions from migrated RELs. Participant and graph links select passages. The text establishes the proposition.
2. Deduplicate by owner-qualified participant set and evidence. Use active, distinct canonical Entities. Exclude generic, unresolved or retired endpoints. Bound the first pass to eight eligible neighboring Memories and four candidate contexts per anchor, deterministically ordered with same-Memory evidence first. Support multiple candidate Relationships involving the same participants. The candidate can carry up to four participants and optional role labels.
3. Use the current participant lookup to supply relevant manual or imported Relationships and prior relational Observations. Check a candidate against existing claims. Leave equivalent legacy claims in their original records. Their manual lifecycle remains available. The relational extraction contract returns a proposition, participant slots, optional roles and cited Memory slots. Co-occurrence, equal names or an existing ungrounded description alone leaves the candidate unpublished. The common verification path evaluates the claim and its evidence. ## Publication, reconsideration and compatibility

Publish both profiles through a single typed Observation history in the Perception store. Use a new versioned carrier in the existing native REL publication envelope. Persist the local owner/generation, stable Observation ID, revision and predecessor, active or withdrawn state, proposition, optional supported temporal scope, profile and participant roles, exact evidence references and lineage, and the bound policy/route and input fingerprint. Preserve supporting and contrary evidence references when they govern the decision. Store no provider prompts, source copies or private rationale. Publish the accepted results and Perception progress from one bounded completed batch in a single commit. A valid empty result can advance progress. Transport or validation failure cannot.

Authenticated Perception processing requires the existing writable REL and `ManageRel` boundary. Capture under authorization, perform inference outside the owner lock, and revalidate grant, mount, cited source/body/mention revisions and expected predecessor at commit. Unrelated writes can coexist. Identical accepted input retries return the prior result, including after a lost acknowledgement. A changed cited source or participant marks the existing head pending on read and triggers targeted reconsideration on the normal processing path. Successful reevaluation publishes a successor on the same ID or withdraws its current standing when support has been refuted or lost. Transport failure leaves it pending. A later correction preserves history. Multiple legitimate claims about the same participants can coexist. Check duplicates by profile, normalized claim wording, participants and supported time scope. The verifier can also match paraphrases to an existing claim supplied with the candidate. Reuse the matched Observation ID. Inspect current and historical Observations through paged, grant-checked Root inspection.

Native REL/PHY 2.1 files retain their headers, IDs and existing Relationship frames, revisions, query and maintenance behavior. A pre-feature REL starts with no synthesized Observations. New relational Observations are written once and read through the Observation surface. Existing manual/imported Relationships remain available to their existing consumers and to candidate selection. Their existing Memory-level references carry their original availability semantics. In particular, historical records need no invented citation spans and new inferred Relationships do not feed automatic Entity identity as independent evidence.

Validate new records at their physical publication prefix. Version the private checkpoint and restore the Observation/progress projection on exact reopen. Use the same physical-prefix checks when replaying a new carrier after a verified checkpoint. Unhandled or incompatible checkpoint state falls back to verified ordinary replay. Include the domain in historical proofs. Verified same-owner copies and supported reclamation preserve these carriers. Pruned evidence resolves as unavailable from history. Refuse any unsupported rewrite, divergent reconciliation or prune that would discard a required Observation carrier or evidence proof before creating a destination. Readers predating the new native carrier may reject files after the first audit publication. Document the minimum version that can read those files.
