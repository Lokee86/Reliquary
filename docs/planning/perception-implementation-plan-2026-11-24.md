# Same-REL Perception implementation plan

Parent index: [Planning](./INDEX.md)

## Purpose

Ship the complete Observation lifecycle in one release. Perception discovers and publishes ordinary and relational Observations, finds new evidence for them, reconsiders their standing, and protects downstream Observations that cite them. A single authorized REL owns the source evidence, claims, progress and publication.

## Overview

Implement the shared audit, creation and reconsideration specs as one feature. The implementation order establishes foundations first and joins them before release. A normal mounted REL session must be able to create an Observation from Memories, create a higher Observation that cites it, route an older sample to the original claim, and handle the resulting review and dependency changes. The same REL can contain evidence from several conversations. Cross-REL and PHY synthesis, automatic wall-time staleness, clarification and full Ego summary generation remain follow-on scopes. The release includes Ego's Fresh-only extraction through the shared audit. [Shared audit](memory-web-audit-spec-2026-11-24.md) · [Observation creation](observation-creation-spec-2026-11-24.md) · [Observation reconsideration](observation-reconsideration-spec-2026-11-24.md)

## Release contracts

- The first audit publishes from a bounded page. Recurring runs trigger on each 25 newly settled source Memories and revisit changed evidence and graph endpoints. Pack up to 125 Memories per discovery request, within the route budget. Per run, rotate up to 15 Stale and five Dormant samples into Perception discovery and existing-Observation routing. Preserve separate coverage for both extraction lists and compare each exact source passage and Observation revision only once under a given contribution policy.
- Creation uses **Propose → Synthesize → Receptors → Evidence back-check → Verify → Finalize**. Eligible published same-REL Observations can supply typed citations for later proposals, with exact revision and underlying source lineage. Reuse the relational evidence rules, including the exclusion of relational-to-relational synthesis. Synthesize provides the exact statement and citations. Owner-session owns the only publication authority for both profiles.
- Use the two frozen native Jev contracts. **Contribution** uses one request per existing head and bounded hit batch to decide whether review is warranted. A deterministic invalidation can queue review directly. **Verify** uses one request per exact draft with an overall verdict and per-hit judgments, for creation and review. A material back-check hit vetoes clearance. Use general inference for synthesis and receptor generation, and the configured embedding route for receptor vectors. [Contribution questions](observation-reconsideration-spec-2026-11-24.md#tested-question-templates) · [Verify questions](observation-creation-spec-2026-11-24.md#tested-jev-question-templates)
- A review reuses the current wording when the accepted proof is still eligible. Synthesize a replacement draft when evidence requires a new proof or revised claim. Both use the same Verify contract and publication checks. Reaffirm identical proof without a new revision. Publish a changed verified successor on the same ID, or withdraw current standing when review establishes that no supported claim can stand. Preserve exact historical citations and successor lineage. [Review and successor verification](observation-reconsideration-spec-2026-11-24.md#review-and-successor-verification)
- Pending claims and dependents remain visible for inspection with their last verified wording and explicit status. Current retrieval, final handoff and new derivations require current standing. Reaffirmation of the exact upstream proof can release dependents without inference. Replacement or withdrawal puts affected dependents through targeted review. Reuse REL Freshness, with +100 at birth and eligible receptor awards upgraded once to +25 or +50 only for a verified semantic change.

## Focused release checks

| Seam | Acceptance |
| --- | --- |
| **Deterministic audit and recorded endpoints** | Fit a full 45-input routine run and a 125-Memory working set within a fitting route. Verify the 25 threshold, 15/5 rotation, bounded first-page publication, local change coverage and independent Fresh-only Ego output. Check exact tested question shapes and call counts for both Jev contracts, including rejected later-only or separate-scope contribution, verification veto, malformed reply, and one bounded resynthesis before a verified successor. Exercise the +25 qualification and +50 correction upgrades from an existing base award, with the scoring ceiling and retry receipt. |
| **One mounted REL through the full lifecycle** | Create ordinary and relational Observations through the normal worker, with A supporting B and B supporting C through exact published citations. Route an unchanged older sample, detect a challenge and compare it once. While A is pending, show prior wording in inspection and exclude A/B/C from current delivery and new derivation. Reaffirm A and release the dependents without more inference. Then verify a material change, check its Freshness upgrade and show B and C settle only on current eligible proof. Exercise direct source invalidation and one revocation or changed-source race. |
| **Recovery and compatibility on the same fixture** | Resume across a committed pending marker and a lost acknowledgment. Check ordinary reopen, exact checkpoint, a suffix with Observation work, and one supported verified copy. Confirm old citations and standing survive, one award and successor survive retry, and a pre-feature REL opens with its original header, owner ID and manual Relationship. Resolve older accepted manifests against their exact histories. Block a new handoff if standing changed after retrieval preparation, even when Memory and Graph versions stayed the same. |

The release gate is one complete mounted lifecycle, with scripted endpoints, plus targeted lower-layer proofs for contracts that fail earlier. Run the architecture guard for new crate edges and the repository-required checks at integration. Keep the recorded native Jev trials as the contract evidence. ## Notes

Existing manual and imported Relationships retain their independent management history. New inferred Relationships use the relational Observation profile and the same publication and review path as other Observations. The shared audit is a common input pipeline for Perception and Ego. Ego's downstream summary product remains separate.
