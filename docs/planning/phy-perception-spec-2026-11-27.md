# Perception Observations and Relationships in the active PHY

Parent index: [Planning](INDEX.md)

## Purpose

Give the active Phylactery the same evidence-led Perception lifecycle as a REL. A private claim can be discovered, verified, recalled and reconsidered with exact provenance. A private inferred Relationship uses the relational Observation profile and the same lifecycle.

## Overview

The first Perception release processes one REL at a time. PHYs already have settled Memory and Graph reads, Entity and manual Relationship records, and an Ego audit. The PHY audit currently enables only the Ego output, and Observation publication, replay and delivery assume a REL. Extend those boundaries to one active PHY using the existing audit, Perception, owner-session and Gateway crates. Freshness remains a REL feature. [Same-REL release](perception-implementation-plan-2026-11-24.md) · [PHY discovery](../../crates/reliquary-application/src/perception_workflow/phy_discovery.rs) · [Owner publication](../../crates/reliquary-owner-session/src/session/observations.rs)

Every claim, participant and cited Memory or Observation in this release belongs to the same PHY. For example, private Memories can establish a family relationship between two resolved Entities in that PHY. A retained import accepted as settled can serve as evidence through its exact local Memory revision. Use its origin only to establish lineage. Keep hosted use and any persisted delivery proof within the authorized private scope of the active PHY. Switching the active PHY fences in-flight work and prepared returns from the previous binding. [Active-PHY privacy ADR](https://github.com/Lokee86/Reliquary/blob/a57a823f87399e4c2028dd74987c47cba800067e/docs/decisions/0034-cross-owner-relationship-graph-and-active-phy-privacy.md#L126-L174)

## Audit and Relationship candidates

- **First audit.** When managed Perception starts on a writable active PHY, freeze an eligible cut and page through its entire settled web. Count up to 125 Memories per batch and apply the existing route limits and UTF-8 slicing. Review and new source changes can proceed while bootstrap is still paging. A completed Ego audit supplies no Perception coverage by itself. Run a Perception catch-up if Ego has already covered that history. Resume each list from its own durable cursor. [PHY eligibility and paging](../../crates/reliquary-owner-session/src/session/phy_audit.rs) · [Shared audit](memory-web-audit-spec-2026-11-24.md)
- **Routine audit.** Start with Ego's cadence of five distinct eligible PHY Memory changes, including additions, revisions and withdrawals. Count a Memory once per captured delta. Include affected graph neighborhoods, mention changes and current derived Observation revisions through their bounded change frontiers. These additional inputs do not increment the Memory count. Keep work discovered after a captured cut for the next run. When a required mention resolves or is withdrawn, revisit the affected relational evidence through targeted work. Direct invalidations and new receptor hits also have their own review path and can be processed before the next audit. [Current Ego cadence](ego-implementation-spec-2026-11-27.md) · [PHY scope and replay](../architecture/owner-session.md)
- **Shared discovery.** Extend the audit's settled-PHY mode to admit Perception sources and participant slots. Use one structured audit request when both lists are due for the same captured batch. Retain separate eligibility, outputs and durable acknowledgment. Ego gets suggested topics and exact Memory references. Perception gets proposed claims and exact source references. Its list can also cite current verified PHY Observations under the existing derived-evidence rules. Use bounded owner-local lexical searches and Graph traversal at the captured cut. A rejected or unavailable reply for one list leaves an accepted sibling intact. [Audit handoff](memory-web-audit-handoff-spec-2026-11-26.md) · [Shared discovery sequence](memory-web-audit-spec-2026-11-24.md#shared-audit-contract)
- **Older evidence.** On each routine Perception run, rotate through up to 20 already covered, otherwise eligible Memories outside the changed set using a durable owner-local cursor. Route these samples through existing Observation receptors. Keep sample reads bounded and skip comparisons already recorded for the same target revision and exact effective evidence. The rotation uses coverage and a stable owner-local order, with no Freshness grades. The creation back-check can also find eligible older evidence before publication. [Receptor candidate selection](observation-reconsideration-spec-2026-11-24.md#triggers-and-candidate-selection)
- **Relationships.** Reuse the existing managed Entity resolution workflow, PHY Entity and mention writer, participant lookup and manual or imported Relationship indexes. Admit newly eligible PHY mention work through the active PHY binding. Use only current, resolved local participants with exact mention or admitted retained-resolution proof. Reuse the same gates for roles, duplicate claims and supported time scope. Equal names, co-occurrence and a manual Relationship's description can route a lookup, while the grounded passages establish the claim. Keep unresolved relational candidates waiting for participant changes and let ordinary work proceed. Inferred Relationships use the relational Observation profile. Relational synthesis may cite grounded Memories and eligible ordinary Observations. Verified relational Observations can support ordinary higher Observations. Manual and imported Relationships keep their native IDs, lookup and history. ## Creation, review and standing

Reuse **Propose → Synthesize → Receptors → Evidence back-check → Verify → Finalize** for ordinary and relational claims. Capture exact owner and history generation, Memory or Observation ID, revision, body and UTF-8 span, with participant revisions and source lineage where applicable. Synthesize one claim with grounded status and time scope. Generate and embed the same receptor set, then back-check authorized PHY evidence before verification. Reuse the tested one-call native Jev Verify contract and its single bounded resynthesis rule. A changed draft gets its own verification. Publication rechecks the active writable mount, grant, exact sources, route, duplicate identity and expected head. [Creation and tested Verify contract](observation-creation-spec-2026-11-24.md)

Route evidence to the same receptors and use the tested one-call native Jev Contribution contract for each target revision and bounded batch of unique passages. One accepted material challenge or qualification can trigger review. Keep the time and scope rules, including the distinction between a later change and a claim that was already wrong. A cited source or participant becoming invalid goes directly to targeted review. Support can be recorded under the existing contribution rules. Keep Freshness scoring and award receipts on the REL path. [Reconsideration and tested Contribution contract](observation-reconsideration-spec-2026-11-24.md)

While pending, show the last verified wording and reason in authorized inspection. Withhold the claim from ordinary recall and new derivations. Dependents wait on upstream review. Reaffirming the exact upstream proof can release dependents without another call. A verified replacement appends a successor on the same Observation ID and sends dependents through targeted review. Withdrawn claims remain in history, subject to source readability. A temporary failure leaves the affected review pending and retriable. Preserve the access and invalidation semantics of the underlying PHY Memory, including terminal withdrawal and any proven source-removal event authorized for that PHY. [Standing, dependency and history rules](observation-reconsideration-spec-2026-11-24.md) · [Copied-source authority](copied-source-deletion-cascade-spec-2026-11-24.md)

Verify PHY readiness from Dream settlement or retained accepted PHY import authority at the publication prefix. Keep the existing REL Archive and turn checks inside REL admission. Extend native admission and full PHY replay to validate these records in physical order. Use the PHY writer lease for publication. Append and sync the accepted publication before exposing its receipt or advancing progress. Persist fingerprints for exact retries and separately resumable list and review work. ## Implementation sequence

| Step | Depends on | Exit condition |
| --- | --- | --- |
| **1. Owner proof, history and authority** | Current 2.1 owner-session | A PHY validates ordinary and relational drafts under its own cut and writer lease. Commit, exact retry, replay, old-file admission and verified copy preserve claim history and existing native Relationships. |
| **2. Shared audit and scoped candidates** | 1 establishes the cut and progress contract | The active PHY resumes bounded bootstrap and changed regions. The combined request yields independent accepted Ego and Perception lists. PHY Entity resolution and older-sample routing produce eligible work under the same owner scope. |
| **3. Mounted creation and review** | 1–2 | The managed worker uses the existing routes, exact Jev contracts, receptor bounds and dependent standing. It publishes once, survives restart, and stops disclosure or publication across a switch or revocation. |
| **4. Scoped recall, inspection and host binding** | 1 for read types, 3 for integrated acceptance | Core returns one mixed PHY result list with citations. Hermes and Mercury expose the active-PHY scope and retained history through their existing integrations. Existing native REL recall remains available. |

## Focused acceptance

1. **One managed disposable PHY.** Seed active Memories, a manual Relationship, resolved participants and an unresolved mention. Cross a bootstrap page or request boundary, then resume after acknowledgment of only one list. Verify the five-change cadence, scoped graph follow-up and older-sample deduplication. Resolve the unresolved mention through the existing workflow and prove relational discovery can then use it. Create an ordinary claim, an inferred Relationship and a dependent claim using scripted General, embedding and the existing native Jev contract fixtures. Check the call counts and measured evidence limits in those fixtures.
2. **Review and recovery on the same owner.** Exercise one inconclusive hit and one putative qualification that warrants review. Confirm current recall with a paraphrase before review and pending inspection while the claim and dependent are withheld. Let full source context support exact reaffirmation and release the dependent. Withdraw a cited source and verify a corrected successor on the same ID with exact replacement citations. Reopen with pending work and retry the accepted fingerprint to prove a single durable effect. Check a verified same-owner copy and one maintenance refusal for required proof. Open a pre-feature PHY with its original ID and manual Relationship.
3. **Serving and privacy.** Query a matching Memory and Observation in one ranked active-PHY result. Reject a foreign participant or citation before inference. Switch active PHY after preparing a result and prove the old payload cannot be delivered. Exercise one active-PHY query in each host with disposable profiles. Verify existing REL retrieval with its Freshness behavior in the focused regression.

Reuse the existing creation, reconsideration, mixed retrieval and retained provenance fixtures where they cover a shared rule. Run the required repository checks for the touched boundaries at integration. Use recorded replies or local scripted endpoints and disposable owners.
