# Shared Memory Web audit implementation plan

Parent index: [Planning](./INDEX.md)

## Purpose

Implement the [shared auditor and Observation contract](memory-web-audit-spec-2026-11-24.md) as part of the [integrated Perception release](perception-implementation-plan-2026-11-24.md). Use one authored REL cohort for both extraction contracts and one compatibility fixture for retained Relationships. Verify the workflow with scripted endpoints and actual owner files.

## Overview

Build the shared batch runner and authorized read path first. Connect both discovery contracts as two lists in one structured call. Hand Perception proposals to the six-stage creation workflow through verification and publication. Connect the normal Gateway processing path with a paged initial audit and incremental work at the 25-Memory cadence. Let due incremental work make progress between bootstrap pages. Verify each owning interface before the integrated run.

## Focused verification

| Seam | Cases and required results |
| --- | --- |
| Audit crate and extraction contracts | With a fitting route budget, pack a 45-Memory routine window and a 125-Memory working set in one combined request each. Over-count and over-budget sets, including an oversized Memory, reach every mandatory slice across requests. Optional search can cite an authorized source outside a batch and cannot count it as mandatory exposure. A repeated batch, an empty result, a failed endpoint, and a forged or malformed citation exercise completion and retry. Assert that one structured discovery call emits subjects and propositions with explicit status, time scope and eligible citations. Offer a mixed-grade batch, reject a cold Ego citation and keep the valid Perception candidate. Accept one Fresh source with multiple distinct supported status/time entries. Check Perception verification independently of extraction. |
| Mounted Core workflow | Use one authored REL with recent, Stale and Dormant Memories, two related software Entities, and a same-name or co-occurring distractor. Use a controlled accepted-turn counter and scripted settlement. Assert that 24 newly settled identities leave the run waiting, the 25th queues it and the next counts toward the following run. Edits, retry and reopen preserve the count. Select 15 Stale and five Dormant alongside all 25 new inputs when available. Cover sparse and empty bands, rotation across restart and same-turn grading. Route an older sample to an existing Observation even when discovery returns no proposal, and verify one accepted comparison across repeat samples. Seed one retained typed mention and a newer override. Assert an actual evidence-backed Relationship, an ordinary Observation, no unsupported claim, and no accepted-use or Freshness reward from the audit. Change a cited source, observe pending or withdrawal after reevaluation, and preserve the preceding revision. Pause a model call once, revoke access or replace the mount, and prove stale output cannot publish. An identical retry publishes only one revision. |
| Incremental coverage on the same mounted fixture | Accept results from the first bounded page while other bootstrap pages remain. After a source correction, an added or removed Dream relation between older Memories and a changed participant binding, prove that the next recurring run covers the affected sources and endpoints. An unrelated region stays out of routine work, and a Leiden label change queues nothing. An unchanged neighbor may be included as optional context. Check that Ego receives source invalidations when evidence leaves Fresh, with unaffected points left usable. Interrupt a run with a later committed change, reopen and cover that change once on a subsequent cut. |
| Native reopen and copies | Reuse [mounted inspection](../../tests/oc06_inspection.rs), [checkpoint cases](../../crates/reliquary-owner-session/src/session/checkpoint/tests.rs), and [verified maintenance](../../tests/g4_maintenance.rs). Open a pre-feature 2.1 file and an Observation-bearing copy with an existing manual Relationship. Check ordinary reopen, exact checkpoint and an Observation-bearing suffix, then one verified copy/reclamation case. Assert the old Relationship ID/revision is unchanged, the Observation provenance and progress survive, interruption exposes only the complete prefix, and an unsupported transformation refuses before writing a destination. |

These checks use small authored files and a recording endpoint. The resource assertion is bounded work per poll with no full-REL body load for an ordinary batch, no Freshness history replay per candidate, and no audit work on a passive open. Synthetic scale cases exercise the cursor and batch caps at the unit or owner-session seam. Corpus quality calibration and wall-clock performance benchmarks are separate work.
