# Current Limitations

Parent index: [Documentation index](INDEX.md)

## Purpose
This document owns known incomplete, transitional, or practically limiting behavior in the current rebuild.

## Overview
Purpose-built local configuration, encrypted credential persistence, model-switchboard routing/auth attachment, direct OpenAI-ready embedding/General transport, provider-native Codex General/Insomnia/Dream transport, durable typed REL/PHY owner UUIDs, Archive, derived conversation/leaf inventory and exact-leaf transcript reads, per-turn source ingestion, a transport-neutral synchronous `InteractionRuntime`, durable assistant-stream checkpoints, interruption recovery, completed-message publication, and the in-process `ReliquaryRuntimeHost` are implemented. The host provides long-lived Insomnia workers, inactivity finalization, dynamic General/embedding capability attachment, continuous missing-Memory-vector backfill, and independent owner-local Dream processing for the active REL and optional PHY while preserving short owner lock intervals around model/embedding calls. Native source attachments, embedded files, deterministic Episodes, authoritative Memory revisions, Graph storage/topology, owner-local derived Leiden Community snapshots, immutable Memory Vectors, reusable community-routed owner-local Memory retrieval, packed matrices, compatibility profiles, vector generations, lexical/semantic/hybrid Archive retrieval, bounded Dream candidate retrieval, classifier-v2 pair classification, independent verification, atomic Graph publication, chronological duplicate chains, lifecycle projection, deterministic canonical promotion, temporal analysis, and bounded shared-runtime Dream processing are also implemented. Remaining gaps include the full workspace/CVA management surface, external live interaction adapters, production provider importer coverage, source-scoped Echo retrieval, Ego cross-owner context composition, Observation synthesis/materialization (including convergence of the implemented Relationship substrate into relational Observations) and active-PHY/authorized-REL relational-Observation runtime composition, Dream relation provenance/evidence persistence and measurement-gated reconsideration, retention-aware historical compaction/vacuum, and production storage hardening. Observation architecture is accepted at the high level, but exact per-lane candidate budgets/priorities and the deductive/inductive/abductive/abstractive reasoning algorithms remain the two major behavioral-design items before implementation planning can be considered complete.

## Storage limits
- Chunks are uncompressed and lack container-level checksum/authentication/encryption.
- `CVACONT1` uses a `u32` content-byte length, so one embedded file/content object must be smaller than 4 GiB; streaming/chunked large-file ingestion is not implemented.
- Conservative physical reclamation is implemented as a verified copy rewrite through `Reliquary::reclaim_storage` / `Phylactery::reclaim_storage` and the repo-local `rel reclaim` / `phy reclaim` commands (`vacuum` is an alias). It removes only provably non-semantic garbage: unpublished version-backed payloads, Archive content with no published Archive reference, standalone Memory bodies with no published/grouped/vector reference, unactivated Archive-Vector backing, packed matrices with no surviving Memory/activated-Archive binding, and explicit free conversation-compaction extents. The source file is never replaced in place; the output preserves owner identity, relocates physical version-record references, reopens through normal validation, and must preserve semantic clocks. This is not retention-aware historical vacuum: published Archive/Memory/Entity/Relationship/Graph/Vector-Generation history is retained until timeline/pin/retention semantics exist. Routine Insomnia queue/claim/renew/retry transitions are runtime-only and add zero CVA bytes; failed extraction, wording, enrichment, or temporal inference also adds zero CVA bytes, while successful REL processing publishes one self-contained atomic completion chunk. Routed PHY publication is a separate owner write performed before that REL receipt.
- No general reopen snapshot/checkpoint acceleration exists. Persisted Community partitions are derived Graph organization, not reconstruction checkpoints.
- The finite Insomnia drain retains its split locking model. The long-lived `ReliquaryRuntimeHost` adds interaction-safe background Insomnia and vector workers by releasing its shared runtime lock during model/embedding inference and reacquiring it only for bounded CVA operations. The single `Container` file cursor/append/version boundary remains serialized; a general arbitrary concurrent-writer transaction system is not implemented.
- Explicit migration into the new 40-byte typed owner-ID header is implemented through `migration::migrate_file` and the repo-local `migrate` command. Migration semantically repacks legacy 16-byte Project CVAs and earlier 24-byte typed REL/PHY files into a separate output file; files already carrying an owner UUID are rejected as already current. REL migration preserves the existing concrete owner histories, including Relationships, and vector/profile state; PHY migration preserves its Memory, Entity, Relationship, Graph, packed-vector, Memory-vector, and profile owners. The Graph owner remains a narrow compatibility exception: pre-Graph CVAs reopen with empty Graph state and write the Graph format marker lazily on the first graph mutation.
- The physical scanner materializes each chunk transiently, so a very large matrix object can create a large peak allocation even though matrix bytes are not retained in the reopen index.

## Memory Freshness implementation status

The accepted [unified deterministic Memory Freshness design](generic-staleness-implementation-plan.md) and [ADR 0039](decisions/0039-unified-deterministic-memory-freshness.md) are **planned, not implemented**. The existing Archive REL activity clock and separately implemented pure typed-clock/due evaluator are not the per-Memory signed score, event-scoped graph reinforcement, concurrent traversal, durable Freshness results or derived lifecycle index. The earlier mandatory Perception stale-Memory audit and per-Memory generic review schedule are withdrawn. PHY Freshness needs a separately justified owner-local activity source.

## Version/history limits
- Current global versions carry owner-local transaction timestamps and support `version_at_or_before(transaction_time_ns)`, but legacy `CVAVERS1` tickets and `CVAINSC2`/`CVAINSC3` embedded ranges remain deliberately untimestamped. Historical wall-clock lookup returns only a provable global-version prefix cut: it stops before the first unknown timestamp or before any earlier version whose timestamp is later than the requested cut. This also handles divergent reconciliation where preserved branch timestamps need not be monotonic in the newly linearized global-version order. Reliquary never skips such blockers or infers missing times from source/update metadata.
- Archive, Memories, Entities, Graph, Vector Generations, and the currently implemented transitional Relationship store are separate mutable persisted timelines with dense local `u64` watermarks and shared CVA-global ordering. ADR 0034 now requires that Relationship semantics converge into Observation rather than remain an independent semantic authority. Community snapshot `generation` is derived bookkeeping only and consumes no semantic/global clock. Insomnia queue/lease/retry state is operational and consumes no semantic clock.
- Packed matrices, Memory-Vector bindings, Archive-Vector bindings, and Compatibility Profiles are immutable backing objects and do not independently consume semantic versions. Memory Vectors are keyed by `(CompatibilityProfileId, MemoryBodyId)` and do not have a revision/generation clock.
- An unversioned generation payload is inert after a crash.
- The latest generation for each compatibility profile is implicitly current. Explicit retirement, disabling, rollback, and retention policy are not implemented.
- `source_archive_version` is validated against current Archive state and the creation versions of mapped fragments, but a general whole-CVA historical materialization API is not exposed.
- Whole-CVA restore-and-continue/timeline branching remains unresolved now that additional mutable persisted owners, including Entities and the transitional Relationship store, participate in the shared global order.
- Archive branch/session retention and generation retention/vacuum policies are undefined.

## Compatibility-profile and endpoint limits
- Direct `openai-ready` embedding/General HTTP execution and provider-native `openai-codex` General/Insomnia Responses execution are implemented. Additional provider-native/local-runtime adapters remain future work.
- Compatibility policy v2 uses the fixed probe suite and requires cosine `>= 0.9998` for every corresponding probe. On 2026-08-15, eight repeated same-route comparisons of `qwen/qwen3-embedding-8b` through OpenRouter produced minimum cosine values from `0.99988147` to `0.99993311`; policy v1's `0.99999` threshold rejected all eight. Broader routed/local endpoint calibration is still incomplete.
- Provider, model, route, and revision are intentionally not compatibility-profile fields. Separate optional provenance metadata has not been designed yet.
- Compatibility profiles currently require dimensions and declared normalization to match exactly. More nuanced compatibility rules, if real endpoints demonstrate a need, remain measurement-driven future work.
- The development generation builder stores endpoint output as `f32` packed rows. Packed storage supports other scalar types, but quantization/dequantization semantics are not yet modeled.
- Low-level `publish_vector_generation` validates references, dimensions, current `f32` representation, and Archive coverage but cannot prove externally supplied vector bytes actually came from the claimed compatibility profile. The high-level builder performs endpoint/profile verification.

## Retrieval limits
- Entity candidate retrieval currently uses deterministic indexed exact surfaces, an existing source-Memory association recovery lane, Entities attached to bounded lexical-Memory hits, and first-hop Dream Memory neighbours. The mention builder considers at most 64 exact-surface collisions before contextual ranking and the resolver-facing cap of eight, so pathological surfaces shared by more than 64 Entities are intentionally non-exhaustive. Zero-candidate Admission separately inspects at most 32 exact-surface Memory-search hits and retains at most eight actual same-surface context Memories; those Memories are context, not Entity candidates. There is no Entity vector/centroid index, multi-centroid maintenance policy, or ANN lane yet; those remain measurement-driven additions rather than being approximated by all-Entity summary scans or per-query re-embedding.
- The one-shot `resolve_entity_mention(...)` owner API is implemented, the 41-case frozen zero-Entity bootstrap converges to the full expected create/resolve/split/unresolved/reject state after reopen, and the long-lived runtime host now schedules Entity pass 1 automatically after Dream for both REL and attached PHY. Reconsideration is event-driven: newly Dream-processed/affected Memories, new same-surface mention context, and changed evidence on previously considered candidate Entities enqueue bounded mention work. Every wake rebuilds candidates/evidence first, and unchanged candidate-set/context fingerprints suppress another model call. Startup performs one recovery scan of active Dream-processed Memories so work cannot remain stranded across restart. There is still no dedicated lexical-event wake index or Entity vector/centroid routing lane; lexical evidence participates when a mention is otherwise scheduled.
- Exact Archive semantic retrieval is implemented as a full cosine scan of one selected compatibility profile's current Fragment generation. It is intentionally `O(rows × dimensions)` and has no ANN acceleration yet. Owner-local Memory retrieval now has a separate Community-routed tier, but its routing vectors and admitted Memory set are still exact-scored rather than ANN-indexed.
- Each search currently materializes that packed matrix object into memory before scanning it; mapped/segmented/streaming search is not implemented.
- The direct `Cva::semantic_search` API re-runs compatibility probes for every request because no shared long-lived runtime/capability cache exists yet.
- Searchable published generations currently require `f32` matrices. Packed storage still supports other scalar types, but alternate searchable representations wait for explicit quantization/dequantization semantics.
- Normal lexical/hybrid retrieval and Insomnia `archive_search` evidence now use the same disposable in-memory inverted index derived from Archive fragments. Normal queries extend it lazily and incrementally; the finite Insomnia drain prewarms it once so worker threads can rank evidence against immutable index state without the Container lock. The index is not persisted and is rebuilt after reopen. Evidence hydration still reads only the bounded winning turn bodies through the serialized Container handle.
- Default hybrid retrieval uses `30` candidates, `10` final results, and `0.45/0.55` lexical-semantic weights. These defaults can now be overridden through validated `RetrievalConfig`.
- Exact active-branch lexical search is implemented for the live transcript tier, but broader Archive conversation/time/metadata filters, reranking, and a cross-tier retrieval controller are not implemented in v2 yet.
- Different compatibility profiles have independent current generations, but there is no multi-profile score-fusion policy; scores from unrelated vector spaces must not be compared directly.

## Indexing and memory limits
Archive node/branch/fragment lookup uses dense records plus compact open-addressed slots. Fragment indexes retain one derived `u64` Archive creation version per fragment so generation coverage can be validated. `ContentId -> ChunkRef` remains a direct fixed-width hash table.

Reopen uses one streaming physical pass shared by all concrete stores. Current measurements are recorded in [development](development.md); live 1024-dimensional vectors have been exercised on the prepared 281-fragment corpus, while larger-population realistic-dimension measurements remain useful before storage optimization.

## Temporal/Chronos limits
- The calibrated detector intentionally does not treat approximate recency words such as `recently` or constructions such as `just completed` as resolvable valid-time evidence. LongMemEval temporal-reasoning cases demonstrate that some event ordering can rely only on source/session chronology plus such wording; Chronos needs an explicit uncertainty/approximate-valid-time representation before broadening this detector path.
- Meridiem-qualified standalone wall-clock expressions such as `6:45 AM` are represented as derived `TemporalTimeOfDay` values without inventing a calendar date. Bare colon-number forms such as `12:34` remain indication-only until corpus calibration can distinguish clock syntax from technical notation; timezone-bearing and date+time composition also remain future work.
- Cue-bound approximate durations (`about two weeks`, `a few hours`, `a couple of days`, `several hours`) and explicit numeric ranges (`10-15 minutes`, `three to five hours`) are represented without fabricated precision. Free-standing retrospective windows such as `past few months` and broader colloquial duration language without a duration cue remain coverage gaps. Exact event-relative offsets such as `30 minutes before cooking` are represented, but Chronos deliberately leaves the referenced event unresolved rather than inventing an event timestamp.
- Detector calibration is measurement-driven rather than a general spellchecker: bounded fuzzy correction remains intentionally conservative, and future grammar/vocabulary additions should preserve the measured false-positive reductions before they are promoted.

## Local configuration limits
- Purpose-built `reliquary.cfg` persistence is implemented with replaceable logical objects and atomic whole-file replacement.
- The default operating-system config location is not selected yet; callers currently provide the config path.
- Fragment, retrieval, `models.general`, optional `models.insomnia`, optional `models.insomnia_metadata`, optional `models.chronos`, optional `models.dream`, `models.embedding`, and encrypted `credential.<id>` objects are implemented. Insomnia resolves to `models.general` when its dedicated route is absent; Chronos resolves to Insomnia and then General; Dream resolves to General.
- Model routes reference credentials by ID; the switchboard validates auth kind and can attach bearer/auth account headers.
- Direct `openai-ready` embedding/General HTTP transport and provider-native `openai-codex` General/Insomnia Responses transport are implemented. Codex routes require explicit reasoning effort and use the stored ChatGPT OAuth credential/account ID.
- `openai-codex` ChatGPT device-code acquisition is implemented through the auth.openai.com device-code protocol. Explicit refresh-token rotation is available through the config credential refresh seam; automatic refresh-on-request is not implemented yet.
- A 256-bit master key can be generated/reloaded, but it is temporarily stored as plaintext `reliquary.master-key.json` beside the config.
- Windows Credential Manager integration is not implemented yet.
- No text import/export format exists yet.

## CLI limits
- `cli/` is repo-local and deliberately not installed or built by the core package; invoke it with `cargo run --manifest-path cli/Cargo.toml -- ...`.
- `vectors probe` and `vectors build` use the configured live `openai-ready` embedding route. The `dev` profile/build/search commands remain explicit simulator paths.
- `insomnia run <rel>` uses the configured Insomnia route (falling back to General), registers uncovered canonical import paths unless `--existing-queue-only` is supplied, and invokes the core drain with both General and Embedding endpoints. Without `--phy` it remains Project-only. `--phy <phy>` enables the dedicated ownership pass, routes User-owned Memories into the explicit Phylactery, and fills missing Memory Vectors in both owners.
- Remote embedding defaults are 16 inputs per HTTP request and 16 concurrent requests, based on the 2026-08-15 OpenRouter/Qwen3 throughput benchmark; retry/backoff and provider-specific rate-limit adaptation are not implemented yet.
- `import graph-jsonl` supports one generic development node/branch format and can carry filesystem-backed attachments, but it is still a batch/development importer rather than a production provider importer. No production ChatGPT, Claude, Codex/Hermes, or other provider/session adapters exist yet.
- The CLI has no single-turn live-ingestion command and no file list/add/export/rename/move/provenance-management command surface.

## Community/traversal limits

- REL and PHY persist deterministic complete community snapshots through `refresh_communities_leiden`; algorithm v2 uses graph-local 2,048-node scan shards, bounded parallel leaf Leiden runs, and a binary weighted merge tree. Unchanged current state is an idempotent no-op and a later Memory-to-Memory Graph mutation makes the prior snapshot stale; Entity/Observation-only semantic Graph mutations do not.
- Scan-and-merge reduces the serial reduction depth to logarithmic shard levels, but it still performs a complete Graph scan and is not incremental changed-region maintenance. Merge decisions are irreversible within one pass, so output may differ slightly from monolithic Leiden; the synthetic benchmark currently shows near-reference modularity on both locality-friendly and deliberately interleaved sparse community graphs.
- Community IDs remain exact-membership identities, but deterministic split/merge lineage is now derived between consecutive snapshots. Lineage uses mutual unique strongest Jaccard matches for continuation; tied splits/merges intentionally remain ambiguous. Continuity-preserving IDs are not introduced.
- Owner-local production Memory retrieval is community-aware. A transient `MemoryRetrievalIndex` derives four routing sub-centroids per current Community by default, routes to four Communities, always admits vectorized unclustered Memories, exact-scores that fine-search population, and then traverses the Graph with Community locality only as an equal-depth scheduling preference. `GlobalExact` remains an explicit mode and is the automatic fallback when no current Community routing profile is available. The production sub-centroid implementation is the same code exercised by the five-fold large-corpus benchmark; see [Community routing validation — 2026-08-29](community-routing-validation-2026-08-29.md).
- `MemoryRetrievalIndex` is currently an in-memory caller-owned cache rather than persisted or automatically retained inside `Cva`/`Phylactery`. High-query-rate runtime/Ego code should build it once, reuse `retrieve_memories_with_index`, and rebuild on `MemoryRetrievalError::StaleIndex`; Memory/Memory-Graph-projection/Community changes and additions to the selected profile's Memory-vector bindings invalidate the cache in O(1) through derived in-memory counters/watermarks; Entity-only semantic Graph mutations do not. The one-shot convenience method intentionally rebuilds the derived index for each call. No routing-vector ANN, fine-search ANN, mapped representation, or incremental sub-centroid maintenance exists yet.
- REL and PHY Memory retrieval remain owner-local. Cross-owner query composition, weighting, deduplication, and final context assembly belong to Ego/retrieval composition and are not implemented by this primitive.
- Ego currently has durable owner-local substrate but no running context-assembly machinery: PHY persists multiple stable Identities with one explicit active selection, Personality, Anchors, and cached web synthesis; REL persists Anchors and cached web synthesis. The graph-aware host already owns dependency closure, deterministic owner ordering, active-PHY participation, and cross-owner retrieval; Ego still needs synthesis inference/scheduling, REL activity-window selection and consumption, mutation-threshold refresh, context budgeting, Cross-chat materialization, and host-facing context projection. The planned Web-synthesis policy is activity-relative and owner-local; exact activity units plus `W`/`N`/`M` calibration remain open. Personality is settled as PHY-owned and persisted in PHY; its evidence-selection details, refresh mechanics, user-edit interaction, output shape, and budget remain open. Identical/strict-extension REL reconciliation preserves Ego records by whole-file copy; true divergent reconciliation fails closed when either side contains Ego state until an explicit Ego merge policy exists. Cross-chat is settled at the policy level as deterministic selection of existing current-REL conversation-compaction state ordered by most recent conversation activity; it adds no second summarizer, and current-session compaction is outside the Ego budget. See [Ego Memory-Web synthesis plan](ego-web-synthesis-plan.md) and [Ego Cross-chat context plan](ego-cross-chat-context-plan.md).
- Reliquary can persist either a Dream-generated or user-authored Community name. Dream keeps four sub-centroids and selects up to eight representative Memories, targeting two per sub-centroid before similarity-ranked fill, and requires a current snapshot plus a compatible Memory-vector profile. User-authored names inherit through clear Community lineage and continue to suppress Dream. Dream-generated names inherit only while cumulative Jaccard similarity to the original naming baseline remains at least 0.750; below that threshold the current Community becomes eligible for renaming. Automatic Community refresh cadence remains separate and is not implemented.
- A real divergent semantic reconciliation repack rebuilds Graph authority without replaying Community snapshots; callers must refresh communities afterward if needed. An already-absorbed no-op preserves canonical bytes and therefore preserves existing snapshots.

## Product/runtime limits
- Core WorkspaceMetadata has been removed. Display names are currently derived by the host/filesystem, and optional domain adapters/capabilities remain a separate unrestricted host concern rather than a single persisted workspace type.
- CVA cloud-conflict support now includes `Cva::compare`, fresh semantic repacking, and `Cva::reconcile_and_promote` for safe path-based canonical replacement. Divergent Archive source state, Files, Branches, immutable Episodes/Fragments, durable interaction-stream checkpoints, Memory revisions, Entity revisions, Relationship revisions, Graph relation transactions, durable Insomnia completion receipts, file-to-Memory links, and compatibility profiles are repacked; incompatible stream text/metadata and owner-specific semantic conflicts fail closed. Graph replays after Memories, supports both single-edge and atomic multi-edge transactions, allocates fresh Graph/global clocks, and deduplicates already-absorbed relation-history prefixes. Graph topology and Dream's duplicate index rebuild from merged relationship authority rather than becoming sync metadata. Disposable lexical state similarly rebuilds lazily, while packed vectors, Memory/Archive vector bindings, and Vector Generations are retired only when a real merge changes canonical state. `canonical_change_required` distinguishes a real merge from an already-absorbed semantic no-op; no-op candidates leave the canonical CVA byte-for-byte unchanged and require no persistent reconciliation receipts/metadata. Promotion uses a validated sibling candidate, canonical fingerprint guard, synced recovery copy, atomic replacement, post-replacement reopen/sync, and recovery on finalization failure. It does not yet provide a general OS-level interprocess writer lock/CAS, provider conflicted-copy discovery, or a Warlock UI for presenting/resolving conflicts. `Cva::rebuild_derived_vectors` now provides the verified endpoint-driven recovery primitive used by Warlock after reconciliation retires vector state. Reliquary exposes typed `CvaReconcileConflict` values with stable conflict kinds and owner-specific identity/details instead of raw owner errors for known semantic merge collisions. Divergent repacking remains intentionally owner-explicit rather than generic: any later persisted semantic owner must add its own reconciliation replay/validation path before cloud-divergent CVAs containing that owner can be merged safely.
- Deterministic Archive Episodes, authoritative Memory revision storage, runtime-only transient Insomnia queue/lease/retry transitions, durable final outcomes, compact successful completion transactions, and unresolved-only Chronos inference are implemented. Verified nondeterministic temporal conclusions persist as body/reference-bound Memory state; deterministic Chronos products remain derived.
- Insomnia extractor contract `v3-4` uses a clause-level authority/disposition ledger, deterministic fixed groups, optional bounded fixed-group metadata classification, optional `user|project` ownership classification, wording-only synthesis, and a separate post-wording Entity-mention enrichment pass. The ledger schema requires every authoritative Episode user turn, owns disposition/authority/lifecycle/provenance/category/type, and may perform one bounded read-only Archive evidence round before finalization. Configured finite/runtime-host execution always runs enrichment: `models.insomnia_metadata` is used when configured, otherwise enrichment falls back to effective main Insomnia. The enrichment pass sees only final Memory title/content and may persist only verbatim bounded Entity mentions; Markdown code delimiters are normalized off otherwise-valid mentions, ASCII case-only drift may normalize back to exact source casing when no exact occurrence exists, and more-specific overlapping mentions suppress contained spans. Invalid/non-verbatim individual mentions are dropped while valid siblings survive; structural/schema violations and hard bounds still reject the enrichment result. It cannot resolve/create Entities or alter Memory semantics. Lexical Memory routing is instead derived deterministically from full current title/content by a disposable REL/PHY Memory lexical index using the Archive tokenizer/scoring formula; it performs no model call and persists no state. Fixed-group `current|future|historical` lifecycle is persisted as `Memory.temporal_status`, independently of Dream `lifecycle_state`; legacy R2–R5 Memories reopen as `unknown` until explicitly backfilled. Evidence remains capped at four requests and 64 turns / 128 KiB and cannot provide user authority. Successful routed processing may durably publish PHY Memories first, then writes one atomic REL completion chunk containing local Project Memory state, owner-qualified external Memory references, and body-bound Entity routing metadata for newly published Project Memories.
- Archive source records do not currently persist a separate conversation-scope field, so the old implementation's cross-scope evidence rejection cannot yet be reproduced inside one CVA. Evidence is confined to the current CVA; if multiple visibility scopes are later stored in one Archive, scope metadata must be added before cross-scope reads are allowed.
- `create_memory` exists as a library-level tail-finalization + immediate-queue seam; it is not yet exposed through a shared live-model runtime/tool adapter.
- `InteractionRuntime` itself remains a synchronous transport-neutral owner: it can open/resume a session, assemble one in-flight user/agent message from text deltas and complete attachments, checkpoint cumulative assistant text durably without making it Archive authority, mark an incomplete stream interrupted, resolve a transcript that overlays those checkpoints on the selected Archive path, durably acknowledge completed turns, attempt size-driven Episode scheduling after completion without coupling that result to acknowledgement, and explicitly finalize inactive session tails. The live assembly buffer is process-local, but synchronized stream checkpoints survive runtime loss and are recovered as interrupted; only completed turns enter Archive/Episode/Insomnia authority. `ReliquaryRuntimeHost` now supplies the continuous inactivity wakeup, Insomnia, REL vector, and optional attached-PHY routing/vector loops around that runtime. Automatic adapter reconnect/resume coordination, IPC/API listeners, and adapter lifecycle management remain future work. Interaction-stream compaction/vacuum is also not implemented.
- Warlock v2 now directly integrates CVA workspace create/open/close plus durable conversation list/start/resume/user-turn/reopen through Reliquary. The broader workspace/CVA application surface remains incomplete: provider/agent execution, attachments in the Warlock composer, branch-selection UI, files, Memories, provenance, selective import/export, and lifecycle management are not yet available through the product surface.
- No live ACP-compatible capture/proxy adapter is implemented yet. ACP is scoped as a first-class external interoperability adapter rather than the primary product interface; Warlock-native interaction and all external adapters are planned to converge through one transport-neutral Reliquary interaction seam. ADR 0015 governs ACP capture semantics and ADR 0016 governs the broader product/runtime boundary.
- `ReliquaryRuntimeHost` applies the default 15-minute inactivity policy while Insomnia is enabled. Hosts can start inactive or toggle Insomnia at runtime, and one optional PHY can be attached/detached without duplicating ownership; vector/Dream/retrieval work remains owner-local. There is no scheduler when Reliquary is used only through one-shot `Cva`/`InteractionRuntime` calls; the embedding application host owns that lifetime. Higher-level selection across multiple REL owners and final cross-owner weighting/deduplication remain host/retrieval-composition concerns, and persisted cross-file Dream Graph semantics are intentionally not part of the architecture.
- A one-shot whole-backlog worker pool is implemented with 1–64 workers and a default of 48. Workers no longer share one whole-CVA mutex: claim scheduling is indexed, Archive state is read-only during the drain, and Memories/Insomnia operational state have independent locks. Physical Archive reads and durable appends still serialize through the single `Container` file handle. Retryable extraction failures are requeued until the configured attempt limit, while invalid endpoint configuration is terminal. On the 2026-08-15 66-Episode Luna/low corpus sweep, 48 workers was the fastest observed setting and repeated within 1%; bracketing 44/52-worker runs and the 56/64-worker points were slower, so the current maximum remains configurable rather than becoming the default.
- The one-shot worker uses a 15-minute default lease and renews immediately before successful publication; it does not yet run an in-flight heartbeat during one blocking model request. Current OpenAI-ready and Codex General request timeouts are 180 seconds and extraction permits at most two model rounds, but heartbeat/cancellation belongs in the shared long-lived runtime before production.
- Memory Vector storage and automatic missing-body embedding are implemented in both the finite drain and the long-lived host for the active REL and, when attached, the user PHY. A Memory is authoritative before embedding. The host probes/embeds outside owner locks, commits missing bindings under short REL/PHY locks, and retries unresolved work on later wakes. Dream inference, same-owner Graph publication, duplicate handling, lifecycle projection, canonical promotion, temporal analysis, and continuous derived-backlog processing are implemented for both REL and PHY. PHY intentionally lacks REL's provenance-anchor corroboration promotion. Dream does not perform REL↔PHY comparison or persist cross-file Graph edges; relationship provenance/evidence metadata and automated reconsideration remain future work. Echo, Ego, production importers, and the native product/management surfaces also remain incomplete.
- Memory authority is independent from embeddings. Memory semantic title/content is immutable across revisions, so metadata-only revisions do not cause embedding regeneration; only a new compatibility profile creates another vector for an existing body.

## Enforcement limits
Repository-local Pitlord enforcement assigns every authored Rust source file under `src/` to exactly one architectural owner and blocks reintroduction of the deleted generic `WorkspaceMetadata` / `workspace_type` authority outside the explicit legacy migration decoder. The source tree is physically grouped by those owner directories, so Pitlord can use coarse directory selectors while Reliquary remains one Rust crate. A refreshed post-reorganization audit found no current basis for splitting the core into multiple crates: production import evidence leaves Archive, Chronos, config/security, facade, Memory, Perception, retrieval, runtime/inference, and semantic graph in one strongly connected component; only `container` and `ego` fall outside that SCC. No dependency-direction/cycle rule is therefore being added merely to force an aspirational package DAG. The generated `.lexicon/` and `.arcana/` state is disposable analysis evidence and remains ignored rather than becoming repository authority.
