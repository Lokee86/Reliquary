# Rust API Reference
Parent index: [Documentation index](INDEX.md)
## Purpose
This document owns the current public Rust library surface exposed by `reliquary_memory`.
## Overview
The public API exposes `ReliquaryConfig` and model-switchboard types for machine-local runtime routing; `InteractionRuntime` for transport-neutral live session coordination; `Reliquary` for the homogeneous non-user scope storage/runtime model; and the separate `Phylactery` type for user-global state. Every newly created REL/PHY has a durable owner UUID. Current REL owner IDs use `rel-<uuid>` and PHY owner IDs use `phy-<uuid>`. Reliquary includes Archive history, Episodes, Memories, Graph, derived community snapshots, Insomnia state, embedded files/source attachments, vector backing/publication, compatibility profiles, reconciliation, hybrid retrieval, durable REL metadata (`type_label` plus directed REL dependencies), REL Anchors, and one cached owner-local Ego web synthesis. Phylactery exposes mutable principal profile metadata (`display_name`), Memories with optional owner-qualified external source references, Graph, derived community snapshots, Packed Vectors, Memory Vectors, Compatibility Profiles, Identity, Personality, Anchors, and one cached owner-local Ego web synthesis. `Cva` remains exported as the Reliquary compatibility/internal type name. Ego inference/context assembly is not yet part of this API; this surface currently establishes only the durable owner-state substrate. The API remains development-stage.
## Exact contract
### Local configuration
`ReliquaryConfig::new(path)` creates an in-memory default config, `ReliquaryConfig::open(path)` loads `reliquary.cfg`, and `save()` validates and atomically replaces the current file. Public fields are `fragments: FragmentConfig`, `retrieval: RetrievalConfig`, `models: ModelSwitchboardConfig`, and `credentials: CredentialsConfig`; `path()` reports the configured path. `validate_runtime()` verifies model-route and credential compatibility without executing a provider request. `load_or_create_master_key()` generates or reloads a 256-bit local master key from temporary sibling `reliquary.master-key.json`. Credential objects are encrypted/decrypted automatically on save/open. Unknown framed objects are preserved across saves. Configuration is separate from `.rel` and has no semantic history.

`ConfiguredRuntime::open(config_path)` is the high-level configured execution seam for operator/runtime adapters. It owns `ModelSwitchboard` construction and configured provider endpoint composition. `runtime_routes()` returns a `ReliquaryRuntimeRoutes` bundle containing the exact configured General/Insomnia/Insomnia-metadata/Chronos/Dream/Embedding endpoints; the bundle owns effective fallback semantics for long-lived `ReliquaryRuntimeHost` workers. `run_insomnia_files` owns the finite REL/optional-PHY Insomnia workflow, including ownership-route fallback, queue finalization, publication, Memory-vector completion, sync, and reporting. `probe_embedding` and `build_archive_vectors` own configured live embedding execution. Adapters should pass operator options or exact provider adapters into these library surfaces rather than reconstructing semantic workflow routing.

`ReliquaryRuntimeRoutes::new(...)` accepts exact host-provided endpoints. Effective main Insomnia is `insomnia ?? general`; `with_chronos(...)` supplies the dedicated temporal route and Chronos does not fall back to Insomnia or General; effective Dream is `dream ?? general`; fixed-group metadata classification is optional; ownership classification is `insomnia_metadata ?? effective_insomnia`; and post-wording **Entity-mention enrichment** uses `insomnia_metadata ?? effective_insomnia`. Lexical Memory routing is deterministic and uses no model route. Embedding has no fallback. `ModelCapability::route_key()` exposes the canonical external keys for hosts with their own generic configuration stores. There is no separately persisted ownership or enrichment route yet.
### REL activity reads

`Cva::rel_turn_count() -> u64` returns the REL-local count of first accepted exact `user`/`assistant` identities. `Cva::activity_position_for_turn(conversation_id: &str, node_id: &str) -> Option<u64>` returns an eligible turn's original one-based position, including on replay, or `None` for missing/noneligible Nodes. Archive exposes the same reads through `Cva::archive()`. Both turn acceptance paths share the Archive projection; existing `append_node*` and `ingest_turn` return types remain unchanged. Reads do not write or sync, and the low-level mutation durability contract is unchanged. Existing version-linked history reconstructs the projection without a mutating migration. `Cva::activity_cut_at_archive_version(version: u64) -> Result<u64, ArchiveError>` returns the preceding eligible activity count at a validated Archive boundary using binary search over sparse transitions. Version zero returns zero; versions above Archive head return `InvalidArchiveRecordVersion`. Archive exposes the same query. Live-runtime receipts expose the canonical activity outcome after sync; see [the activity-clock plan](rel-activity-clock-implementation-plan.md).

Principal backfill, project-backed attachment repack, storage reclamation and copy-only reconciliation preserve activity positions and every historical cut exactly, validated after reopening. Fresh migration preserves the eligible identity set, count and acceptance order; divergent reconciliation accepts the left history followed by novel right identities, counting compatible duplicates once. Replayed histories may rebase Archive versions, so numerical source cuts require explicit mapping before reuse.

### Context Engine

Reliquary owns deterministic context-compaction policy through the exported Context Engine types and functions. `ContextView`, `ContextTurn`, `ContextRole`, and `ContextMessage` are provider-neutral context inputs. `request_context(view, checkpoint)` applies a valid branch-local `CompactionCheckpoint`, emits the compacted-history continuation instructions when the checkpoint belongs to the current branch, and returns the provider-neutral `ContextRequest`; stale checkpoints are ignored. `request_messages` remains the lower-level message-only projection.

`compaction_budget`, `compaction_needed`, `budget_satisfied`, `plan_compaction`, and `plan_session_compaction` own trigger/target hysteresis, raw-tail preservation, bounded compaction-input selection, continuation-map instructions, checkpoint advancement, and summary-token limits. Provider adapters supply a `ContextTokenCounter` because exact token accounting remains model/provider specific. `normalize_summary` enforces the deterministic summary-token bound.

`render_assistant_content_from_echo` maps durable Reliquary Echo events into deterministic prior-assistant evidence context, including reasoning/commentary/tool evidence while excluding activity-only events. The generic `render_assistant_content` variant accepts already-normalized `ContextEvidence`.

Host applications may map `ContextRequest` and `ContextMessage` into provider wire DTOs and execute the summarization request, but they do not own checkpoint applicability, compaction selection, raw-tail policy, evidence rendering, summary instructions, or normalization.

### Project Environment host
`ProjectRepositoryMode` selects `ManagedLore`, `ManualLore`, or `Git` bootstrap policy. `ReliquaryRuntimeHost::create_project_environment_rel` and `adopt_project_environment_rel` own repository discovery/bootstrap, durable repository identity, initial revision correlation, and REL creation/adoption. `inspect_project_adoption_source` validates an uncorrelated durable-owner REL before adoption.

For mounted Project RELs, `validate_project_environment_for` verifies the supplied local project directory against the durable repository identity and refreshes only a moved repository-relative `project_path`; `validate_project_environment_cva` provides the same check before mount. `checkpoint_manual_project_for` owns explicit externally-managed Lore checkpoints. `project_repository_root_for` resolves the repository root after identity validation.

`ingest_project_attachment[_for]` owns Lore/Git attachment ingestion, exact snapshot/checkpoint revision creation, correlation, and `ProjectFileRef` registration. `resolved_file_bytes_for` resolves repository-backed files from their exact historical revision and falls back to embedded REL bytes for ordinary files. Existing `warlock.repositoryId`, `.warlock/`, and `warlock/uploads` names are retained only as repository-format compatibility identifiers.

### Managed conversation sessions

`ReliquaryRuntimeHost` owns the active conversation/session for each mounted REL owner. `start_conversation_session` closes/finalizes the previous managed session, generates a new durable conversation ID, and opens the new session. `reopen_conversation_session(conversation_id, leaf_message_id)` resumes one exact durable branch leaf, marks that conversation active, and records transient reopen-pending state. `active_session_id`, `require_active_session`, `reopened_session_pending`, `mark_reopened_session_resumed`, and `close_active_session` expose that authority without requiring the host application to shadow it.

Mount repairs stale durable conversation-active flags left by process loss. Unmount closes/finalizes the owner’s managed session and clears its durable active flag before returning the REL.

`persist_active_message` owns the user/agent message transaction above the lower-level interaction primitives: Reliquary generates message identity/timestamp, validates the managed session, begins the message, appends text, ingests repository-backed attachments when supplied, rolls back the in-flight message on failure, completes the durable turn, and marks the conversation active. `begin_active_assistant_stream`, `checkpoint_active_assistant_stream`, `interrupt_active_assistant_stream`, and `complete_active_assistant_stream` similarly own durable assistant-stream lifecycle and apply the owner execution’s Episode policy on completion.

The lower-level `InteractionRuntime::open_session`, message primitives, and transcript APIs remain available as library mechanics. Host applications should use the managed-session surface when they want Reliquary to own conversation lifecycle authority.

### Cross-owner semantic access

`ReliquaryRuntimeHost::visible_semantic_owners()` is the ambient semantic visibility contract. It returns the active REL's transitive dependency closure in deterministic dependency-first order and then the attached Phylactery when present. Merely mounting an unrelated sibling REL does not make it ambiently visible. `semantic_owner(owner_id)` addresses any mounted REL or attached PHY explicitly, while `visible_semantic_owner(owner_id)` additionally requires membership in the active ambient set.

`search_visible_memories(query, limit, depth)` embeds the query once, executes eligible REL/PHY retrieval lanes concurrently, preserves deterministic owner ordering, and returns owner-qualified lanes/errors. `search_visible_archive(query, limit)` performs the corresponding concurrent Archive search over visible REL owners only; `search_visible_archive_owner` requires ambient visibility, while `search_archive_owner` explicitly targets any mounted REL. Lower-level explicit `*_for(owner_id, ...)` primitives remain available where a caller has already selected an owner.

Knowledge operations are owner-polymorphic through `read_knowledge_for_owner`, `create_knowledge_memory_for_owner`, `replace_knowledge_memory_for_owner`, `mutate_knowledge_relation_for_owner`, and `rename_knowledge_community_for_owner`. The host determines REL versus PHY ownership and generates mutation timestamps internally. `read_memory_provenance_for_owner` exposes direct REL Archive provenance, while `resolve_knowledge_provenance_for_owner` resolves REL-local or PHY external-source provenance and reports `None`, `Unresolved`, or `Resolved` without requiring an application host to inspect owner stores directly.

`read_echo_source_for(owner_id, conversation_id, start_message_id, end_message_id)` is the owner-qualified exact-path Echo expansion seam. It validates that the requested range belongs to the selected REL path and returns only Echo events attached to turns inside that range. Host applications remain responsible for deciding when an already-returned source range is authorized to be expanded; Reliquary owns the source/path resolution itself.

### Container
Public types include `Container`, `ContainerError`, `ChunkRef { offset, len }`, `FormatVersion`, `ContainerIdentity`, `FileKind`, `RelMetadata`, and the legacy compatibility enum `ReliquaryScopeKind`. `FileKind` is `Reliquary` or `Phylactery`. Current files persist a UUID in the container header. `owner_id()` derives `rel-<uuid>` for a current homogeneous REL and `phy-<uuid>` for a PHY; `owner_uuid()` exposes the raw 16 bytes. Legacy typed REL headers retain their historical `proj-`, `org-`, or `con-` owner prefix so existing identities remain stable while opened/reconciled. `ReliquaryScopeKind` and `legacy_scope_kind()` exist only to inspect those old typed headers and must not drive current behavior. Container still exposes opaque append/read/chunk enumeration, sync, path/format inspection, and `latest_version()` for the existing file-global semantic clock. Current semantic version allocation persists owner-local wall-clock transaction time. `transaction_time_ns(version)` returns that timestamp when the version has one. `version_at_or_before(transaction_time_ns)` returns the highest representable global-version prefix cut whose every included version has a known transaction timestamp no later than the supplied wall-clock time. It never skips an unknown or later-timestamped earlier version merely because a higher global version has an older timestamp after divergent reconciliation. Legacy `CVAVERS1` tickets and older embedded Insomnia version ranges return no transaction timestamp; the API never fabricates historical times.

`Reliquary` and `Phylactery` also expose `latest_global_version()`, `transaction_time_ns(version)`, and `version_at_or_before(transaction_time_ns)` as owner-level projections of the Container transaction-time index.

`Reliquary::create(path)` creates an unlabeled homogeneous REL. `create_project`, `create_organization`, and `create_connection` are compatibility/convenience constructors that create the same generic REL identity and set only the optional metadata type label. Likewise `open_project`, `open_organization`, and `open_connection` are compatibility aliases for `open`; they do not enforce a class. `rel_metadata()` returns `RelMetadata { type_label, dependencies }`. `set_rel_metadata(type_label, dependencies)` durably replaces that metadata after trimming, sorting, and deduplicating dependencies and rejecting self-dependency. Type labels are organizational metadata only and may not select storage/retrieval behavior. Dependencies are durable owner-ID edges for host/Ego context composition.

Repository-associated RELs expose the repository-neutral project-history correlation seam. `ProjectRepositoryRef { kind, repository_id, project_path }` identifies the Lore/Git repository and selected Warlock project subtree; `ProjectRevisionRef` adds one opaque repository revision; and `ProjectFileRef` adds a revision-relative path plus optional 32-byte content hash. `ProjectRepositoryManagement` records whether ordinary repository revisions are `WarlockManaged` or `External`. `current_rel_semantic_cut()` reports the current `RelSemanticCut { global_version, archive_version, memory_version }`; `correlate_project_revision(revision)` captures that cut using the compatibility default (`WarlockManaged` for Lore, `External` for Git), while `correlate_project_revision_with_management(revision, management)` persists an explicit policy in the same `ProjectRevisionCorrelation`. `project_revision_correlations()` and `latest_project_revision_correlation()` read that durable history after reopen; the runtime host exposes the same correlation without reopening the REL. Existing `PRJCOR01` records remain readable and infer the compatibility default; new writes use the management-aware correlation format. Correlation is valid for any REL with repository association, does not itself advance the semantic global clock, and requires repository kind plus durable `repository_id` to remain stable across the REL's correlation history; `project_path` and repository-management policy may evolve within that same repository.

`Cva::register_project_file(...)` registers a transcript/provenance attachment backed by an exact `ProjectFileRef`. REL stores attachment metadata plus the durable FileId-to-`ProjectFileRef` binding, but stores no duplicate payload body for that project-backed file. The resulting `FileId` incorporates repository kind, durable repository ID, selected project subtree, repository revision, repository-relative file path, content hash, byte length, filename, and MIME metadata. Identical bytes referenced at different repository revisions therefore keep the same content hash while receiving distinct historical `FileId` identities. `project_file_ref(file_id)` resolves the durable repository reference used by transcript and provenance views.

### Conservative storage reclamation

`Reliquary::reclaim_storage(output)` and `Phylactery::reclaim_storage(output)` write a separate verified copy and return `StorageReclamationReport`. The pass preserves the source owner UUID and semantic watermarks while reclaiming only never-published/staged backing objects, orphan Archive content and standalone Memory bodies, unactivated Archive-vector backing, packed matrices without surviving bindings, and explicit free conversation-compaction chunks. Published semantic revision/generation history is not retention-pruned. Version records containing physical `ObjectRef`s are relocated during the copy; the completed output is reopened through the normal owner lifecycle before success is returned. The source file is never modified or replaced.

### Explicit migration

`migrate_file(source, output)` is the current format migration boundary. It accepts legacy 16-byte Project CVAs and earlier 24-byte typed REL/PHY files and writes a separate current 40-byte file. It rejects current files that already have an owner UUID and never replaces the source in place. For old RELs containing a valid legacy `WorkspaceMetadata.id`, the owner UUID is deterministically derived from that ID; otherwise migration generates a new UUID. The obsolete workspace metadata record itself is not republished.

Migration is a semantic repack rather than a header byte-shift because existing semantic version records contain absolute `ChunkRef` offsets. REL migration replays Archive, Memory, Entity, typed Graph, Entity-resolution, Insomnia completion, interaction-stream, conversation-compaction, file-to-Memory, profile, packed-vector, Memory-vector, Archive-vector, and Vector Generation state through current owner APIs. Only live conversation-compaction records are republished; reclaimed/free extents and superseded physical allocations are not copied. A legacy REL with no compaction state therefore migrates with an empty compaction store. PHY migration replays its Memory/Entity/typed-Graph/profile/vector owners and Entity-resolution state. `MigrationResult` reports the resulting typed owner ID and whether its UUID came from a legacy workspace ID.

### CVA comparison and reconciliation

Public reconciliation types are `CvaComparison`, `CvaRelation`, `CvaReconcileResult`, `CvaReconcileConflict`, and `CvaReconcileError`. `Cva::compare(left, right)` opens and validates two Reliquaries, requires matching durable `owner_id()` values, compares their physical append-only chunk histories, and reports `Identical`, `LeftExtendsRight`, `RightExtendsLeft`, or `Diverged` plus common/total chunk counts. Files without the new durable owner UUID must be migrated before reconciliation.

`Cva::reconcile(left, right, output)` writes a new output REL. Identical/strict-extension cases copy the complete valid side, including its Project revision-correlation history. True divergence is handled as a fresh semantic repack that preserves the original owner UUID, replays the complete left semantic history plus the right divergent tail through normal owner APIs, and therefore allocates fresh valid global/Archive/Memory/Graph version numbers rather than retaining either branch's physical/version layout. Replay preserves known transaction timestamps from the source semantic mutations and preserves legacy unknown transaction time as unknown. Replay covers source Nodes, attachment-bearing ingested turns, standalone Files, Branch revisions, Conversation Metadata revisions, immutable Episodes, immutable Fragments, Memory revisions, Entity revisions, typed Graph relationship transactions, durable Insomnia completion receipts, file-to-Memory links, interaction-stream checkpoints, and compatibility profiles. Entity revisions are replayed before Graph transactions that reference them. Existing Project correlation cuts are not replayed into that renumbered semantic timeline. Repository-correlation histories must instead have prefix-compatible `(ProjectRevisionRef, ProjectRepositoryManagement)` sequences; branch-local `RelSemanticCut` values are intentionally ignored for this compatibility check because those clocks are being replaced. When the merged canonical state changes, reconciliation appends one fresh correlation at the final merged REL cut using the latest compatible project revision and management policy. A right-side repository-correlation extension counts as a canonical change even if that side contributes no Archive/Memory mutation. Truly divergent repository revision sequences fail closed rather than silently choosing one project-history association.

Memory replay preserves stable IDs and mutation IDs and uses ordinary expected-revision rules, so identical mutations deduplicate while incompatible concurrent revisions surface as Memory conflicts. Entity revisions replay after Memories and before typed Graph transactions, so every replayed Graph endpoint already exists. Single-edge and atomic `GraphRelationChange` batches are decoded from their source histories and republished through the Graph owner so destination global/Graph versions and dense topology mappings are allocated afresh. For each oriented `(source, target, kind)` relationship, left/right divergent active-state sequences are compared by semantic prefix: an already-present prefix is deduplicated, a stale candidate contributes nothing, and only an unabsorbed right suffix is replayed. A non-prefix history fails closed as `CvaReconcileConflict::GraphRelation`; with the current binary toggle model, valid histories from one shared base are naturally prefix-comparable. Grouped Insomnia completions are decomposed into their embedded Memory revisions, those revisions are replayed normally, and a completion-only receipt is re-emitted against the merged Memory IDs. Existing Fragment ranges are revalidated and replayed, so the disposable lexical index rebuilds lazily from the merged Fragment/File population after reopen. Graph topology, Dream's duplicate index, and Community snapshots are derived state and rebuild from merged relationship authority rather than being reconciled as semantic synchronization state. Packed vector matrices, Memory-Vector bindings, Archive-Vector bindings, and Vector Generations are intentionally not copied into a divergent repack because their population cuts may be stale; compatibility profiles are retained so callers can rebuild them with a verified embedding endpoint. `CvaReconcileResult` reports replayed/duplicate Graph mutations and transactions as well as `canonical_change_required`. If a physically divergent candidate is already semantically absorbed, reconciliation restores an exact copy of the left/canonical CVA as output, reports no canonical change, and does not require vector rebuilding. `vector_rebuild_required` is therefore true only when a real divergent merge changed canonical state and retired derived vector data.

`Cva::rebuild_derived_vectors(endpoint)` is the bounded recovery primitive for that retired state. It verifies the embedding endpoint once, reuses or publishes the compatible profile, fills missing Memory-vector bindings, rebuilds the current Archive Vector Generation when Fragments exist and the generation is missing/stale, syncs the CVA, and returns `DerivedVectorRecovery` describing the active profile and work performed. `ReliquaryRuntimeHost::reconcile_rel_file(path)` owns the higher-level environment lifecycle: it discovers same-owner sibling RELs beside the canonical path, classifies and safely promotes eligible candidates, detects retired vector state, uses the host embedding route when recovery is required, reopens the promoted REL, validates Memory-vector coverage and the current Archive vector generation, and returns a transient `RelReconciliationReport`. Hosts may trigger this lifecycle around mount/unmount boundaries and present the report, but do not implement reconciliation or recovery semantics.

Semantic merge conflicts are returned as `CvaReconcileError::Conflict(CvaReconcileConflict)`. The public conflict variants currently identify source-turn collisions, divergent Branch heads (including existing/incoming leaf IDs), Episode/Fragment/File identity conflicts, Memory revision/mutation/semantic-mutation conflicts, incompatible Graph relation histories, and incompatible Insomnia completions (including the competing extractor model/version receipts). `CvaReconcileConflict::kind()` exposes a stable machine-facing kind string and `CvaReconcileError::conflict()` returns the structured conflict when present. Corruption, invalid format, I/O, and promotion failures remain ordinary non-conflict errors.

`Cva::reconcile_and_promote(canonical, conflicted)` adds the path-based safe-promotion lifecycle. It first reconciles into a hidden sibling candidate. If reconciliation reports `canonical_change_required = false`, the candidate is removed and the canonical bytes are left untouched. Otherwise promotion fingerprints the canonical CVA, syncs and validates the candidate, verifies that the canonical file did not change during preparation, writes and syncs a recovery copy, atomically replaces the canonical path, and reopens/syncs the promoted CVA before retiring the recovery copy. Reconciliation or promotion failure leaves the conflicted source untouched; any post-replacement finalization failure restores and revalidates the recovery copy before an error is returned. Hidden candidate/recovery files are cleaned up after normal success or failure. This is a filesystem-path primitive, not provider-specific conflicted-copy discovery or a general interprocess locking system; see ADR 0019.

### Archive
Public Archive models include `ContentId`, `Node`, `Branch`, `ConversationMetadata`, `ResolvedTurn`, `ConversationSummary`, `ConversationSearchHit`, `ArchiveSearchHit`, `ArchiveStats`, `FragmentId`, `Fragment`, `FragmentConfig`, `FileId`, `StoredFile`, `IncomingAttachment`, `IncomingTurn`, `IngestedTurn`, `FileMemoryLink`, and:

```text
ArchiveRecordVersion {
    global_version: u64,
    archive_version: u64,
    record: ChunkRef,
}
```

Core operations through `Cva` include `append_node`, native `ingest_turn`, `append_branch`, `set_conversation_title`, `conversation_metadata`, `branch_turns`, `branch_at`, current `branches()`, derived `conversation_summaries()`, exact-leaf `conversation_turns(conversation_id, leaf_node_id)`, cursor-paged `conversation_turn_page(conversation_id, end_node_id, limit)` returning the selected oldest-to-newest page plus the next older parent cursor without resolving the whole branch body, topology-derived `conversation_branch_start_node_ids(conversation_id, leaf_node_id)` for every fork crossed by a selected path, read-only `search_conversation_branch(conversation_id, leaf_node_id, query, limit)`, owner-wide `search_archive(query, limit)`, fragment materialization/read methods, `store_file`, `file`, `files`, `file_bytes`, `search_files`, `files_for_source`, `link_file_to_memory`, `file_memory_links`, `files_for_memory`, `stats`, `archive_version`, `record_versions`, `record_version`, deterministic `fragments()`, and `sync()`.

`ingest_turn(IncomingTurn)` is the source-ingestion boundary. `IncomingTurn` carries the source node, optional durable `principal_id`, plus zero or more `IncomingAttachment { filename, mime_type, bytes }` values. The node, attachment manifests, and source-to-file provenance are published as one Archive semantic mutation; callers do not store an attachment and then separately link it back to the turn. `files_for_source(conversation_id, node_id)` resolves those native attachments. Repeating the identical source event is idempotent; changing the attachment set for an existing node is a conflict.

`Cva::ingest_turn` remains the lower-level synchronous Archive-facing operation. `InteractionRuntime::accept_turn` is the current transport-neutral completed-turn runtime boundary described below. The development graph importer still calls `Cva::ingest_turn` directly because it is a batch import path rather than a live interaction adapter.

`store_file` remains the lower-level path for a file that is not being introduced as part of a source turn. `link_file_to_memory` is intentionally separate: a later Memory relationship is a real cross-owner semantic link, not source-ingestion provenance. File manifests carry filename, optional MIME type, byte length, and a content-addressed reference to arbitrary binary CAM bytes. One `CVACONT1` content object uses a `u32` byte-length field, so one stored file/content body must be smaller than 4 GiB. `search_files(query, limit)` uses the disposable incremental lexical index over filenames only; punctuation such as `-` and `.` separates terms, so extensions are searchable. File-tree operations and file-content indexing are not part of this surface yet.

`set_conversation_title(conversation_id, title)` publishes conversation-owned Archive metadata independently of branch topology; replaying the same title is idempotent. `conversation_metadata(conversation_id)` reads the latest metadata revision. `conversation_summaries()` derives one summary per conversation from current Archive nodes without choosing one branch and overlays the current optional title. Each summary contains the conversation ID, optional title, all current durable leaf node IDs, turn count, and latest source timestamp. Leaf IDs are ordered newest-timestamp first with node ID as a deterministic tie-break. `conversation_turns` requires an explicit leaf and resolves exactly that ancestry path; callers must not silently collapse a multi-leaf conversation to one branch.

`search_archive(query, limit)` is the owner-wide historical Archive search primitive. It lazily refreshes the disposable lexical index over persisted Archive Fragments, returns hydrated `ArchiveSearchHit { fragment, text, score }` values, performs no embedding/model call, and mutates no semantic state. It searches the complete REL Archive rather than one active branch; PHY has no Archive or Archive search surface. Query is bounded to 512 UTF-8 bytes and results to at most 10 hits.

`search_conversation_branch(conversation_id, leaf_node_id, query, limit)` is the cheap hot-history search primitive. It resolves that exact root-to-leaf ancestry, derives the same default 8-turn/2-turn-overlap Fragment windows transiently with a closed tail, applies the existing Archive lexical term/scoring formula, and returns ranked `ConversationSearchHit { fragment, text, score }` results. It does not publish Fragments, advance Archive/global state, embed the query, inspect sibling leaves, or scan other conversations. Because its windows are transient, the newest durable tail is searchable before normal background Fragment materialization. Query must be non-empty and `limit` must be `1..=MAX_SEMANTIC_SEARCH_LIMIT`.

Global/Archive versions are ordering and watermarks only. Conversation ancestry remains node-parent based.

### Normalized interaction runtime

Public interaction types are `InteractionRole::{User, Agent}`, `InteractionAttachment`, `InteractionTurn`, `InteractionSession`, `InteractionReceipt`, `InteractionCompletion`, `InteractionStreamRecord`, `InteractionStreamStatus`, `InteractionTurnStatus`, `ResolvedInteractionTurn`, `InteractionError`, and `InteractionRuntime`.

`InteractionTurn` is the first transport-neutral completed-turn contract above Archive ingestion. It carries `message_id`, `session_id`, optional `parent_message_id`, normalized role, optional durable `principal_id`, timestamp, content, and zero-or-more byte-bearing attachments. `session_id` maps to Archive `conversation_id`; message IDs map to node IDs; `User` maps to Archive role `user`; `Agent` maps to Archive role `assistant`. `principal_id` identifies the human PHY principal associated with the interaction rather than the literal message author. Protocol/provider-specific fields are intentionally absent from this contract.

`InteractionRuntime::new(cva)` takes ownership of one `Cva`. `open_session(session_id, resume_from)` establishes runtime session state. A new session uses `resume_from = None`; if durable Archive nodes already exist for that session ID, an explicit durable resume message is required. The resume message must exist in that same Archive conversation. `session()` reports the current durable leaf and any in-flight message; `close_session()` rejects closure while a message remains in progress.

`begin_message` starts one in-flight message whose parent is the session's current durable Archive leaf. `ReliquaryRuntimeHost::begin_message` captures the currently attached Phylactery owner ID as the user principal at creation time; an Agent message with a durable parent inherits that parent's principal exactly, so later PHY attachment changes cannot reattribute the response. Hosts without an attached PHY persist no principal. `append_text` appends runtime-only text, while `append_checkpointed_text` appends a delta and synchronously publishes the cumulative stream state into the append-only interaction-stream journal before returning. `checkpoint_message` persists the current cumulative in-flight text without adding another delta. `attach` adds a complete attachment, `cancel_message` discards an unacknowledged in-flight buffer, `interrupt_message` publishes the last assembled text with `Interrupted` state and ends the in-flight message, and `complete_message` converts the assembled buffer into one authoritative `InteractionTurn`. A session permits only one in-flight message at a time.

The interaction-stream journal is durable but is not an Archive semantic owner. It exists to retain user-visible partial output without promoting an incomplete assistant response into Archive/Episode/Insomnia authority. Stream checkpoints consume container chunks but no Archive, Memory, Vector Generation, or CVA-global semantic version. A process restart has no live in-memory stream, so a recovered `Streaming` record is exposed through transcript resolution as `Interrupted`. When `complete_message` successfully publishes the same message ID into Archive, transcript resolution prefers the completed Archive node and suppresses the journal copy.

`accept_turn(turn)` remains the direct completed-turn path. Both it and `complete_message` use the existing atomic source-turn ingestion semantics and call `Cva::sync()` before returning `InteractionReceipt { turn, archive_version, inserted, activity_position, rel_turn_count }`. A successful receipt therefore means the source turn has crossed the current durability boundary. `inserted` reports canonical Node novelty, `activity_position` retains the eligible turn's first position even on replay, and `rel_turn_count` reports current REL activity at acceptance. These fields come from Archive's typed acceptance result, not version arithmetic. Identical replay remains idempotent and does not advance the Archive watermark. Checkpointing, interruption and session resume do not count activity before completed source-turn ingestion; a sync error returns no success receipt.

`complete_live_message(session_id, message_id, policy, now_ns)` is the normal live completion helper. It first performs `complete_message` and obtains the durable receipt, then attempts size-driven live Episode scheduling. It returns `InteractionCompletion { receipt, scheduling }`, where `scheduling` is an independent `Result`. A scheduling failure therefore cannot revoke or obscure an already-durable source receipt.

`schedule_session(policy, now_ns)`, `finalize_inactive_session(policy, now_ns)`, and `finalize_explicit_session(policy, now_ns)` expose the live Episode/Insomnia scheduling paths from the current durable session leaf and sync any resulting semantic Episode publication. Size-driven scheduling deterministically closes complete response-cycle packs, inactivity closes the current tail after the configured quiet period, and explicit finalization closes the current tail immediately with `EpisodeBoundary::Explicit` and queues it at `ImmediateLive` priority. `ReliquaryRuntimeHost::close_session()` applies that explicit boundary to any non-empty open session before dropping its runtime state; empty sessions close without creating an Episode.

`conversation_summaries()`, `conversation_turns(conversation_id, leaf_node_id)`, cursor-paged `conversation_transcript_page(conversation_id, end_node_id, limit, include_stream_records)`, topology-derived branch-start reads, and `set_conversation_title(conversation_id, title)` expose the same Archive conversation inventory/path/metadata operations through the live runtime. `search_conversation_branch(...)` exposes exact-leaf lexical search through `InteractionRuntime`. `conversation_transcript(conversation_id, leaf_node_id)` overlays matching uncompleted interaction-stream records on that exact durable path, reports each turn as `Complete`, `Streaming`, or `Interrupted`, and keeps interrupted assistant text available to a later provider request without changing Archive authority. `ReliquaryRuntimeHost::search_open_session(session_id, query, limit)` resolves the currently open session's durable leaf internally before searching. The host also exposes owner-wide read-only `search_archive(query, limit)` over its REL and owner-local Memory retrieval lanes through `retrieve_reliquary_memories(query_vector, config)` and `retrieve_phylactery_memories(query_vector, config)`, plus `retrieve_memory_pair` for concurrent REL/attached-PHY retrieval from one already-embedded query vector. `start_inactive` and `set_insomnia_enabled` let a host stay retrieval/vector/Dream-ready without claiming Insomnia work; `attach_phylactery`, `detach_phylactery`, and `has_phylactery` allow one PHY to move between host lifetimes without duplicating ownership. `cva()` provides read-only access to the owned CVA and `into_cva()` transfers ownership back to the caller.

### Episodes

Public Episode models are `Episode`, `EpisodeId`, `EpisodeOrigin::{Live, Import}`, `EpisodeBoundary::{Size, Inactivity, CreateMemory, ImportEnd, Explicit}`, `EpisodeConfig`, and `EpisodeBuildResult`. `DEFAULT_EPISODE_MAX_INPUT_BYTES` is 32 KiB and `DEFAULT_EPISODE_INACTIVITY_NS` is the current inactivity-policy default.

`materialize_branch_episodes` and `materialize_path_episodes` derive deterministic contiguous ancestry ranges from whole user-led response cycles. `episodes`, `episodes_for_conversation`, `episode`, and `episode_turns` inspect the resulting Archive-owned source ranges. Finalizing an Episode does not close its conversation.

### Phylactery

`Phylactery::create(path)` creates a typed `.phy` with user-global semantic identity; `Phylactery::open(path)` requires that exact identity and rejects REL and legacy CVA files. The implemented owner composition is principal-profile metadata, Memories, EntityStore, Graph, derived Community snapshots, Packed Vectors, Memory Vectors, Compatibility Profiles, durable Ego state, and a process-local disposable Memory lexical index. Archive, Episodes, Files/attachments, Insomnia, Archive Vectors, Vector Generations, interaction-stream checkpoints, and the Archive lexical index are not part of the Phylactery API.

`Phylactery::profile()` returns `PhylacteryProfile { display_name }`; the optional display name is mutable presentation metadata and never participates in durable identity. `set_profile(display_name)` trims the value, treats empty input as absent, appends a latest-wins PHY profile record only when the normalized profile changes, and preserves the header-derived `phy-<uuid>` owner ID. `ReliquaryRuntimeHost::phylactery_profile()` exposes the attached profile and `set_phylactery_profile(...)` durably updates it. When the matching `phy-UUID` principal Entity already exists in the active REL, host startup, attach, first deterministic principal resolution, and live profile changes synchronize the profile into that principal Entity's aliases/summary without changing its canonical `phy-UUID` or EntityId. Ego Identity names remain separate persona/identity labels and are never used as principal identity.

Phylactery exposes Memory reads/revisions/stats/body IDs and `publish_memory`; Graph mutation/query APIs matching the same-file Reliquary Graph surface; packed-vector object APIs; compatibility-profile establishment/verification; Memory-vector binding/build APIs including `build_missing_memory_vectors`; owner-local Dream context/candidate/temporal/publication/lifecycle APIs; and Ego persistence APIs. Identity is a PHY-owned collection of stable `EgoIdentityId` records. `ego_identities()` lists live identities, `ego_identity_by_id(id)` reads one, `ego_identity()` returns the currently active Identity, and `active_ego_identity_id()` exposes the selection. `create_ego_identity(name, text)`, `update_ego_identity(id, expected_revision, name, text)`, `activate_ego_identity(id)`, and `delete_ego_identity(id, expected_revision)` own lifecycle and swapping; the first Identity activates automatically, later creation does not implicitly switch, re-selecting the active Identity is a no-op, and an active Identity must be switched away before deletion when alternatives exist. The compatibility `put_ego_identity(expected_revision, text)` updates the active Identity or creates the first `Default` Identity. Legacy single-Identity records reopen as that active `Default` Identity. `ego_personality` / `put_ego_personality` own the current derived Personality document; `source_memory_version` records the PHY Memory watermark from which that projection was synthesized. `ego_anchors`, `ego_anchor`, create/update/delete Anchor APIs, and `ego_web_synthesis` / `put_ego_web_synthesis` expose the owner-local standing-context and cached-synthesis records. Writes use optimistic local revisions; byte-identical writes and no-op activation do not advance the independent Ego owner version. It does not own Episodes or an Insomnia queue, but an active REL may route Insomnia results into an explicitly supplied `Phylactery` through the routed processing/drain APIs and the long-lived runtime host. `sync()` flushes the shared container.

Reliquary exposes the shared Ego Anchor and web-synthesis APIs but intentionally exposes no Identity or Personality mutation surface: those records are PHY-owned. Anchors are capped at 2,500 Unicode scalar-value characters and carry `High`, `Normal`, or `Low` owner-local priority. Anchor deletion is durable tombstoning rather than history erasure. `EgoWebSynthesis.source_memory_version` records the owner-local Memory watermark from which the cached synthesis was produced so later Ego machinery can detect stale input deterministically. Personality/synthesis source watermarks may be stale but may never point beyond the owner's current `memory_version`; writes and reopen validation fail closed on impossible future cuts.

Direct `Phylactery::publish_memory` still requires all REL-local Episode/node/conversation provenance fields in `MemoryDraft` to be `None`; PHY never embeds the originating REL's source records. Routed Insomnia publication instead persists an identifier-only `MemorySourceRef` on the resulting PHY Memory. That reference names the originating REL owner, optional source-turn PHY principal, Episode, primary source node, and optional authority/grounding conversation-node identities without copying any turn or Episode content. `source_time_ns` remains separately persisted semantic chronology.

### Generic review clock evaluation

The public `staleness` module exposes `ClockRef`, `ClockValue`, `ClockReading`, `ClockError`, `ReviewInterval`, `is_due`, `threshold_from_anchor`, and `due_now`. Readings bind one value to an exact source and reject incompatible units. `is_due(threshold, current)` compares only readings of the same source, including its owner UUID. `Fixed` supports positive sequence or signed Unix-nanosecond intervals; `ProportionalCapped` supports positive rational sequence intervals with integer ceiling, a minimum increment of one and a cap. Threshold arithmetic is checked; overflow is an error.

`Cva::review_clock(source)` reads the existing REL activity or Memory-version accessor after validating owner identity. `Phylactery::review_clock(source)` accepts only the PHY's existing Memory-version source. Legacy owners without a durable UUID cannot supply owner-qualified readings. `ClockReading::unix_ns(sample)` takes a trusted caller sample without reading hidden global time. Backward samples leave thresholds unchanged.

`threshold_from_anchor(policy, anchor, current)` rejects future or mismatched anchors and calculates from examined progress, rather than completion-time progress. `due_now(policy, current)` is an explicit consumer bootstrap. These APIs persist nothing, do not register targets, queue workers or reinforce Memories, and do not establish historical coverage; the future owner-controlled completion protocol must validate coverage and target revisions. See [the generic staleness plan](generic-staleness-implementation-plan.md).

### Memories

Public Memory models are `MemoryId`, `MemoryBodyId`, `MemoryRevisionId`, `MemoryRef`, `MemorySourceRef`, `MemoryDraft`, `Memory`, `MemoryStats`, `MemoryTemporalInference`, `MemoryRoutingMetadata`, `MemoryEntityMention`, `MemoryTextField`, and `MemoryError`, plus the Entity-routing bounds `MAX_MEMORY_ENTITY_MENTIONS` and `MAX_MEMORY_ROUTING_TEXT_BYTES`. Public deterministic lexical lookup additionally exposes `MemoryLexicalSearchHit`, `MAX_MEMORY_LEXICAL_SEARCH_QUERY_BYTES`, and `MAX_MEMORY_LEXICAL_SEARCH_RESULTS`. `Memory` includes durable `temporal_status` (`current`, `future`, `historical`, or legacy/manual compatibility value `unknown`), optional `source_time_ns`, a source-derived semantic timestamp distinct from `created_at_ns`/`updated_at_ns` bookkeeping, optional `source_ref` for identifier-only cross-owner provenance, optional verified `temporal_inference` for nondeterministic Chronos residue, and optional body-bound `routing_metadata`. `temporal_status` is the extraction-time proposition classification and is separate from Dream-owned `lifecycle_state`. `MemoryRef { owner_id, memory_id }` identifies a Memory in another owner. `MemorySourceRef` identifies the originating REL owner, optional source-turn `principal_id`, Episode/source node, and optional authority/grounding node identities; it stores no source body. `MemoryRoutingMetadata` is clock-neutral derived routing state bound to exact `MemoryId + MemoryBodyId`; Entity mentions identify `Title` or `Content` plus exact UTF-8 byte span/text. It does not create Entity identity or Memory authority.

`Cva::publish_memory(id, expected_revision, draft)` publishes one Reliquary Memory revision after validating Archive/Episode provenance. `Phylactery::publish_memory` uses the same revision/body/mutation semantics but validates that REL-local provenance fields are absent. Routed publication supplies an external `MemorySourceRef` through the internal PHY publication seam; ordinary later metadata/lifecycle revisions inherit that reference automatically so they cannot silently erase provenance. `source_time_ns`, when present, and `temporal_status` are persisted Memory semantics and participate in mutation/idempotency equality. Current Insomnia carries its fixed-group metadata lifecycle into `Memory.temporal_status` instead of discarding it after wording. A new Memory may omit `id`, in which case its stable ID derives from `mutation_id`; replaying the same mutation/draft is idempotent, while changed content or temporal/source-time semantics under the same mutation conflicts. Existing Memory IDs require the exact expected current revision.

A Memory's semantic title/content is represented by one immutable `MemoryBodyId`. Later revisions may change metadata, provenance, temporal status, Dream lifecycle, archival, parent, or supersession state, but they cannot mutate semantic title/content in place. `Cva::set_memory_temporal_status` and `Phylactery::set_memory_temporal_status` are metadata-only revision seams for explicit legacy/backfill correction; they require the exact expected revision, accept only `current|future|historical`, preserve body/provenance/timestamps/Dream lifecycle, and are no-ops when the requested status is already current. A semantic correction to the title/content is therefore another Memory rather than a rewritten body.

`memory(id)`, `memory_revision(id, revision)`, `memory_stats()`, `memory_version()`, and `memory_body_id(id)` expose current/historical revision state and the dense Memory-local watermark. `Cva::memory_routing_metadata(id)` and `Phylactery::memory_routing_metadata(id)` expose the optional body-bound Entity attachment without introducing a new semantic revision. `Cva::search_memories(query, limit)` and `Phylactery::search_memories(query, limit)` lazily rebuild/query the disposable owner-local lexical index over current non-archived Memory title/content and return hydrated `MemoryLexicalSearchHit { memory, score }` values. They use the same tokenizer, inverted-index postings, bounded frequency, and coverage+density scoring formula as Archive lexical search; query is bounded to 512 UTF-8 bytes and results to 10. The index performs no embedding/model call, writes no container bytes, and rebuilds after reopen or `memory_version` changes. Memory publication consumes one CVA-global semantic version and one dense `memory_version`; Memory-body backing objects, Entity-routing attachments, and the lexical index are clock-neutral.

### Entities

Public Entity models are `EntityId`, `EntityDraft`, `Entity`, `EntityStats`, and `EntityError`. REL and PHY expose `publish_entity(id, expected_revision, draft)`, `entity(id)`, `entities()`, `entity_version()`, and `entity_stats()`. A new ordinary Entity may omit its ID and receive deterministic identity from the creation mutation ID; later metadata revisions require the exact current revision and preserve the Entity ID and original creation timestamp. REL also supports the reserved `kind="principal"` Entity class for durable PHY-backed human identity. A principal's canonical name is its exact `phy-<uuid>` owner ID and its internal `EntityId` is deterministically derived from that principal ID; malformed/mismatched principal records are rejected. PHY rejects principal Entities entirely because the file itself is already the principal identity boundary.

`entity_candidates_for_surface(surface, limit)` is the exact deterministic lane backed by a derived one-to-many normalized surface index; it does not scan every Entity. `entity_candidates_for_mention(key, config)` is the bounded Perception candidate builder for one exact Insomnia mention. It combines exact name/alias candidates, any Entity already associated with the source Memory, Entities attached to lexically retrieved owner-local Memories, and Entities attached to first-hop Dream Memory neighbours. `EntityCandidate` preserves those lanes separately (`exact_surface`, `source_association`, lexical hit count/best score, graph-neighbour hit count, bounded supporting Memory IDs); ranking only selects which candidates enter the resolver and never proves identity. If no Entity candidate exists, the returned `EntityCandidateSet` may additionally carry up to eight bounded same-surface `admission_context_memory_ids`; those Memories are Admission context, not Entity candidates. The default Entity-candidate cap is the resolver cap of eight. Entity records still do not contain supporting Memory IDs or Memory↔Entity adjacency; those associations belong to Graph.

`resolve_entity_mention(resolver, key, config, now_ns)` is the one-shot owner API on both REL and PHY. Before candidate construction or inference, owner-relative principal surfaces such as `user` / `the user` take a deterministic principal lane: in REL, the source turn's durable `principal_id` resolves to the matching lazy `phy-UUID` principal Entity; in PHY, the same owner-relative surface is terminally suppressed/rejected without creating a self-Entity. If no deterministic principal applies, the normal path constructs the current candidate/context set and chooses one of two model contracts: **Entity Admission v2** for zero candidates, or the frozen calibrated **V4 identity resolver** for one or more candidates. Admission may `create_new`, `unresolved`, or `reject` and materializes stable initial kind/summary metadata when creating. V4 may `resolve_existing`, split a distinct identity with `create_new`, leave the mention `unresolved`, or `reject`; a V4 split uses the separate metadata-materialization v2 contract rather than changing V4's calibrated input/output shape. The processor then deterministically publishes any new Entity, `Memory -> Entity` association, and per-mention resolution state. Existing source associations are candidate evidence so an interrupted association-before-resolution write can recover. Internally the runtime uses the same semantics through a prepare → infer → commit seam: preparation snapshots durable owner identity, Memory/Entity/Graph/resolution versions, and bounded evidence under the owner lock, model inference runs without that lock, and commit rejects stale snapshots. `ReliquaryRuntimeHost` schedules this automatically after Dream for REL and attached PHY. Perception model routing prefers `insomnia_metadata`, then falls back through Dream/General.

### Relationships

The following API is the currently implemented **transitional relational-profile persistence surface**. ADR 0034 now defines Relationship semantically as a specialized Observation; this API remains valid implementation state until it is converged with the Observation owner, and new semantic lifecycle/synthesis authority must not be added here independently.

Public Relationship models are `EntityRef`, `RelationshipId`, `RelationshipParticipant`, `RelationshipDraft`, `Relationship`, `RelationshipStats`, and `RelationshipError`. REL and PHY expose `publish_relationship(id, expected_revision, draft)`, `relationship(id)`, `relationships()`, `relationships_for_entity(entity_ref)`, `relationship_version()`, and `relationship_stats()`.

A new Relationship may omit its ID and receives deterministic identity from the creation mutation ID; later revisions require the exact current revision and preserve the original creation timestamp. References whose `owner_id` equals the containing REL/PHY must resolve to a current local object at publication and reopen; a retired local Entity ID is rejected rather than silently redirected. ### Graph

Public Memory-projection models remain `GraphRelationKind`, `GraphDirection`, `GraphRelationChange`, `GraphRelation`, `GraphNeighbor`, `MemoryGraphPath`, `GraphStats`, and `GraphError`. The shared semantic Graph additionally exposes `SemanticNodeKind`, `SemanticNodeRef`, `SemanticGraphRelationKind`, `SemanticGraphRelationChange`, `SemanticGraphRelation`, and `SemanticGraphNeighbor`.

`Cva::set_memory_relation` / `set_memory_relations` and the equivalent Phylactery APIs retain the existing oriented Memory-to-Memory surface and Dream/User relation vocabulary. `set_entity_association(memory_id, entity_id, active, expected_graph_version)` publishes the ordinary Perception-owned directional `Memory -> Entity` `EntityAssociation`. Principal identity uses a separate durable `Memory -> principal Entity` `PrincipalAssociation`; publication is internal to deterministic principal resolution, ordinary Entity association APIs reject principal targets, and principal-association publication rejects non-principal targets. The Memory and Entity must already exist in the same owner. One non-empty transaction consumes one file-global version and one dense Graph-local version regardless of change count, and the caller must supply the exact full semantic `graph_version`.

`graph_version()` is the dense optimistic concurrency token for all semantic Graph transactions. `memory_graph_version()` is a derived watermark equal to the latest full Graph version containing a Memory-to-Memory mutation. `semantic_graph_relations()` and `semantic_graph_neighbors(node, direction)` expose the ordinary typed semantic topology but deliberately omit `PrincipalAssociation`; `entity_associations_for_memory` and `memories_for_entity` expose ordinary Entity lookup, while `principal_associations_for_memory` and `memories_for_principal` are the explicit opt-in principal traversal seam. `principal_entity(phy_owner_id)` and `memories_for_phy_principal(phy_owner_id)` provide the direct `phy-UUID` lookup path without requiring callers to scan Entities or know the internal principal EntityId. Existing `graph_relations()`, `graph_neighbors(memory_id, direction)`, and `shortest_memory_path` remain deliberately Memory-only projections. Dense Arcana node IDs stay internal, typed references remain owner-local, and Observation endpoints remain rejected until a durable Observation owner and accepted relation families exist.

The runtime Knowledge Interface reads the ordinary semantic surface: current Memories, non-principal Entities, active non-principal `SemanticGraphRelation` values, and the current Community snapshot/names. It does not use the Memory-only `graph_relations()` projection. PHY-backed principal Entities and `PrincipalAssociation` edges are intentionally omitted from this generic visualization/read surface and require explicit principal lookup. Community data returned beside the ordinary graph remains a Memory-derived overlay, so ordinary Perception relations and Entity nodes are visible without being implicitly admitted into Leiden.

`source_node_id` plus `source_episode_id` identify user authority inside an authoritative Episode. `content_source_*` identifies adopted/retained assistant authority when present; `grounding_source_*` identifies context used only to resolve a referent. Both external source tuples must resolve to real Archive nodes. Grounding never supplies semantic authority.

### Communities

Public community types are `CommunityId`, `Community`, `CommunitySnapshot`, `CommunityStats`, `CommunityLineageLink`, `CommunityLineageTransition`, and `CommunityError`. Both `Cva`/`Reliquary` and `Phylactery` expose `community_snapshot()`, `community_stats()`, `community_lineage()`, and `refresh_communities_leiden()`.

`refresh_communities_leiden()` materializes a complete owner-local partition of the current Memory Graph projection using community algorithm v2; Entity/Observation nodes and non-Memory relation families are excluded. Active relationships project to unique undirected structural pairs. The projection is scanned in deterministic graph-local BFS order into 2,048-node shards, shard-local Leiden modularity runs execute through a bounded worker pool, and shard communities are reduced through a deterministic binary merge tree. Merge stages carry every original structural edge upward as weighted coarse edges/self-loops, so boundary evidence is not discarded. The persisted snapshot remains one complete partition with global resolution `1.0`, fixed seed `0x4c454944454e0001`, its derived generation, and exact source `memory_graph_version`.

Scan-and-merge does not mutate Graph relationships or consume a semantic/global version. Worker count affects concurrency only; focused tests require byte-equivalent output across worker counts. Refresh against an already-current v2 snapshot is a no-op and appends no bytes. Older supported derived snapshots remain readable, but an algorithm-version mismatch causes the next explicit refresh to publish the current v2 partition. REL and PHY are always partitioned independently, and files without durable owner UUIDs cannot publish community identity.

Community IDs identify exact owner-scoped membership, not continuity across changed membership. `community_lineage()` derives the transition between the two latest persisted Community generations, including non-zero-overlap predecessor/successor links, split/merge flags, and a conservative `continuation` bit that is true only for mutual unique strongest Jaccard matches. `community_semantic_name(id)` and `community_semantic_names()` resolve optional names for current Communities through that lineage. `set_community_name(id, name)` writes the user-authoritative form; user names inherit through clear continuation links and continue to suppress Dream. Dream names inherit only while cumulative Jaccard similarity to their original naming baseline remains at least `0.750`. Incremental changed-region invalidation is still not part of this API.

### Owner-local Memory retrieval

Public Memory-Web retrieval types are `MemoryRetrievalMode`, `MemoryRetrievalConfig`, `MemoryRetrievalIndex`, `MemoryRetrievalHit`, `MemoryRetrievalResult`, and `MemoryRetrievalError`. Both `Cva`/`Reliquary` and `Phylactery` expose `build_memory_retrieval_index`, `retrieve_memories_with_index`, and the one-shot convenience `retrieve_memories`.

`build_memory_retrieval_index(profile_id, subcentroids_per_community)` materializes transient owner-local retrieval state from current non-archived Memory vectors plus the latest Community snapshot when that snapshot matches the current Memory Graph projection and community algorithm. The index is derived in memory only: it persists no Community vector, Memory, Graph edge, or semantic version. Its public watermarks record the compatibility profile, Memory version, Memory-Graph projection version, Community generation, profile-local Memory-vector binding count, vector dimensions, indexed Memory count, and routing-vector count. Entity-only semantic Graph mutations do not stale this index because neither its Communities nor Memory traversal input changed. A caller that caches the index must rebuild it when `retrieve_memories_with_index` returns `MemoryRetrievalError::StaleIndex`.

`DreamCommunityNamer<E: GeneralEndpoint>` is the Dream-owned semantic naming seam for an already-current Community snapshot. `name_communities(cva, profile_id, limit)` and `name_phylactery_communities(phy, profile_id, limit)` keep the existing four Community sub-centroids and select up to eight representative Memories, targeting two nearest unique Memories per sub-centroid before filling any remaining slots by best centroid similarity. They send bounded title/content text to the model and persist `CommunitySemanticName { community_id, baseline_community_id, contract_version, source, name, representative_memories }` as clock-neutral Community metadata. Direct records set `baseline_community_id == community_id`; inherited views retain the original baseline while resolving against the current Community ID. Raw embedding vectors are not model input. `set_community_name(id, name)` on REL or PHY persists a user-authored name with `source = User`; clear lineage carries that authority forward, so Dream excludes the successor from naming regardless of later Dream naming-contract versions. Generated names are retained across clear lineage only while the current membership remains at least 0.750 Jaccard-similar to the original baseline; otherwise the successor becomes eligible for a new Dream name. Naming requires a current snapshot and a compatible Memory-vector profile; failure publishes no name and does not change Graph version or Community generation.

The default `MemoryRetrievalConfig` uses community routing with four deterministic sub-centroids per Community, routes to the top four Communities, exact-scores admitted Memory vectors, retains the top four Memory seeds, and traverses up to 32 Memories at maximum Graph depth three. Vectorized Memories with no current Community membership are always admitted as a residual lane, so Graph-isolated Memories do not become unreachable. Graph traversal always prefers shallower nodes first; Community locality is only a tie-break inside equal Graph depth, where paths with fewer Community-boundary crossings are scheduled first.

`MemoryRetrievalMode::GlobalExact` remains an explicit reference/fallback path. Community-routed retrieval also falls back to global exact Memory-vector search when the built index has no current routing profile, such as before the first Community refresh or while the latest persisted snapshot is stale. The result reports the mode actually used, whether fallback occurred, selected Communities, scored seed Memories, deterministic traversal order, and the routing/fine/global comparison counts useful for measurement.

The query vector must already belong to the index's selected Compatibility Profile space; Memory retrieval performs no embedding call and never compares scores across profiles. REL and PHY retrieval remain strictly owner-local. Cross-owner composition belongs to the higher retrieval/Ego layer rather than to Dream, CommunityStore, or this primitive. The validated operating point and quality measurements are frozen in [Community routing validation — 2026-08-29](community-routing-validation-2026-08-29.md) and the architecture decision is recorded in [ADR 0026](decisions/0026-community-routed-memory-retrieval.md).

### Dream candidate retrieval

Public types are `DreamCandidateConfig`, `DreamMemoryContext`, `DreamCandidate`, `DreamCandidateSet`, `DreamCandidateError`, and the `DEFAULT_DREAM_*` / `MAX_DREAM_CANDIDATE_LIMIT` constants.

`Cva::dream_candidates(profile_id, source_id, config)` and `Phylactery::dream_candidates(profile_id, source_id, config)` perform bounded read-only candidate discovery for one existing Memory inside that owner. The source Memory must already have a Memory-Vector binding under the selected owner-local compatibility profile. Its stored Document vector is compared directly with other stored Memory-body vectors from the same file, so these APIs perform no embedding endpoint or model call and never federate candidates across REL/PHY. A candidate without a vector may still enter through deterministic lexical/metadata or temporal matching.

`Cva::dream_memory_context(memory_id)` and `Phylactery::dream_memory_context(memory_id)` expose the same production context builder used by candidate discovery for one exact Memory without ranking or requiring a vector. They return the current Memory/body identity, authoritative source timestamp when resolvable, deterministic temporal analysis, and active same-owner Graph relations touching the Memory. This is a read-only inspection/tuning seam; it does not evaluate a relationship or mutate semantic state.

The current default limits are 12 final candidates, 24 primary semantic candidates, 3 prior-semantic reservations, 8 lexical candidates, and 8 temporal candidates. Active Graph neighbours and unordered Memory pairs already successfully evaluated by Dream are excluded before ranking and final-slot allocation, so settled positive or `none` pairs do not consume later maintenance capacity. Prior-semantic coverage uses authoritative source timestamps rather than Memory creation timestamps. Temporal matching uses overlapping deterministic content-time anchors or matching recurrence patterns; source-time proximity alone is not a match. Archived Memories are excluded. Every returned source/candidate context includes the immutable `MemoryBodyId`, resolved authoritative source timestamp when available, deterministic temporal analysis, and all active Graph relations touching that Memory. Candidate discovery is deterministic for unchanged CVA state and configuration and does not mutate Graph, Memories, or semantic clocks.

### Chronos deterministic temporal analysis

Canonical public types are `TemporalAnalysis`, `TemporalAssessment`, `TemporalResolution`, `TemporalResolutionStatus`, `TemporalAnchor`, `TemporalTimeOfDay`, `TemporalClockPrecision`, `TemporalDuration`, `TemporalDurationRange`, `TemporalApproximateDuration`, `TemporalDurationApproximation`, `TemporalDurationUnit`, `TemporalEventRelation`, `TemporalEventDirection`, `TemporalInterval`, `TemporalPattern`, `TemporalMatch`, `TemporalGranularity`, `TemporalOrigin`, `TemporalFrequency`, `TemporalWeekday`, and `TemporalMatchKind`. Detection additionally exposes `TemporalDetection`, `TemporalIndication`, and `TemporalIndicationKind`. Bounded fallback exposes `TemporalInferencer<E>`, `TemporalInference`, `TemporalInferenceResolution`, `TemporalInferenceError`, and `CHRONOS_INFERENCE_CONTRACT_VERSION`. `TemporalTimeOfDay` preserves a normalized 24-hour clock value plus minute/second precision and original evidence without implying a calendar date or timezone. `TemporalDuration` preserves an exact positive quantity plus calendar/unit semantics instead of flattening months or years into fixed nanoseconds. `TemporalDurationRange` preserves explicit lower/upper quantities such as `10-15 minutes`. `TemporalApproximateDuration` preserves either an approximate numeric amount (`about two weeks`) or a qualitative quantity (`a few hours`) without inventing numeric bounds. `TemporalEventRelation` preserves an exact duration offset, `Before`/`After` direction, and textual event referent such as `30 minutes before cooking` without inventing an event timestamp. `TemporalInterval` is the derived valid-time range form: `start_ns` and `end_ns` are independently optional half-open bounds, with per-bound granularity plus original evidence. The former `DreamTemporal*` names remain public compatibility re-exports of the pre-existing analysis types.

`chronos::detect(text)` is the read-only indication boundary. It can report explicit/calendar/relative/boundary/recurrence/duration material even when the current parser cannot resolve it, and each indication preserves original byte offsets/evidence. Bounded typo recognition is restricted to known temporal vocabulary and records the normalized token separately; it never rewrites authoritative text.

`chronos::analyze(text, reference_timestamp_ns)` is the shared deterministic parser/resolver boundary. It accepts semantic text plus an optional authoritative reference timestamp and owns the calendar, absolute-date, relative-date, time-of-day, recurrence, normalization, and matching primitives now extracted from Dream. Meridiem-qualified standalone clock expressions resolve to `TemporalTimeOfDay` rather than being combined with the reference timestamp into an invented date. When high-confidence vocabulary correction is available, analysis parses a transient normalized view in addition to the original text, merges only new semantic results, and maps corrected evidence back to the exact original source span. It does not choose source chronology or persist semantic state.

`chronos::assess(text, reference_timestamp_ns)` performs one shared detection/normalization pass, returns the deterministic `TemporalAnalysis`, and derives `TemporalResolution { status, unresolved_indications }`. `TemporalResolutionStatus` is `NoTemporalMaterial`, `FullyResolved`, or `Unresolved`; `needs_inference()` is true only for `Unresolved`. Unresolved indications retain their original byte spans/evidence so a consumer can send only unresolved temporal residue to a bounded inference route instead of regenerating deterministic anchors.

`TemporalInferencer::infer(text, reference_timestamp_ns, assessment)` is the bounded probabilistic seam. It returns without a model call unless the assessment is `Unresolved`. The endpoint receives only unresolved indication IDs/kinds/spans/evidence plus already-resolved deterministic evidence. For each unresolved item the model may return one standalone canonical expression or abstain with an empty expression. Every non-empty answer is reparsed by deterministic Chronos and must become fully resolved as the same source indication kind; unverifiable or type-changing answers fail closed. `chronos::analyze_with_inference(...)` reapplies an already-verified persisted inference by reparsing its canonical expressions and mapping evidence back to the original source wording.

`Cva::dream_temporal_analysis(memory_id)` and `Phylactery::dream_temporal_analysis(memory_id)` are thin Dream consumer adapters over Chronos. REL resolves recoverable Archive/Episode provenance first and then falls back to persisted `Memory.source_time_ns`; PHY uses persisted `source_time_ns` because it has no REL-local source pointers. Explicit parsing covers RFC3339 timestamps, ISO/natural calendar dates, inclusive date ranges, months, quarters, contextual years, and recurrence patterns. Relative forms such as `today`, `tomorrow`, `last week`, `next month`, `next Tuesday`, `in N days/weeks/months/years`, and corresponding `... ago` forms are resolved only when authoritative source time is available. Relative quantities accept bounded decimal values and English word numbers through ninety-nine; month/year offsets preserve the source day when possible and clamp to the target month's final day when necessary. Boundary parsing additionally resolves bounded `from … to/through/until …` intervals and open `since`, `until`, `before`, `after`, `starting`, and `ending` forms. Bare months/weekdays at a boundary require authoritative reference time; explicit endpoint dates do not. Bounded intervals are also projected as compatibility `TemporalAnchor { granularity: Range }` values so existing Dream matching remains unchanged. Exact standalone duration forms such as `for three months`, `lasted two hours`, and `duration of one year` produce `TemporalDuration` values without requiring reference time. Recurrence additionally accepts English word-number intervals and unambiguous alternating forms such as `every three weeks`, `every other Tuesday`, and `every other month`; ambiguous cadence labels such as `biweekly` are intentionally not guessed. Qualified named seasons such as `northern spring 2027` or `summer 2027 in the southern hemisphere` resolve to meteorological three-month anchors with `TemporalGranularity::Season`; unqualified `spring 2027` is detected but not assigned a hemisphere. Safe loose-calendar forms include `Sep. 7th, 2027`, `7th of May 2028`, `Nov 2029`, reference-bound `next March`, and `March 7 next year`. Locale-ambiguous numeric dates and other phrases without one safe interpretation are not guessed. `Memory.created_at_ns` is never a temporal reference frame.

Temporal anchors are half-open nanosecond ranges and remain distinct from source chronology. Current calendar interpretation uses UTC because source provenance does not yet carry an explicit source timezone. Deterministic analysis and resolution status remain derived/read-only and have no independent Chronos clock. Insomnia creates a transient `TemporalAssessment` for each prepared Memory draft using authoritative `source_time_ns`; only verified nondeterministic residue may become durable as `Memory.temporal_inference`. That payload is bound to exact `MemoryBodyId + source_time_ns`, stores the model/contract plus original span/kind/evidence and canonical expression, survives matching lifecycle-only revisions/reopen/reconciliation/migration, and is not carried forward when the binding changes. `ModelSwitchboardConfig::chronos` optionally selects a dedicated model route; absent configuration falls back to Insomnia and then General. `DreamMemoryContext` carries the complete derived Chronos analysis in process; Dream’s current classifier/verifier JSON projection still emits the compatibility anchor/pattern surface only. New interval/duration products are therefore available to consumers without silently changing the existing Dream inference contract.

### Dream pair classification

Public types are `DreamClassifier<E>`, `DreamPairClassification`, `DreamPairEvidence`, `DreamRelationKind`, `DreamRelationDirection`, `DreamEvidenceSide`, `DreamClassificationError`, `DREAM_CLASSIFIER_CONTRACT_VERSION`, `DREAM_CLASSIFIER_SYSTEM_PROMPT`, and `dream_classifier_schema()`.

`DreamClassifier::new(endpoint)` binds the production `DREAM_CLASSIFIER_SYSTEM_PROMPT`. `DreamClassifier::with_system_prompt(endpoint, prompt)` is the explicit tuning seam used by the exact-pair harness to measure a candidate without changing the production default. `DreamClassifier::classify_pair(left, right)` canonicalizes the two distinct Memory contexts into stable MemoryId A/B order, submits the canonical pair through `GeneralEndpoint::complete_json`, and validates the structured result. `classify_candidates(set)` evaluates every candidate in the already-bounded `DreamCandidateSet`; the classifier does not discover additional candidates.

The v2 classifier returns one primary proposal: `None`, `Topical`, `Factual`, `Causal`, `Recurrent`, `DuplicateOf`, or `Supersedes`. `Topical`, `Recurrent`, and `DuplicateOf` are semantically undirected; `Factual`, `Causal`, and `Supersedes` require an explicit A→B or B→A direction. Every non-none result requires exactly two verbatim evidence quotes, one from each Memory; invalid direction combinations or invented evidence are rejected. `None` requires no evidence. The result records the endpoint model name but is transient: classification does not write Graph state or change Memory lifecycle.

### Dream independent verification

Public types are `DreamVerifier<E>`, `DreamPairVerification`, `DreamVerificationPolicy`, `DreamVerificationSignal::{Yes, No, Uncertain}`, `DreamVerificationVerdict::{Accept, Reject, Uncertain}`, `DreamVerificationError`, `DREAM_VERIFIER_CONTRACT_VERSION`, `DREAM_VERIFIER_SYSTEM_PROMPT`, and `dream_verifier_schema()`.

`DreamVerifier::verify_pair(classification, left, right)` requires a non-`None` classification, canonicalizes the supplied contexts with the same MemoryId ordering used by the classifier, verifies that the classification identifies that exact pair, and submits the pair plus proposal/evidence through a separate strict structured-output call. The verifier returns categorical support for the proposed relation, direction, and classifier evidence. Any `No` deterministically yields `Reject`; otherwise any `Uncertain` yields `Uncertain`; three `Yes` signals yield `Accept`.

`verify_if_required(policy, ...)` skips the model call when the selected policy does not require verification. `DreamVerificationPolicy::default()` verifies `DuplicateOf` and `Supersedes`; `broad_semantic()` additionally verifies `Factual`, `Causal`, and `Recurrent` for measurement. Neither policy verifies `None`, and topical remains single-pass. Verification exposes no numeric confidence and remains transient: it writes no Graph state and changes no Memory lifecycle.

### Dream owner-local processing

`DreamProcessor::process_memory` / `process_memory_with_pair_concurrency` execute the complete same-owner Dream path for one Reliquary Memory. `process_phylactery_memory` / `process_phylactery_memory_with_pair_concurrency` provide the equivalent single-Memory path for a Phylactery. `process_memories_with_concurrency` and `process_phylactery_memories_with_concurrency` are the bounded population primitives: source IDs are divided into deterministic frontiers, all candidate sets in one frontier are selected from the same pre-frontier owner state, candidate pairs are interleaved across Memories and consumed by one globally bounded inference worker pool, and successful Memories are published in caller order before the next frontier is selected. Classification or verification failure publishes nothing for that Memory and leaves it eligible for retry; candidate, publication, and lifecycle failures abort the batch. `DEFAULT_DREAM_FRONTIER_SIZE = 6` and `DEFAULT_DREAM_INFERENCE_CONCURRENCY = 12` are the current runtime defaults. Each path remains strictly owner-local and performs verification when required, Graph publication including chronological duplicate-chain maintenance, and owner-local lifecycle reconciliation.

`RuntimeBackgroundConfig` exposes `dream_frontier_size` and `dream_inference_concurrency` separately from `max_dream_memories`. `InteractionRuntime::process_background_work` uses the population primitive rather than serially blocking on one complete Memory at a time. Inference concurrency is a global per-processor bound across the active frontier; it is not multiplied by the number of Memories and does not imply credential pooling or multiple configured Dream routes.

`Cva::publish_dream_pair` and `Phylactery::publish_dream_pair` require the caller's expected current Graph version and reject stale publication. Duplicate publication requires authoritative source chronology; PHY uses persisted `source_time_ns` and never substitutes Memory creation time. `reconcile_dream_lifecycle` exists on both owners. PHY applies owner-local lifecycle rules but deliberately does not claim REL-style independent-source corroboration merely from an external source reference; owner-local Dream does not dereference another REL to manufacture corroboration.

No Dream API in this slice accepts a second owner. REL↔PHY comparison, cross-owner duplicate/supersession, and persisted cross-file Graph edges are outside this contract; see ADR 0024.

### Credentials
Public types are `CredentialId`, `Credential`, `CredentialsConfig`, `CredentialError`, and redacting `SecretString`. `CredentialId::new` accepts non-empty ASCII alphanumeric/`.`/`_`/`-` IDs up to 128 bytes. `CredentialsConfig::insert_api_key` stores API-key auth in memory; `insert_chatgpt_oauth` stores ID/access/refresh tokens plus optional account ID. `get`, `remove`, and `ids` expose current credential inventory without exposing secret strings through `Debug`.

### Model switchboard
Public types are `ModelProvider::{OpenAiCodex, OpenAiReady}`, `ModelCapability::{General, Insomnia, InsomniaMetadata, Dream, Embedding}`, `ModelAuthKind::{ChatGptDeviceCode, ApiKey}`, `ModelReasoningEffort::{None, Minimal, Low, Medium, High, XHigh, Max}`, `GeneralModelEndpoint`, `EmbeddingModelEndpoint`, `ModelSwitchboardConfig`, `ModelRequestAuth`, `ModelSwitchboard`, and `ConfiguredGeneralEndpoint`.

Each route includes a `CredentialId`. `ModelProvider::supports(capability)` exposes provider capability. `OpenAiCodex` supports General/Insomnia/InsomniaMetadata/Dream routing, uses provider-owned routing, requires ChatGPT OAuth material, and requires an explicit `ModelReasoningEffort`; `OpenAiReady` supports General/Insomnia/InsomniaMetadata/Dream/Embedding, requires explicit HTTP(S) URLs and API-key material, and currently leaves General-model reasoning unset. Embedding routes also require non-zero dimensions and explicit normalization. `models.insomnia` and `models.dream` are optional and independently resolve to the General route/credential when absent; `models.insomnia_metadata` is optional and does not become a mandatory classification stage.

`ModelSwitchboard::new(config, credentials)` validates route structure and credential availability/auth kind. `general_auth()`, `insomnia_auth()`, `dream_auth()`, and `embedding_auth()` return redacting `ModelRequestAuth` values. `ModelRequestAuth::apply_to` adds `Authorization: Bearer ...` and, for ChatGPT auth when available, `ChatGPT-Account-ID`. `OpenAiCodexDeviceAuth` implements ChatGPT device-code acquisition against `auth.openai.com`, including authorization polling, OAuth code exchange, account-ID extraction, and insertion into `CredentialsConfig`. `ConfiguredGeneralEndpoint` dispatches the selected General/Insomnia/Dream route to either `OpenAiReadyGeneralEndpoint` or `OpenAiCodexGeneralEndpoint`; the latter uses the ChatGPT Codex Responses backend, structured JSON-schema output, SSE streaming, and the route's reasoning effort. For `OpenAiReady`, the dedicated Dream constructor forces exactly one named function/tool call whose parameters are the requested schema and parses only that tool's JSON arguments; ordinary General/Insomnia OpenAI-ready calls retain JSON-schema `response_format`. The OpenAI-ready General transport performs bounded retries for connect/timeouts and ordinary retryable HTTP statuses such as 408/409/5xx; HTTP 429 is instead surfaced immediately as typed `GeneralEndpointError::Backpressure` so the owning runtime can coordinate capacity backoff across work rather than multiplying request-local retries. Explicit Codex OAuth refresh-token rotation is implemented through the config credential refresh seam; automatic refresh-on-request remains future work.

### Insomnia extraction and backlog worker
Public Insomnia surface includes `InsomniaExtractor`, `InsomniaRoutingMetadata`, `InsomniaOwnership::{User, Project}`, `InsomniaWorkerConfig`, `InsomniaDrainResult`, `InsomniaWorkerError`, queue/work/attempt models, and the extraction/ownership contract constants. `ConfiguredGeneralEndpoint::from_insomnia_switchboard` constructs the effective dedicated-Insomnia-or-General-fallback endpoint and dispatches it to the selected provider transport. Extractor contract `v3-4` keeps the authoritative ledger, fixed-group classification, wording, ownership, and Entity-enrichment responsibilities separate. `with_metadata_endpoint(...)` enables the optional fixed-group metadata classifier and also supplies that route to Entity enrichment; `with_enrichment_endpoint(...)` supplies enrichment independently. Configured finite/runtime-host execution always enables Entity enrichment, using `models.insomnia_metadata` when configured and otherwise a second effective main-Insomnia endpoint. Enrichment sees only final Memory title/content and may emit only verbatim bounded Entity mentions. Lexical Memory routing is derived deterministically by the owner-local Memory lexical index and makes no model call. Ownership can select only the durable destination; it cannot change propositions, authority, provenance, category/type/lifecycle, grouping, candidate identity, or Entity routing metadata. Without an ownership endpoint, candidates default conservatively to Project.

`Cva::finalize_canonical_imports_and_queue(EpisodeConfig, now_ns)` materializes uncovered deterministic import Episodes for canonical Archive branches and idempotently ensures all import-origin Episodes have Insomnia work. `Cva::process_claimed_insomnia_episode` and `Cva::drain_insomnia_backlog` remain Project-only. `process_claimed_insomnia_episode_routed(phylactery, ...)` and `drain_insomnia_backlog_routed(phylactery, ...)` accept an explicit PHY and route User-owned drafts there. User publication converts validated REL-local provenance into an identifier-only `MemorySourceRef`, removes the REL-local provenance fields from the PHY draft, syncs the PHY before the REL completion receipt, and records each external result as `MemoryRef { owner_id, memory_id }`; deterministic mutation IDs make a crash between those two writes idempotently retryable. A User-owned candidate presented to a Project-only commit fails closed rather than silently falling back to REL.

The finite drain runs 1–64 workers (default 48, calibrated against the current Luna/low corpus run). Claims and bounded source/commit operations use the concrete owner locks; model calls execute outside those locks and therefore overlap across Episodes. Ordinary retryable extraction failures are requeued until `max_attempts`; invalid endpoint configuration is terminal. HTTP 429 capacity/quota responses are different: provider `Retry-After`/`resets_in_seconds` hints are honored with a 60-second minimum cooldown, the affected claim remains Failed/retryable regardless of its normal attempt count, and the first backpressure wave stops the finite drain from claiming additional Episodes. `InsomniaDrainResult::paused_for_backpressure` reports that intentional partial-drain state. After Episode work completes or the drain pauses, Project-only drains fill missing REL Memory-vector bindings, while routed drains independently establish/reuse the same verified embedding-space contract and fill missing bindings in both REL and PHY. `InsomniaDrainResult` reports Project/User Memory and vector outcomes separately.

Memory publication remains authoritative before vectorization: if embedding/profile establishment fails, completed Memories and Insomnia outcomes remain durable, and a later drain with no queued Episode work will retry the still-missing vectors. Reusing the same compatibility profile performs no re-embedding; a genuinely new profile creates new immutable bindings for the existing Memory bodies. The long-lived `ReliquaryRuntimeHost` provides the persistent service form of these mechanics: `start(...)` owns only the REL, while `start_with_phylactery(...)` additionally owns one PHY, enables ownership classification/routing, and continuously backfills vectors in both owners. Its Insomnia workers share one provider-backpressure gate, so one 429 wave pauses new claims until the retry window instead of walking the whole backlog; replacing runtime routes clears that host-wide gate. `phylactery_owner_id`, `phylactery_memory_stats`, and `phylactery_memory_vector_stats` expose bounded inspection; `into_cva_and_phylactery()` returns both durable owners after workers stop.

### Exact semantic retrieval
Public surface: `SemanticSearchHit { fragment, score, ordinal, generation_id }`, `SemanticSearchError`, and `MAX_SEMANTIC_SEARCH_LIMIT = 1000`.

`Cva::semantic_search(profile_id, endpoint, query, limit)` requires a non-empty query and limit `1..=1000`. It verifies the endpoint against the selected compatibility profile, embeds the query in `EmbeddingMode::Query`, resolves that profile's current Vector Generation, exact-scans its `f32` packed matrix using cosine similarity, drops scores `<= 0`, orders descending with row ordinal as the deterministic tie-break, and maps selected rows through Archive Vectors to durable `Fragment` records.

Each hit carries the generation ID actually searched. Search is read-only: it does not advance Archive, vector, or CVA-global semantic clocks. The current direct API verifies endpoint compatibility on every call; a future long-lived runtime may cache a verified capability without changing the generation/search ownership model.

No lexical search, hybrid score fusion, ANN index, reranker, or retrieval controller is part of this low-level method.

### Default hybrid retrieval
Public surface: `RetrievalConfig`, `SearchCandidate { fragment, lexical_score, semantic_score, combined_score, generation_id }`, `SearchError`, `DEFAULT_LEXICAL_WEIGHT = 0.45`, `DEFAULT_SEMANTIC_WEIGHT = 0.55`, `DEFAULT_SEARCH_CANDIDATE_LIMIT = 30`, and `DEFAULT_SEARCH_RESULT_LIMIT = 10`.

`Cva::search(profile_id, endpoint, query)` restores the original default search path. Lexical and semantic channels independently contribute up to 30 candidates. Candidates are merged by `FragmentId`; if only one channel produced a positive finite score, that score is retained without dilution. If both did, the combined score is `0.45 × lexical + 0.55 × semantic`.

Lexical scoring uses the original formula: `0.85 × unique query-term coverage + 0.15 × bounded matched-term frequency density`. Candidate ordering is followed by duplicate range removal and greedy diversity selection that multiplies same-conversation candidates by `1 - overlap` for each already-selected fragment. V2 computes overlap from actual node membership because fragments store node ranges rather than v1 numeric turn sequences. The diversified candidate pool is capped at 30 and the default method returns the first 10.

`Cva::search_with_config(profile_id, endpoint, query, config)` applies a validated `RetrievalConfig`; positive finite weights are normalized before fusion. `Cva::search` delegates to `RetrievalConfig::default()`. The current path has no reranker or conversation/time/metadata filters and remains read-only.

## Defaults or precedence
`FragmentConfig::default()` is eight turns with two-turn overlap, sourced from exported `DEFAULT_FRAGMENT_TURNS` and `DEFAULT_FRAGMENT_OVERLAP` so adapters do not redefine that policy. Compatibility probe suite v1 and compatibility policy v2 are fixed by the current implementation.

Node identity is `(conversation_id, node_id)`. Branch identity is `(conversation_id, branch_id)`. Repeated branch records are revisions; the newest Archive version is current.

## Diagnostics or failure behavior
`ConfigError`, `ArchiveError`, `PackedVectorError`, `ArchiveVectorError`, `CompatibilityProfileError`, `VectorGenerationError`, `SemanticSearchError`, and `SearchError` own their concrete domains. `CvaError` composes create/open failures and rejects global-version claims shared by multiple semantic owners.

Durability remains explicit through `Cva::sync()`.
