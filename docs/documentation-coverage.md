## Frozen publication checkpoint

`src/runtime_inference/runtime_host_owner_publication*.rs` implements the exact prepared-Memory envelope using the existing semantic codecs, route planning, separate PHY publication and REL receipt observation. `runtime_host_rel_insomnia.rs` loads plans before model reruns. `runtime_host_gateway_pending_publication_tests.rs` covers exact offline/quiesced recovery, admitted-write draining, unrelated real background vectors and deduplicated attachment churn. `runtime_host_gateway_semantic*.rs` plus its five acceptance cases cover instance-authorized private search/read delivery and explicit source-fenced profile projection. The ownership script and compiled routing guard cover gateway and concrete REL/PHY production modules, while preserving the isolated legacy host. `runtime_host_gateway_publication_tests.rs` covers mixed-principal/private/project destinations, ambiguous and unknown rejection, captured grant authority, persistent withdrawal, offline journals, changed bindings, same-ID conflicts and restart boundaries. The worker loads plans before extraction, can replay without an endpoint, and verifies completed receipts read-only. [The Phase 2 execution record](multiplexing-implementation-plan.md) records verified gates and the remaining ordered work.

## REL distribution recovery

The internal P4 sequencer, registry and snapshot modules own bounded delivery and exact-watermark resync acknowledgement. Post-snapshot events remain bounded until acknowledgement; overflow invalidates the cut. Snapshot gateway tests protect recovery, disconnect/resubscribe and grant/epoch isolation. P4.7 adds production conversation snapshot/receipt/checkpoint binding while leaving subscriber and cursor state in P4. P4.8 audit passed 1,026 library and 95 integration tests, runtime `cargo check`, formatting check, and a 28-fixture/112-API structural guard across all five REL worker files; this heuristic does not prove indirect arbitrary Rust calls. Strengthened tests cover PHY-private exclusions and maintenance quiescence/reopen continuity. The 120-second architecture refresh timed out during Lexicon analysis before Arcana/Pitlord; unrestricted examples retain the inherited `archive_open_profile` allocator conflict. See the [snapshot/resync record](multiplexing-implementation-plan.md), [P4.7 convergence record](multiplexing-implementation-plan.md), and [P4.8 audit](multiplexing-implementation-plan.md).

## P5-B background controls

`runtime_host_gateway_background.rs` implements exact-owner counters, dispatch switches, wake and route configuration over existing REL/PHY authority. `runtime_host_gateway_background_tests.rs` covers same-principal sharing, two-principal privacy, paused native work, route wake, stale-token/restart isolation and blocked provider I/O during quiesce. Canonical PHY vector publication synchronizes before wake. The host router admits only executable ConversationExecution and validates exact ID/digest retries; its deterministic tests cover unsupported claims, retained debt and changed-input rejection. Canonical contracts are in [Architecture](architecture.md), [Rust API](api.md), [Current limitations](current-limitations.md) and [the B capability ledger](multiplexing-implementation-plan.md).

## Architecture adapter profile

The refresh wrapper defaults the Lexicon child environment's `CARGO_PROFILE_DEV_OPT_LEVEL` to `3`, because the Rust adapter launches through `cargo run`. An explicit caller setting takes precedence. This optimizes the analysis tool, retains the complete Rust corpus and all policy rules, and leaves ordinary application build/test profiles unchanged. Python source guards run independently of the Rust graph.
