### Admission and replay ordering

For replay, each owner first consumes its own physical frames in the established deterministic physical order and `finish` validates only that owner's state. After all relevant owner-local finishes succeed, REL/PHY lifecycle composition runs the existing cross-owner checks in their current order. A mount is returned only after all required checks pass. This preserves invalid-history refusal while allowing a store to compile without a sibling store import. For a live cross-owner mutation, the caller obtains read-only accepted facts from the authoritative owners at one coherent mounted cut, validates relation/liveness/authorization, then calls the destination's owner-local guarded mutation. The destination rechecks local expected revision and local admission before publication. Phase 2 does not create a general transaction coordinator; cross-owner repair/reconciliation and new policy remain Phase 3.

## Privacy, provenance, and replay preservation

- REL and PHY stores remain independent. An owner-qualified reference does not trigger opening or traversing the other owner. Missing authorization, inaccessible scope, or unresolved target remains unresolved/refused according to the current caller contract; evidence does not confer access.
- Read/proof views are bounded by an explicit owner and version/cut, and immutable for the lifetime of the current owner snapshot. No direct index/map references escape. A read never appends Freshness use, advances clocks, repairs stale state, or changes bytes.
- Archive remains authoritative for source/Episode/interaction/compaction evidence; Memory for authored Memory/provenance; Perception for Entity/Resolution and transitional Relationship; Graph for relations/Communities; Freshness for scores/events; vector stores for profiles/bindings/generations; Dream/Insomnia for durable work and receipts; Ego for persisted semantic records; Import for epochs; External Index for its derivative cursor/source index; Maintenance for local proofs.
- Preserve every current V2 payload, typed ID, owner and global version, timestamp, provenance/span, append order, compact/delta reconstruction, grouped publication, first-acceptance identity, terminal/tombstone behavior, exact retry/no-op behavior, import receipts and completion binding, Dream Begin/replay proof, Insomnia attempts/receipts, vector generation/profile binding, and maintenance/prune evidence. Do not introduce a record tag or second durable fact copy.
- Phase 1 `Container` cursor, explicit repair, writer exclusion and snapshot leases remain unchanged. Normal owner open is byte-pure. Owner-local replay does not acquire authority to mutate Container or skip the held-source protocol.
- Exact six-file canonical history/oracle, hashes, clocks and timestamps remain Phase 2 acceptance evidence. A format mismatch stops the work at the format gate; this contract authorizes no migration or runtime compatibility bridge.

## Pitlord source ratchet

Keep the existing root `policy.json`, current 19-area ownership map, Phase 0 graph capture, `convergence-baseline.json`, `convergence-debt.json`, and Phase 1 logical DAG acceptance intact. Ratchet sequence:

1. Use the accepted B0 ledger for the current exact file/line/function and production/test-file classification, and extend it at each task where source review finds a missing or grouped edge. Bind every touched finding to source evidence and a task ID. Do not refresh or overwrite Phase 0 evidence to make debt disappear.
2. At each owner gate, add or tighten explicit consumer-to-dependency allow rules from the accepted component DAG for the migrated modules. Store components may depend on Container and allowed pure codec/clock modules plus their own owner-local modules; they may not depend on facade/Cva/Runtime, siblings, or parent-layer services. No inferred transitive permission: direct source edges must be allowlisted.
3. Retain existing global target-rank and `forbid_dependency` checks, and reject every unlisted direct edge even when the graph stays acyclic. Add negative fixtures for `graph-store -> memory-store`, `perception-store -> memory-store`, `archive-store -> memory-store`, `freshness-store -> archive-store`, `vector-store -> retrieval`, and any store -> `Cva`/facade/runtime. Include a deliberately acyclic upward edge to prove rank/allowlist enforcement is not just SCC detection.
4. Preserve production findings as debt until the call site is deleted or corrected. Rebind only source-proven equivalent findings; mark colocated `cfg(test)` records test-only only after Rust visibility/source evidence confirms they cannot compile in production. Record analyzer artifacts with evidence instead of fictional migrations. Any newly observed unlisted edge fails closed; no blanket suppression, recapture, broad rebaseline or growing exception set.
5. Once authored source stabilizes (P2.10.05), refresh Lexicon/Arcana once, compare against the retained Phase 0 manifest, reconcile every stale/new finding, and require all owner rules and negative fixtures to pass. The source graph supplements direct source review; absence of a static edge is not proof of absence.

The logical 34-component DAG is the sole target. The coarse area graph remains an evidence/checking view until source rules enforce the finer component allowlist. No current policy configuration or debt ledger is changed by this contract document.
