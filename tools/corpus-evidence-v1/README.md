# PG-C01 corpus-evidence v1 tooling

Status: provisional implementation, not an accepted evidence contract. This standalone Python tooling is outside the Cargo workspace and production dependency DAG. It provides deterministic framing, strict typed JSON validation, synthetic interoperability fixtures, and report validation. It does not export or verify authentic source owners, establish a source carrier inventory, or permit conversion or activation.

The 11 semantic group codes and retained-value obligations are frozen from the post-G4 contract. They are semantic areas, not physical markers or proof that a source carrier was observed. The physical-carrier registry is deliberately empty and fail-closed. Every value-record schema in this bundle uses a synthetic fixture namespace, and the four fixture domain IDs do not represent the real REL/PHY domain catalog. Only five representative fixture families are defined; six stable-identity preimages and the remaining graph, relationship, attachments, Dream/import and operational families are not covered, so this does not claim D01-T03 synthetic family or identity coverage. Authentic admission remains false. A reviewed authentic registry, carrier mapping, real schemas, and source-derived cuts require a separately versioned and F03/D01/D02-reviewed contract update. Do not use the 173 lexical marker candidates as an allowlist.

## Provisional byte-level v1 rules

- Evidence JSON is strict UTF-8 with no BOM, no duplicate decoded object keys, no unpaired surrogates, no unknown fields or enum values, and no JSON numeric tokens. Decimal values are canonical strings. Bytes and digest IDs are lowercase hexadecimal. Floating values are width/endian-tagged IEEE bit bytes; non-finite encodings reject.
- Canonical JSON follows RFC 8785 (JCS), including UTF-16-code-unit object-member ordering. Text is not normalized; UTF-8 text bytes are preserved after decoding. Object keys are fixed by each closed schema. The supplementary/BMP key-order golden distinguishes JCS from UTF-8-byte ordering.
- Nonempty semantic JSONL uses LF separators and a final LF. An empty byte stream means zero rows. LF delimiters are not part of canonical row bytes or row hashes.
- Row sorting remains the contract-fixed tuple (family, stable_key, revision_or_event), each UTF-8-byte lexicographic, then ordinal as eight-byte unsigned big-endian. Thus ordinal 2 sorts before ordinal 10. Ordinals are canonical unsigned decimal strings in 0..2^64-1. An exact duplicate tuple rejects; otherwise repeated identical events with different ordinals remain distinct. Snapshot membership is not part of the semantic row key. The row coordinate is publication/source-origin only, never an observation cut.
- LP(x) is u64be(byte_length(x)) followed by x. Lengths and record counts are unsigned 64-bit big-endian; overflow rejects. IDs in hash preimages are lowercase-hex UTF-8, not raw ID bytes. The owner key is canonical JCS bytes for exactly {owner_uuid, owner_kind, scope}. The owner descriptor also carries source_file_sha256 as custody metadata; it is excluded from canonical_semantic_owner_descriptor and from common semantic owner/corpus digests.
- Cut ID is SHA256(b"reliquary:corpus-evidence:cut:v1\0" || LP(canonical_coordinate_json)).
- Family digest is SHA256(b"reliquary:corpus-evidence:v1\0" || LP(owner_key) || LP(family_id_utf8) || LP(canonical_family_coverage_json) || u64be(row_count) || each LP(canonical_row_bytes)). The validated API accepts typed rows, checks owner/family/row-count membership, and canonicalizes internally. Family coverage includes a separate digest-bound row_cut_memberships table keyed by stable_key, revision_or_event, ordinal, and cut_id. It is ordered by the first two UTF-8 byte strings, ordinal u64be, then raw 32-byte cut ID; repeated row keys at different cuts are allowed, duplicate row/cut pairs reject. Every semantic row key must be mapped. The family row_count counts unique semantic rows; each cut row_count counts membership entries for that observation cut.
- Registry identity is canonical JCS of {contract_id, semantic_groups_sha256, record_schemas_sha256, physical_carriers_sha256}, where each hash is SHA-256 of that complete registry object canonicalized as number-free JCS. Owner and corpus preimages begin with LP(registry_identity), binding group, value-schema and carrier catalog identity as well as their versioned IDs. Owner digests hash the canonical descriptor with source_file_sha256 omitted.
- Owner digest is SHA256(b"reliquary:corpus-evidence:owner:v1\0" || LP(registry_identity) || LP(owner_key) || LP(canonical_semantic_owner_descriptor) || u64be(group_count) || group coverage rows sorted by UTF-8 group ID, each LP(canonical_group_coverage_json) || u64be(family_count) || family entries sorted by UTF-8 family ID). Each family entry is LP(family_id_utf8) || LP(canonical_family_coverage_json) || u64be(cut_count) || each LP(canonical_cut_coverage_json) in raw cut-ID-byte order || raw 32-byte family digest. The descriptor binds owner UUID/kind/scope, history generation, typed lineage, version heads and the declared cut catalog. Group family_count is the number of registered logical family schemas, not a count of observed rows.
- Corpus digest is SHA256(b"reliquary:corpus-evidence:corpus:v1\0" || LP(registry_identity) || u64be(expected_owner_count) || each LP(expected_owner_key) in canonical owner-key order || u64be(owner_count) || owner entries sorted by canonical owner-key bytes), with each entry LP(owner_key) || LP(canonical_semantic_owner_descriptor) || raw 32-byte recomputed owner digest. corpus_digest requires the explicit source-derived expected owner catalog, recomputes every owner digest from full owner/family evidence, checks optional claimed hashes, and rejects missing or extra owners. The expected catalog and descriptor include a source file hash per owner, but those physical hashes do not enter the comparable semantic corpus digest; the separate custody digest/report binds them.
- Custody digest is SHA256(b"reliquary:corpus-evidence:custody:v1\0" || LP(canonical_custody_json)). owner_files maps each full owner key (UUID, kind, scope) to source/target file hashes and byte lengths, including owners with no relocations; entries sort by canonical owner-key bytes and duplicate full owner-key mappings reject. Relocations must name that same full owner key and normalize by (canonical owner-key bytes, family ID UTF-8, source object hash bytes, source offset u64be, source length u64be, target object hash bytes, target offset u64be, target length u64be, payload identity bytes, reference-kind UTF-8). Duplicate relocation tuples reject. Physical file hashes, offsets and relocations are custody evidence, excluded from common semantic digests. This tooling validates typed shape/order and digests; it does not verify offset bounds, reference closure or injectivity, which D01/D02 must check. Logical source identity, source-body hash and source-body half-open byte span are semantic provenance and change the common semantic digest.

Coverage has distinct supported, absent, unsupported, unavailable, corrupt, unaudited and unclassified states, plus exhaustive, sampled or incomplete completeness. The row's event/source-origin coordinate remains separate from its as-of snapshot membership. Each membership cut ID must appear in both the owner cut catalog and the family's cut coverage, and per-cut row_count must equal membership entries. The table is part of canonical family coverage, so changing which snapshots include an event changes semantic digests. A row's value and availability are immutable across all cuts listed for that row key; a changed value or lifecycle state requires a distinct revision/event row, and v1 has no per-cut value override. Supported with row_count "0" is supported-empty; absent is separate and serializes no semantic rows. An absent family may be exhaustive only if every owner cut is explicitly absent. Unsupported, unavailable, corrupt, unaudited and unclassified states do not claim exhaustive semantic rows. Every owner binds each of the 11 groups and every versioned semantic family schema. Group coverage is a summary; per-family coverage and per-cut entries carry the independently reviewable detail. Typed coordinates keep global version, UTF-8-byte-sorted domain versions, transaction timestamp, REL activity position, accepted-event boundary and availability separate. This validator checks structure and cross-field consistency, but it cannot establish that a source-derived cut catalog is complete. F03 must derive and authenticate that catalog from the historical reader, independently of converter traversal.

The synthetic source/target examples intentionally have the same current memory revision but different intermediate history, a pruned body state, reordered freshness events, non-ASCII archive text, a >2^53 timestamp, and different vector float bits. The row-cut membership fixture maps one fixed-origin Freshness event into two later snapshot cuts, proving event coordinate and observation membership are distinct. These examples test the contract shape only; F03 must produce authentic membership from the historical reader, and the fixtures do not authorize or enumerate real carriers.

## Artifacts

- registry/semantic-groups-v1.json: fixed 11 semantic group codes and retained-value obligations.
- registry/record-schemas-v1.json: closed synthetic-only record schemas and fixture-only domain IDs.
- registry/physical-carriers-v1.json: empty, explicitly incomplete carrier inventory pending F03-V02/D01-T01.
- schemas/*.schema.json: generated schemas for rows, owners, family/group coverage, reports and custody.
- fixtures/: hand-authored synthetic source/target JSONL, a typed owner-cut catalog, a row-to-cut membership table, an empty-family stream, an incomplete report example, and literal independent golden bytes/digests.
- corpus_evidence_v1.py: canonicalization, typed validation, digest construction, and report registry-hash checks. Report validation uses pinned jsonschema==4.26.0. There is no source traversal or conversion.

Reports carry typed source_owner_bindings ordered by full canonical owner key; source_hashes must equal their source hashes in that same order. With evidence supplied, validation recomputes owner/family/cut/row counts and completeness, checks the expected owner catalog against owner descriptors and custody owner_files, and requires semantic/custody evidence hashes in parent_artifact_hashes. PASS is rejected without recomputable evidence. Producer role/evidence-scope pairs are closed; only source_reader may report authentic_source, and the current synthetic registry still blocks it. The report example has synthetic placeholder producer/toolchain fields and is explicitly INCOMPLETE. Report-example files are excluded from the contract-bundle digest so they can carry that digest without self-reference. The bundle digest covers the UTF-8-path-sorted contents of registry/, schemas/, and fixtures/, excluding report-example-* files and bundle.sha256; each entry is LP(path_utf8) || LP(file_bytes), preceded by b"reliquary:corpus-evidence:contract-bundle:v1\0" and u64be(file_count). registry_hashes() exposes SHA-256 for each registry file and this bundle digest.

Comparator PASS requires the validator's closed evidence object {source_witness, target_witness, custody}. Each witness has exactly producer_role, producer_code_sha256, producer_binary_sha256, expected_owner_catalog, and owners; both owner catalogs and evidence sets must be nonempty. Its binding is SHA-256 of JCS for {schema_id: reliquary-corpus-witness-binding-v1, producer_role, producer_code_sha256, producer_binary_sha256, semantic_corpus_sha256, owner_catalog}. Report parent hashes must include both recomputed semantic digests, both witness-binding hashes, and custody digest. Source and target full owner keys must agree and their per-owner hashes must match custody source/target file hashes. Source and target semantic corpus digests and coverage counts must match, and each side must contain at least one semantic row overall. Individual supported-empty families remain valid; an all-zero-row expected corpus cannot pass. The source-reader, target-reader, and comparator code and binary hashes must be distinct. These are structural checks, not proof of producer identity or source completeness; authentic D02 acceptance still requires independently verified producer artifacts, F03 source-admission and D01 conversion-receipt anchors, and exact mismatch reconciliation.

Diagnostics are discrepancy rows, not informational notes. Their total_count and sample_limit are canonical u64 strings, and sample length must equal min(total_count, sample_limit). Samples sort uniquely by owner UUID, family, cut ID, stable key, then revision/event; each row must show a differing availability or hash. Comparator PASS requires total_count zero and an empty sample. A non-PASS total count cannot be independently reconstructed until D02 fixes and implements its exact mismatch counting rule.


Run the lightweight tests from the repository root:

    python -m unittest discover -s tools/corpus-evidence-v1/tests -p "test_*.py" -v

The tests require jsonschema==4.26.0 (see requirements-test.txt); they do not run Cargo or read corpus data. Passing them verifies only this synthetic contract tooling. It does not satisfy PG-C01 acceptance, F03 source admission, D01 conversion, D02 parity, D03 staging, G5 release acceptance, or operator authorization.
